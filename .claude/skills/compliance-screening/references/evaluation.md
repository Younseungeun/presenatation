# 검수 성능을 재는 법

모델을 도입하거나 규칙을 고칠 때 "좋아졌는지"를 알 수 있게 하는 장치.
이게 없으면 모든 변경이 감이 되고, 나중에 왜 그 임계값인지 아무도 설명하지 못한다.

## 무엇을 재야 하는가

전체 탐지율 하나는 거의 쓸모가 없다. **실패의 종류가 섞여서 실상이 숨기 때문이다.**
최소한 이 네 가지를 따로 본다.

| 지표 | 정의 | 왜 중요한가 |
|---|---|---|
| **즉시 거절 오탐** | 정상 글인데 사람 확인 없이 거절된 건수 | **0이어야 한다.** 보류 오탐은 사람이 되살리지만 거절 오탐은 되살릴 사람이 없다 |
| 오탐률 | 정상 글 중 걸린 비율 | 높으면 공급이 죽는다 (오탐이 더 비싼 서비스인 경우) |
| 종류별 탐지율 | 직설/회피/패러프레이즈 각각 | 정규식의 천장이 어디인지 드러난다 |
| 유형별 탐지율 | 카테고리별 | 어느 유형이 비어 있는지 보인다 |

즉시 거절 오탐은 **회귀 테스트로 못 박아 둔다.** 규칙을 넓히는 변경이 이걸 깨면
CI에서 먼저 걸린다.

## 코퍼스 설계

문장마다 두 가지를 라벨링한다: **실제 위반인가**, 그리고 **어떤 종류의 문장인가**.

### 위반 문장

| 종류 | 뜻 | 무엇을 검증하나 |
|---|---|---|
| `literal` | 금지 표현을 그대로 씀 | 규칙이 기본은 하는가 |
| `evasion` | 글자 벌리기·기호 삽입 | 정규화 패스가 도는가 |
| `paraphrase` | 같은 뜻, 다른 말 | **모델이 메워야 할 몫** |

패러프레이즈를 넉넉히 넣는 것이 핵심이다. 금지 단어를 한 번도 쓰지 않고 같은 약속을 하는
문장 — `"떨어지면 차액은 제 사비로 채워드릴 테니 걱정 마십시오"` 같은 것. 정규식은
원리적으로 못 잡고, 이 비율이 곧 모델 도입의 기대 이익이 된다.

### 정상 문장 (오탐 측정용)

| 종류 | 뜻 | 무엇을 검증하나 |
|---|---|---|
| `normal` | 평범한 글 | 기본 오탐 |
| `negation` | 금지 표현을 **부정**함 | 부정 처리 (pitfalls #1) |
| `disclosure` | 리스크 고지·면책 문구 | 위험 어휘가 많은 정상 문장 |

**부정문을 따로 세는 이유**는 두 가지다. 규칙 단계에서는 오탐의 주요 원인이고,
임베딩 단계에서는 원리적 약점(`"보장합니다"`와 `"보장은 못 합니다"`의 유사도가 높다)이
그대로 드러나는 지점이다. 섞어 세면 두 문제 모두 보이지 않는다.

**하드 네거티브가 진짜 값어치**다. 위반 문장과 어휘가 겹치지만 정상인 문장을 넣어야
"위험 단어만 보고 판단하는" 탐지기를 걸러낼 수 있다. 완전히 무관한 문장은 아무것도 검증하지 않는다.

### 규모와 한계

손으로 80~150문장이면 시작하기 충분하다. 다만 **손으로 만든 코퍼스는 절대 수치가 아니라
변경 전후 비교에만 쓴다** — 실제 사용자 문체·빈도 분포와 다르다. 이 한계를 코드 주석과
출력에 명시해 두면 나중에 수치를 과신하는 일을 막는다.

## 하네스 설계

탐지기를 **"문장 → 소견 목록" 함수**로만 취급한다.

```ts
type Detector = (text: string) => Finding[];
function evaluate(detector: Detector, corpus: CorpusItem[]): EvalReport;
```

이렇게 두면 규칙이든 임베딩이든 LLM이든 **같은 잣대로** 잴 수 있고, 구현이 바뀌어도
하네스는 그대로다. 탐지기별로 다른 평가 코드를 쓰면 비교 자체가 성립하지 않는다.

리포트에는 집계뿐 아니라 **놓친 문장과 잘못 잡은 문장을 그대로 출력**한다.
수치만 보면 다음 수가 안 나오지만, 놓친 패러프레이즈 목록을 눈으로 보면 바로 나온다.

## 모델 채택 기준

모델을 붙이기 **전에** 채택 기준을 문장으로 못 박는다. 나중에 정하면 결과에 맞춰
기준이 움직인다.

> 오탐률이 현재 기준선을 넘지 않는 선에서, 패러프레이즈 탐지율이 가장 높은 설정을 고른다.

임계값이 있는 모델(임베딩 유사도 등)은 **스윕 도구**를 만들어 표로 뽑는다:

```
임계값   탐지율   패러프레이즈   오탐률   즉시거절오탐
0.70     ...      ...           ...      ...
0.74     ...      ...           ...      ...
...
```

고른 값과 **고른 근거**를 상수 주석에 남긴다. 임계값은 시간이 지나면 반드시 누군가
"이게 왜 0.82지?"를 묻게 된다.

## 운영 데이터로 넘어가기

초기 코퍼스는 부트스트랩이다. 운영자 판정이 쌓이면 **그쪽이 진짜 검증셋**이 되고
초기 코퍼스는 회귀 테스트용으로 남는다.

전환 시점에 확인할 것:

- 운영자 판정 표본이 유형별로 골고루 있는가 (한 유형에 몰려 있으면 아직 이르다)
- 자동 처리(시간 만료 등)가 라벨에 섞이지 않았는가
- 미탐이 실제로 기록되고 있는가 — 사후 철회 경로가 라벨을 남기지 않으면
  미탐률은 데이터가 아무리 쌓여도 0으로 보인다

증류(작은 모델 학습)로 갈 때도 같은 라벨을 쓴다. 운영자 판정 스키마
(`verdict` / `categories` / `findingsValid` / `source`)가 그대로 지도학습 라벨이 되도록
설계해 두면 추가 수집이 필요 없다.
