# 13차 검토 요청 — 우회(Adversarial) 표기를 어떻게 인지하고, 규칙으로 세우고, 학습시킬 것인가

## 0. 이 문서의 성격

INTOVILL은 리서처가 올린 투자 리포트를 **게시 전에 자동 검수**합니다. 검수는 두 층입니다.

| 층 | 무엇 | 할 수 있는 판정 |
|---|---|---|
| **규칙** (정규식, 결정적) | `applyRules()` | REJECT / HOLD / PUBLISH |
| **학생 모델** (KoELECTRA-small 14M, 온디바이스 ONNX) | 8개 다중 라벨 | **HOLD 까지만** |

**설계 원칙(고정)**: 즉시 거절(REJECT)은 **결정적 규칙만** 할 수 있습니다. 모델은 아무리 확신해도 보류까지입니다. 모델은 재현 불가능한 판정을 내리므로, 사람의 생계가 걸린 거절을 맡기지 않습니다.

**비용 모델(고정)**: 오탐(성실한 리서처를 막음) > 미탐(위반을 놓침). λ = 4. 즉 **오탐 1건 = 미탐 4건**의 손해로 셉니다. 놓친 것은 2차 사람 검수와 신고가 잡지만, 부당하게 막힌 리서처는 돌아오지 않습니다.

**운영 제약(고정)**: 외부 API 호출 없음. 전량 사장님 서버의 CPU에서 돕니다.

임계값 0.7, 가중치 `aeb1786b06ed9331`. 각 문장에 정상 예측 카드(삼성전자·상승 12%·90일·신뢰도 5)를 붙여 **운영과 같은 입력**으로 쟀습니다.

| ② 구분기호 | 7 | 57% | 71% |

대조군 8건은 `삼성SDI`, `POSCO홀딩스`, `LG화학`, `NAVER`, `KT&G`, `KODEX 200`, 그리고 표준 면책 문구(`과거 수익률이 미래 수익을 보장하지 않습니다`, `원금이 보장되지 않는 상품이므로`)입니다. **현재 오탐은 0입니다 — 이 0을 지키는 것이 이번 설계의 제약입니다.**

### 2-1. 이미 확인된 결함 하나

우리에게 정규화 패스가 이미 있습니다. 구분기호를 걷어낸 사본에 같은 규칙을 다시 돌리고, 거기서 나온 소견은 WARN으로 낮춥니다. 그런데:

```
"텔.레.그.램 으로 오세요"  → 정규화 "텔레그램으로오세요" → 소견 없음   ✗
"텔/레/그/램 주소입니다"   → 정규화 "텔레그램주소입니다" → SOLICIT_CONTACT/WARN  ○
"원.금.보.장 합니다"       → 정규화 "원금보장합니다"     → 소견 없음   ✗
"원 금 보 장 약속"         → 정규화 "원금보장약속"       → PROFIT_GUARANTEE/WARN  ○
```

원인은 이 세 줄입니다:

```ts
// 문장 경계를 넘어 붙은 매칭은 우연이다 ("복원. 금보장 구역" → "복원금보장구역").
// 회피는 한 표현 안에서 글자를 벌리지, 중간에 마침표를 찍지 않는다.
if (/[.!?\n]/.test(text.slice(start, endIndex + 1))) continue;
```

**오탐을 막으려고 넣은 가드가 그대로 회피 통로가 되었습니다.** 그리고 주석에 적힌 가정("회피는 마침표를 찍지 않는다")은 이번 코퍼스가 정면으로 반증합니다 — ②군의 표준 형태가 마침표입니다.

이건 이 저장소에서 반복되는 모양입니다: **오탐을 줄이려고 넣은 예외가 공격면이 된다.** 그래서 이번 검토의 축은 "더 잡는 법"이 아니라 **"오탐 0을 유지하면서 무엇까지 잡을 수 있는가"** 입니다.

### 2-2. 학생 모델이 보인 이상한 행동

③ 음성 변형에서 학생은 **틀린 유형**을 냅니다:

```
"텔레그렘 으로 오세요"   → RISK_INDUCEMENT   (정답 SOLICIT_CONTACT)
"원금보쟝 해드립니다"    → RISK_INDUCEMENT   (정답 PROFIT_GUARANTEE)
"손실 0% 보쟝"           → RISK_INDUCEMENT   (정답 PROFIT_GUARANTEE)
"원금bojang 확실"        → UNSUPPORTED_CLAIM, RISK_INDUCEMENT
```

**"뭔가 이상하다"는 감지는 했는데 어느 서랍인지를 못 맞춥니다.** 반대로 ④ 은유는 유형까지 정확히 맞힙니다(`노란 앱`·`파란 비행기`·`프로필 상단 링크` → SOLICIT_CONTACT).

## 3. 검토 질문

### P-1. 정규화를 어디까지 밀 것인가 — 오탐과의 교환비

받은 문서는 NFKD 유니코드 정규화, 동형자 치환(`0↔O`, `1↔l/I`, `5↔S`), 자모 합성을 권합니다. 기계적이고 구현은 쉽습니다. **문제는 한국 주식 시장의 실제 종목명이 라틴 문자와 숫자를 정상적으로 쓴다는 것입니다:**

`삼성SDI` · `POSCO홀딩스` · `LG화학` · `NAVER` · `KT&G` · `SK하이닉스` · `KODEX 200` · `TIGER 미국나스닥100` · `HD현대일렉트릭` · `한화솔루션`

동형자 치환을 켜면 `O↔0`, `l↔1`이 종목명 안에서도 일어납니다. 여기에 한/영 음차(`gold→금`, `bojang→보장`)까지 더하면 정상 문장이 무작위로 변형됩니다.

- **정규화 층을 몇 개로 둘 것인가?** (원문 / 기호제거 / 동형자치환 / 음차 — 각각 별도 패스로 돌리고 층이 깊을수록 심각도를 낮추는 사다리가 타당한가?)
- **각 층에서 나온 소견의 심각도 상한**은? (현재 기호제거 층은 WARN 상한. 동형자·음차 층은 그보다 더 낮춰야 하는가, 아니면 WARN 아래는 의미가 없는가?)
- **종목명 마스터를 정규화에서 제외**하는 방식은 타당한가? (등록된 종목명과 일치하는 구간은 정규화하지 않고 건너뛴다 — 상장사 목록은 우리가 이미 갖고 있음)
- 이 교환에서 **측정해야 할 지표**는 무엇인가? "정상 8건 오탐 0"은 표본이 너무 작습니다. 대조군을 어떻게 설계해야 이 판단이 근거를 갖습니까?

### P-2. 마침표 가드의 딜레마 — 우연과 회피를 무엇으로 가르는가

같은 마침표인데 둘을 갈라야 합니다:

```
"복원. 금보장 구역입니다"     → 정규화 "복원금보장구역입니다"   → 우연 (오탐이면 안 됨)
"원.금.보.장 확실합니다"      → 정규화 "원금보장확실합니다"     → 회피 (잡아야 함)
```

제 가설은 **규칙성**입니다. 회피는 글자마다 균일하게 기호를 넣고(`원.금.보.장` — 3글자 간격 중 3곳), 우연은 한 곳에만 들어갑니다(`복원. 금보장` — 5글자 간격 중 1곳). 즉 **매칭 구간 안의 구분기호 밀도와 간격의 균일성**이 판별자가 됩니다.

- 이 가설이 타당합니까? 반례는 무엇입니까? (예: `원금, 보장은 불가합니다` — 쉼표 1개, 밀도 낮음, 게다가 부정)
- 밀도 임계값을 정하는 근거는 무엇이어야 합니까? 우리는 λ=4를 쓰므로 **오탐 1건을 늘리려면 미탐 4건 이상을 줄여야** 합니다 — 이 기준으로 임계값을 고르는 절차를 어떻게 짭니까?
- 아니면 밀도가 아니라 **다른 판별자**가 더 낫습니까? (예: 제거된 기호가 모두 같은 종류인가 / 매칭 구간이 형태소 경계와 어긋나는가 / 원문 구간에 조사가 없는가)

### P-3. 학생이 "틀린 서랍"을 여는 것을 신호로 쓸 것인가

2-2의 관찰입니다. 음성 변형에서 학생은 유형을 틀리지만 **무언가에는 반응합니다.** 여기서 두 가지 설계가 가능합니다:

- **(가) 유형 무관 총합 신호**: 8개 라벨 중 최대 확률이 아니라 **총합/엔트로피**를 별도 신호로 보고, "유형은 모르겠으나 정상 같지 않다"를 HOLD 사유로 쓴다.
- **(나) 무시**: 틀린 유형의 지적은 리서처에게 무의미한 안내다("위험 투자 조장입니다"라고 하면 리서처는 무엇을 고쳐야 할지 모른다). 신호가 약하다는 뜻이므로 학습으로 해결한다.

- 어느 쪽입니까? (가)라면 그 신호의 심각도 상한과 리서처에게 보여줄 문구는 어떻게 씁니까?
- (가)는 **오탐을 어디까지 늘립니까?** 정상 문장의 총합 확률 분포를 먼저 재야 한다면, 어떤 표본으로 재야 합니까?
- 근본적으로: **유형을 못 맞히는 것**과 **위반을 못 느끼는 것**은 다른 실패입니다. 지금 학생은 전자입니다. 이건 학습 데이터의 문제입니까, 라벨 체계의 문제입니까, 아니면 14M 모델의 용량 한계입니까? 무엇을 재면 구분됩니까?

### P-4. 은유는 규칙으로 만들 수 있는 것인가 — 그리고 REJECT를 못 하는 문제

④ 은유는 규칙 0%, 학생 50%입니다. 학생이 `노란 앱`·`파란 비행기 아이콘`·`제 프로필 상단 링크`를 잡았습니다. 이건 규칙이 원리적으로 못 하는 일로 보입니다 — 목록이 무한하고, `노란 앱`은 다음 주에 `병아리색 앱`이 됩니다.

그런데 우리 설계상 **학생은 REJECT를 못 합니다.** 즉 은유형 회피는 아무리 잘 잡아도 **보류까지**이고, 사람 검수자의 부담으로 남습니다.

- 이 설계를 유지해야 합니까? 아니면 **일부 유형에 한해** 모델 단독 REJECT를 허용할 근거가 있습니까? (허용한다면 그 조건은 무엇입니까 — 확률 임계? 연속 위반 이력? 규칙과의 동시 발화?)
- 은유를 **규칙화할 수 있는 부분**이 있습니까? 예를 들어 `색상어 + 앱/어플` 같은 **구조**는 목록이 아니라 패턴입니다. 이런 "메타 패턴"이 실용적입니까, 아니면 `노란 우산 관련주` 같은 정상 문장을 막습니까?
- 사람 검수 부담을 어떻게 셉니까? 은유형이 전량 HOLD로 쌓이면 검수자가 몇 건/일을 봐야 하는지가 출시 인력 계획에 직결됩니다.

### P-5. 이 코퍼스를 학습에 넣을 것인가 — 채점지 오염

**지난 회차에서 실제로 저지른 실수입니다.** 외부 AI에게 받은 96건을 전부 학습에 넣었더니, 학습 후 같은 자료로 잰 탐지율이 47%→82%로 올랐지만 **그 숫자가 일반화를 뜻하는지 알 방법이 없어졌습니다.** 독립 채점지(손코퍼스)에서는 순이익이 16→14로 사실상 제자리였습니다.

이번 44건도 같은 갈림길입니다.

- 이 코퍼스를 **전부 채점지로 두고 학습에서 빼는 것**이 맞습니까? 그러면 회피 탐지 능력은 무엇으로 올립니까?
- 아니면 **기법군 단위로 쪼개는 것**이 맞습니까? (예: ①③⑤는 학습, ②④는 채점지 — 기법이 다르면 일반화를 재는 의미가 있으므로)
- 일반적으로: **적대적 코퍼스를 학습셋과 평가셋으로 나누는 원칙**은 무엇입니까? 무작위 분할은 같은 기법이 양쪽에 들어가 평가를 오염시킵니다. **기법군 단위 분할(leave-one-technique-out)**이 정답입니까?
- 우리가 매번 새 기법을 받을 때 **자동으로 홀드아웃을 떼는 절차**를 어떻게 설계합니까? (현재 `gen:ingest`는 전량을 학습으로 보냅니다 — 이걸 고치려 합니다)

### P-6. 군비경쟁의 정지 조건

정규화 표를 늘리는 것은 끝이 없습니다. `텔le그ram`을 막으면 `텔1e그ram`이 오고, 그걸 막으면 `테ㄹle그ram`이 옵니다. **표를 늘리는 방식은 원리적으로 항상 한 수 뒤**입니다.

- 언제 표 늘리기를 멈추고 무엇으로 대체합니까? 정지 조건을 **측정 가능한 형태**로 어떻게 씁니까? (예: "새 기법 1건 추가의 한계 탐지 이득이 X 미만이면 중단")
- 표 대신 쓸 수 있는 **구조적 방어**는 무엇입니까? 후보로 생각한 것들:
  - **정규화 거리 자체를 신호로**: 정규화해서 크게 바뀐 토큰은 그 사실만으로 의심스럽다(무엇으로 바뀌었는지와 무관). `삼성SDI`는 정규화해도 자기 자신이지만 `텔le그ram`은 크게 변합니다. 이건 새 변형에도 자동으로 반응합니다.
  - **종목 마스터 대조**: 등록된 종목명이 아닌데 한글·라틴이 한 토큰 안에서 섞였으면 의심.
  - **문자 단위 모델**: 받은 문서의 제안. 다만 우리 학생은 subword(WordPiece)라 문자 단위가 아니고, 바꾸면 재학습·재보정 전체를 다시 해야 합니다.
- 위 셋 중 **λ=4 아래에서 가장 비용 효율이 높은 것**은 무엇입니까? 그리고 그 판단을 위해 무엇을 먼저 재야 합니까?
- 마지막으로 — **회피 탐지를 규칙에서 완전히 빼고 학생에게 몰아주는 것**은 왜 안 됩니까? 혹은 되는 것입니까? (규칙은 REJECT를 할 수 있고 학생은 못 한다는 비대칭이 이 결정의 축입니다)

각 질문에 대해:

1. **결론** — 무엇을 하라는 것인지 한 문장
2. **근거** — 왜 그 선택인지. 특히 **오탐 비용(λ=4)** 아래에서 어떻게 정당화되는지
