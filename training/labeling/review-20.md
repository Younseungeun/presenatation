# 20차 검토 요청 — 검사기를 둘로 접습니다. 규칙은 어떻게 다스리고, 학생은 어떻게 키웁니까

## 0. 구조 결정 (2026-08-21 창업자 확정)

지금까지 검사기가 넷이었습니다 — 코드 정규식 · 학습 표현 사전 · 의미 검색 · 학생 모델.
**기술이 네 개라서 넷이었지, 질문은 두 개뿐이었습니다:**

```
① 이 글자들이 금지 목록과 맞는가   → 결정적으로 답할 수 있다 → 규칙 엔진
② 이 글의 뜻이 위반인가            → 확률로만 답할 수 있다   → 학생 모델
```

그래서 접습니다:

- **학습 표현 사전은 검사기가 아니라 규칙 엔진의 입력이다.** 창업자의 지적 —
  *"학습 표현 등록은 코드 규칙을 위한 인풋값 아니니?"* — 이 맞았습니다. 사전은 패턴의
  **다른 출처**(운영자가 등록 / 코드에 박음)일 뿐인데 검사 경로까지 갈라 놓아서,
  6층 해석을 하나도 못 받고 있었습니다. 실측:

  | 운영자가 `원금보장` 등록 후 | 규칙 엔진(6층) | 사전(indexOf) |
  |---|---|---|
  | `ㅇ ㅝ ㄴ ㄱ ㅡ ㅁ ㅂ ㅗ ㅈ ㅏ ㅇ` (자모 분리) | 3층이 잡음 | **미탐** |
  | `원금보쟝` (음성 변형) | 5층이 잡음 | **미탐** |
  | `원금 복원. 금보장 구역` (정상) | 간격 판별로 버림 | **오탐** |

  **6층을 안 지나는 구멍이 양방향으로 나 있었습니다.** 코드 패턴이 우연히 주요 표현을
  다 덮고 있어 안 드러났을 뿐 — 사전에 코드에 없는 표현이 등록되는 순간(그게 사전의
  존재 이유입니다) 그 표현은 보호 없이 홀로 섭니다.

- **의미 검색은 삭제한다.** ②와 같은 질문의 중복이고, 임베딩 공급자가 `return null`이라
  지금도 한 줄도 안 돕니다. 오늘 지워도 손실 0입니다.

목표 구조:

```
검사기 = 2  (규칙 엔진 · 학생)
패턴 입력 = 2원천  (코드 패턴 · 운영자 사전) — 같은 6층을 지난다
되먹임 = 운영자 판정 하나가 두 갈래로 갈라져 둘 다 먹인다
   빠른 길: 사전 등록  → 몇 초 만에 규칙 엔진에 (정확히 그 표현만)
   느린 길: 학습 라벨  → 재학습으로 학생에 (비슷한 말까지)
졸업 = 학생이 그 표현을 잡게 되면 사전 항목을 끈다 (사전이 영구 부채가 안 되게)
```

권한 사다리는 유지합니다: 즉시 거절은 **코드 원천 패턴만** · 사전 입력은 WARN까지 ·
학생은 WARN까지.

**고정 제약**: λ=4 · **운영 경로 외부 API 0회** · KoELECTRA-small 14M · 운영자 1~2인

## 1. 19차 답변 이행 결과 — 그리고 반증 하나

### 이행한 것

- **W-6 (`findAll` + `filter` 구조)**: 이번 규칙 엔진 재구조화에 함께 넣습니다 —
  사전 입력 합류와 같은 파일을 고치므로 따로 하면 두 번 뒤집는 셈입니다
- **W-2·W-3·W-5 (`그대로`)**: 유지
- **W-1 (어간+종결어미 압축)**: 실측했습니다. 부정 어휘 든 문장 30건 중
  나열식 30 / 압축형 **23** — 압축형이 오히려 7건을 놓칩니다(`위법`·`금지`·`배제`처럼
  종결어미 없이 문장 중간에 오는 어간들). 나열식을 유지하되 압축형을 **보조로 합치는**
  방향이 맞아 보이는데, X-3에서 묻습니다

### W-4 의 처방("최대값+1")이 반증됐습니다

검토 지시대로 손코퍼스 86 + 대조군 54에서 타겟↔부정어 거리를 쟀습니다.
**위반·정상 라벨을 갈라서** 쟀더니:

```
정상 문장 (창이 덮어야 함)     최소 6   중앙 9   최대 19   (표본 7)
위반 문장 (창이 덮으면 안 됨)   최소 17  중앙 17  최대 17   (표본 1)
```

gap 17 에 정확히 겹칩니다:

```
위반  gap 17  "이 종목은 원금 보장이 되는 구조라 손해 볼 일이 없습니다"
정상  gap 17  "원금 보장은 어떤 경우에도 약속드릴 수 없습니다"
```

**같은 타겟, 같은 부정어(`없`), 같은 거리 — 라벨은 정반대입니다.** 위반 쪽의 `없`은
주장을 무르는 부정이 아니라 **주장을 강화하는 말**입니다("손해 볼 일이 없다" = 보장).
창 크기 N 을 어떻게 잡아도 이 둘은 못 갈립니다. "최대값+1"은 위반 문장의 gap 을 함께
세면 **바로 그 위반을 침묵**시키는 처방이었습니다.

표본이 8건뿐이라 분포라 부르기 민망하지만, **반례 한 쌍이 정확히 같은 좌표에 있다**는
것은 표본을 늘려도 안 변하는 사실입니다. 현행 창 8 유지 + 이 한계를 학생의 몫으로
넘기는 쪽으로 기울었고, X-3에서 묻습니다.

## 2. 검토 질문 — 축이 둘입니다

### 축 A. 규칙 엔진을 어떻게 다스리는가

#### X-1. 사전 입력이 6층에 합류할 때, 층마다 자격이 같습니까

코드 패턴은 6층을 다 지납니다. 사전 문자열도 그래야 한다는 것이 이번 결정인데,
**층마다 위험이 다릅니다**:

| 층 | 사전 합류 시 | 우려 |
|---|---|---|
| 1 원문 | 문제없음 | — |
| 2 기호 제거 | 이득 (간격 판별을 얻음) | — |
| 3 유니코드·자모 | 이득 | — |
| 4 연락처 모양 | **해당 없음** (문자열이 아니라 숫자 묶음) | — |
| **5 음성 변형** | 이득이지만 | **등록 표현의 자모 거리-1 이웃이 정상 용어일 수 있다** — `수익보장` 등록 → `수익보전`(실제 상품 유형)이 거리 1 |
| 6 표기 훼손 | **해당 없음** (개별 표현이 아니라 표기 방식 판정) | — |

- 5층 합류의 안전장치로 **등록 시점 충돌 검사**(종목 마스터 16,553건 + 금융 용어 사전과
  거리-1 대조, `checkWhitelistCollisions` 계열)를 생각했습니다. 충돌하면 그 항목은
  5층에서 빼고 1~3층만 태웁니다. 이 설계가 맞습니까? 충돌 검사가 놓치는 갈래가 있습니까?
- 사전 항목이 규칙이 되면 **규칙 수가 운영 중에 늘어납니다.** 6층 × 항목 수라
  검사 비용이 곱으로 늘고, 항목 간 간섭(한 항목의 매칭이 다른 항목의 간격 판별을
  흔드는 것)이 생길 수 있습니다. 상한을 둬야 합니까? 몇 개부터 문제가 됩니까?

#### X-2. 사전 → 코드 승격의 기준이 필요합니다

사전 항목은 WARN까지고, 코드 패턴만 BLOCK을 냅니다. 그러면 **사전에서 오래 검증된
표현을 코드로 승격**하는 길이 있어야 사다리가 완성됩니다:

```
운영자 등록 (WARN, 즉시)  →  정확도 쌓임  →  코드 승격 (BLOCK 가능, 배포)
                                          →  또는 졸업 (학생이 배움, 항목 끔)
```

- 승격 기준을 무엇으로 잡습니까? 지금 있는 것: 항목별 `matchCount`(걸린 횟수) ·
  `confirmedCount`(반려 확정). "N회 이상 걸리고 정확도 100%"가 후보인데 N 은 얼마입니까?
  Rule of Three 로 유도할 수 있습니까? (오탐률 상한을 보증하려면 N = 3/상한)
- 승격은 배포를 타므로 사람이 하는 게 맞아 보입니다. 그런데 **승격과 졸업이 경쟁합니다** —
  같은 항목이 "코드로 올릴 것"과 "학생이 배웠으니 끌 것" 둘 다일 수 있습니다.
  어느 쪽이 우선입니까? 판단 기준이 뭡니까?

#### X-3. 부정 판정의 관할 — gap 17 겹침이 가른 경계

1절의 반증이 보여준 것: **글자의 거리로는 "주장을 무르는 부정"과 "주장을 강화하는
부정"을 못 가릅니다.** 그 구별은 뜻의 영역이고, 이 구조에서 뜻의 관할은 학생입니다.

- 그래서 이렇게 가르려 합니다 — 규칙의 부정 검사는 **확실한 형태만**(`~지 않/못` 직접
  결합 + 불가능·어렵·힘들) 침묵시키고, 애매한 부정(`없`·`아니`)은 WARN 강등까지만.
  **"부정인데 위반"을 가르는 일은 학생의 학습 목표로 명시**한다. 맞습니까?
- 그러려면 학습셋에 그 대비쌍이 있어야 합니다:
  `손해 볼 일이 없습니다`(위반) vs `약속드릴 수 없습니다`(정상). 손코퍼스에 지금
  몇 쌍 있는지 세면 부족할 것이 뻔한데, **합성으로 대비쌍을 만들어도 됩니까?**
  17차에 "코퍼스를 보고 규칙을 만들면 학습셋이 된다"고 못 박았는데, 학생의 학습셋은
  애초에 학습셋이니 그 금기가 적용되지 않는 것 맞습니까?
- W-1 실측에서 압축형(어간+종결어미)이 나열식보다 7건을 **덜** 덮었습니다.
  나열식 유지 + 압축형을 합집합으로 더하는 것과, 나열식만 유지하는 것 — 어느 쪽입니까?
  합집합은 덮는 범위가 넓어지는 만큼 STRONG 침묵의 범위도 넓어져 미탐 쪽이 열립니다

### 축 B. 학생 모델의 능력치를 어떻게 올리는가

#### X-4. 학습 자료의 사다리 — 지금 가진 것으로 어디까지 갑니까

학생의 존재 이유는 규칙이 원리적으로 못 하는 두 가지입니다:
**패러프레이즈**(같은 뜻 다른 말 — 규칙 기준선 0%)와 이제 **부정 의미 판별**(X-3).

자료 현황:

| 자료 | 양 | 학습 사용 | 비고 |
|---|---|---|---|
| 손코퍼스 | 86문장 | **금지** | 유일한 채점지 |
| 적대 코퍼스 | 90건 | 금지 | 17차에 규칙 학습셋으로 소각됨 |
| 합성 코퍼스 | 491건 | 사용 중 | 교사(대화) 라벨 |
| 운영자 판정 | 0건 | 출시 후 | `train:operator` 배선 완료 |
| 교사 답(수동) | 0건 | 출시 후 | 18차 릴레이 배선 완료 |
| DART 3,000문장 | **미확보** | 오탐 측정용 | `corpus:dart` — API 키 대기 |

- **출시 전에 학생을 올릴 길은 합성 확장뿐입니다** (교사=대화 라벨, 외부 API 0회 유지).
  491 → 얼마까지 늘리는 것이 의미 있습니까? 14M 모델에서 합성 데이터의 수확 체감이
  어디쯤 옵니까? 늘릴 때 **무엇을 늘려야** 합니까 — 패러프레이즈 변형? 부정 대비쌍(X-3)?
  하드 네거티브?
- 합성을 늘리면 **채점지가 그대로 86문장**입니다. 학습셋 3,000 / 채점지 86이면
  채점지가 못 보는 방향으로 과적합해도 모릅니다. 채점지를 늘리는 방법이 있습니까 —
  손으로 더 쓰는 것 말고? (DART는 정상 문장만이라 오탐 축만 잽니다)
- **재학습 트리거**: 19차까지 "오탐 50건 또는 미탐 20건"이 후보였는데 근거가 없습니다.
  수동 라벨 유입 속도(하루 수십 건 상한)를 감안하면 어떻게 정합니까?

#### X-5. 졸업 판정 — "학생이 이 표현을 잡는다"를 어떻게 증명합니까

사전 항목을 끄는 조건이 "학생이 잡는다"인데, 그 증명이 순환에 빠지기 쉽습니다:

- **원 표현만 넣어 보면 부족합니다** — 사전이 잡던 건 원 표현이고, 학생에게 기대하는 건
  변형까지입니다. 그래서 **원 표현 + 자동 생성 변형 K개**를 학생에 넣어 전부 임계값을
  넘으면 졸업, 을 생각했습니다. K 는 얼마고 변형은 어떻게 만듭니까? 변형 생성기가
  규칙의 6층과 같은 논리면(기호 삽입·자모 분리…) **규칙이 이미 잡는 것만 시험하는**
  동어반복이 됩니다
- 졸업시켰다가 학생이 재학습으로 **잊으면**(치명적 망각) 그 표현이 무방비가 됩니다.
  졸업한 표현을 재학습 때마다 자동 재시험하는 회귀 장치가 필요합니까? 그 회귀 목록이
  또 하나의 채점지가 되는 셈인데, 학습셋과의 격리는 어떻게 지킵니까?
- 졸업의 반대 — **학생이 잡는 줄 알았는데 실운영에서 놓친 경우** — 는 미탐 신고로
  잡힙니다. 그때 사전 항목을 자동 재활성화해야 합니까, 사람이 해야 합니까?

#### X-6. 학생의 성적을 실운영에서 어떻게 읽습니까

그림자 모드라 학생 판정은 기록만 됩니다. 운영자 판정과 대조해서:

- **학생만 잡은 위반**(규칙 미탐 + 학생 WARN + 운영자 반려) = 학생의 순기여
- **학생만 잡은 오탐**(학생 WARN + 운영자 승인·오탐 표시) = 학생의 순비용

λ=4 로 접으면 순이익 = 기여 − 4×비용. 이 지표로 라이브 전환을 판단하는 게 맞습니까?
표본이 몇 건이면 판단할 수 있습니까? (전환 전에는 학생이 보류를 못 만들어
"학생만 잡은 위반"이 운영자 눈에 안 띄는 편향이 있습니다 — 그림자 기록을 운영자
화면에 참고로 띄워야 합니까? 그러면 독립성이 또 깨집니다)

## 3. 답변 형식
