# 대화 교사 라벨링 — 절차와 주의

API 종량 과금 없이, 이미 쓰고 있는 구독의 대화형 Claude를 교사로 삼아 라벨을 만드는 경로.

**용도는 학습셋 생산뿐이다 (2026-08-19 2차 검토 H-2 확정).** 대화 라벨은 평가(교사
기준선·채택선)에 인용할 수 없다 — 대화 세션이 코퍼스 원본(정답 포함)을 접했는지 기계적으로
검증할 방법이 없어서다. 평가는 동결된 Ground Truth(손코퍼스 128건의 사람 라벨 + 이후
운영자 판정) 위에서, API 교사(temperature 0)로만 잰다. `eval:teacher -- --from`이
`conversation:` 라벨을 받으면 인용 불가 경고를 강제 출력한다 — 규율이 아니라 도구가 막는다.

## 절차

합성 후보를 만들어 라벨링하는 것이 주 흐름이다:

```bash
npm run label:pack -- --task generate --n 20     # 생성 지시서 → 대화에 붙여넣기
# 받은 JSONL을 training/data/candidates.jsonl 로 저장
npm run label:pack -- --task label --source candidates   # 라벨링 문제지 생성
# pack-N.md 를 대화창에 붙여넣고, 받은 JSONL을 answers-N.jsonl 로 저장
npm run label:ingest -- training/labeling/answers-1.jsonl [...]
```

코퍼스 대상 팩(`--source corpus`)도 남아 있지만 **비공식 참고 측정용**이다 — 코퍼스에는
이미 사람 라벨이 있어 학습 원천으로서의 가치가 없고, 평가로는 인용 불가이기 때문이다.

## 설계상 지켜지는 것

- **규정문을 복제하지 않는다.** 팩은 운영 어댑터의 `SYSTEM_PROMPT`를 그대로 싣는다.
  따로 적으면 프롬프트가 바뀔 때 조용히 어긋나 두 교사의 라벨 기준이 갈린다.
- **정답을 팩에 넣지 않는다.** 사람 라벨·생성 의도는 `manifest.json`에만 있고 팩에는
  없다. 보여주면 교사가 그것을 따라가 독립적인 판정이 아니게 된다.
- **답안은 검증 후에만 병합된다.** id 오타·라벨 오탈자·중복은 `label:ingest`가 막고,
  하나라도 걸리면 아무것도 저장하지 않는다.
- **출처가 기록된다.** `labeler: conversation:claude-opus-5` — 이것이 롤백 레버다.
  학습 후 하네스 지표가 무너지면 그 출처만 걷어내고 재학습한다:
  `python train.py --data … --exclude-labeler conversation:`

## ⚠ 오염 기록 — 2026-08-19 1차 측정

교사 세션이 **코퍼스 원본(`src/domain/__fixtures__/*.ts`)을 이미 읽은 상태**에서 문장
86건을 라벨링했다. 그 파일에는 정답 라벨이 함께 적혀 있어, 판정이 독립적 판단이 아니라
답안 회상일 수 있다. 팩에서 정답을 빼는 방어는 이 경우 무력하다.

측정값(탐지 100% · 오탐 0%)은 **전체를 참고치로 강등한다.** 처음에는 "정상 34건은 세션이
원본을 읽기 전 구간이라 오탐률 0%는 유효"라고 썼으나 철회했다 — 그 구간 구분 자체가 사람의
기억에 기댄 검증이라, "사람의 규율에 기대는 방어는 방어가 아니다"라는 이 문서의 원칙과
모순된다. 유효한 교사 기준선은 API 키가 생기는 날 `npm run eval:teacher`로 처음 나온다.
