# 33차 검토 요청 (사건 구동 — 32차 판정 전건 이행 완료) — 이행 전표 + 판정 사안 5건

32차 II-1~II-5 판정을 그대로 이행했고, 이행 중 실측이 새 판정 사안을 만들었습니다.
순서는 32차 "먼저 재야 할 것" 그대로: ① DART 재평가 → ② zero-shot r6 → ③ 지연 실측 → ④ 런 D.

## 1. 이행 전표

### ① II-2 — DART 게이트 정정: P1-A 통과 확정

게이트 스크립트(`evalControlStudent.ts`)를 **켜진 라벨 기준**으로 고치고(전 라벨 수치는
관측용 병기, 기준 출처는 라이브의 `DEFAULT_ENABLED_LABELS` 한 곳) P1-A 를 공식 재측정:

> 정제판 1,945건 — **켜진 라벨 오탐 0건 (0.00%)** · 전 라벨 6건(전부 CARD_MISMATCH) → **통과**

반증 조건(활성 라벨 오탐 1건 이상) 미실현 — RISK_INDUCEMENT·PROFIT_GUARANTEE 포함 활성
라벨 소견이 정확히 0. r5 소급: 7건 = CM 3 + EVASION 표 조각 4 → **켜진 라벨 4건**. 여전히
기준(3) 초과지만 CC-1(게이트는 채택 관문, 소급 퇴출 아님)이 그대로 적용되어 라이브 유지.

### ② II-5 — 최종 도장: r6 격리본 264 zero-shot (r5 vs P1-A)

264건 = 위반 134(PG 58·PRIVATE 38·SOLICIT 38) + **부정형 하드 네거티브 130**. 어느 쪽
학습에도 안 들어간 자료(P2 런들만 학습, P2 는 후보 아님). `probe:zeroshot-r6` 신설.

| t=0.7 | r5 | **P1-A** |
|---|---|---|
| PROFIT_GUARANTEE 탐지 | 50.0% | **77.6%** |
| PRIVATE_INFO 탐지 | 34.2% | **60.5%** |
| SOLICIT_CONTACT 탐지 | 65.8% | **50.0%** ⚠ 유일한 하락 |
| 부정형 130 오탐 | 14건 (10.8%) | **3건 (2.3%)** |
| 부정형 최대점수 중앙값 | 0.327 | **0.073** (부정 구분이 구조적으로 좋아짐) |
| λ=4 순이익 환산 | +11 | **+75** |

반증 조건(일반화 향상 없음 / 오탐 폭증 = 통짜 암기) **미실현** — 학습 안 한 자료에서
탐지가 오르고 오탐이 1/5 로 줄었습니다. **P1-A 를 차기 교체 후보로 확정 기록했습니다**
(training/README.md · ledger). SOLICIT 하락(66→50%)은 아래 JJ-4 로 올립니다.

### ③ II-4 (a) — 지연 최적화 실측: 세 가지 발견

**(1) ONNX 패딩 배치는 손해입니다 — gap 17 경고 그대로.** 실측(i7-9700F 8코어): 배치
추론이 창당 82~123ms 로 낱개(65~83ms)보다 느립니다(메모리 대역폭 + 패딩 헛계산). 게다가
큰 배치 요청 하나가 클라이언트 타임아웃(2s)을 넘어 낱개 폴백과 겹치는 최악 경로까지
실측됐습니다. → 채택한 것은 **전송 묶음**: `/screen_batch` 는 한 요청으로 창 여러 개를
받되 **서버 안에서 낱개로 실행**(계산이 /screen 과 동일 — 판정이 갈라질 자리 없음),
클라이언트는 8창씩 조각. 왕복·파싱 비용(요청당 ~45ms)만 제거합니다. 옛 사이드카(404)면
낱개 경로로 자동 복귀 — 창 방어가 조용히 꺼지는 일은 없습니다.

**(2) 진짜 지렛대는 그래프 융합이었습니다.** onnxruntime transformers optimizer 로
Attention·LayerNorm·GELU 를 융합(fp32 유지, 가중치 불변): **로짓 최대 차 1.4e-6** (배치
축 포함 무작위 대조), 512tk 단건 699→433ms(−38%). int8 규칙을 준용해 **별도 후보**로
만들었습니다 — `fuse_candidate.py`, 카나리아를 융합 파일로 재굽기, 오차 1e-4 초과 시
자동 폐기, `out/candidates/a0e3d04aa8892cdc-fused/`, sha `923921208bfc6815`.

**(3) 합산 실측** — 최악 길이(≈700tk, 창 10~11) 문서 100건, 같은 클라이언트 경로,
두 모드의 소견 문서 단위 대조:

| P1-A 서빙 | P50 | P95 | P99 | 판정 동일성 |
|---|---|---|---|---|
| 기저 fp32 · 낱개 순차 | 2,025ms | 3,292ms | 4,050ms | — |
| 기저 fp32 · 전송 묶음 | 1,694ms | 2,870ms | 5,505ms | 불일치 0 |
| **융합 · 낱개 순차** | 1,385ms | 1,668ms | 1,883ms | — |
| **융합 · 전송 묶음** | **1,309ms** | **1,511ms** | **1,651ms** | **불일치 0/100** |

P95 가 예산(1,500ms) 위 **11ms** 입니다. 단 측정 조건이 최악 방향으로 보수적입니다 —
100건 전부 상한 길이(실제 리포트는 제목100+요약300+본문1,000자를 꽉 채운 것만 700tk),
기계 상태 변동 ±20~50% 실측(같은 셋이 회차 간 P50 1,634→2,126ms 로 흔들림). 부검 때
낱개 1,283~1,545ms 로 잰 것과 같은 계열의 변동입니다. → JJ-2.

### ④ II-3 — 핑 재선정: PRIVATE 교체 완료, PG 는 교집합이 비어 있음

측정 도구 `scripts/selectPings.ts` 신설(현행 8문항 + 후보를 r5·P1-A 양쪽에 실측).

- **PRIVATE 위반 핑 교체**: 구 문장(r5 0.834 — 미달, 자격 박탈) → 신규 "어제 그 회사
  재무팀 친구한테…" **r5 0.859 / P1-A 0.947** — 교집합 통과. `check:ping` 오염 0,
  시험 64건 통과.
- **PG 는 재선정이 불가능했습니다**: 명백한 위반 문장 9종(직설 보장·보전·배상 변주)을
  실측한 결과 **r5 의 PG 최고점이 정확히 현행 핑(0.839)** 이고 나머지는 0.50~0.83.
  P1-A 는 전부 0.90+. 즉 미달의 원인은 문장 자격이 아니라 **r5 PG 헤드의 상한(~0.84)**
  입니다. 32차 반증 조건("명백한 위반인데 110M 만 헷갈리면 퇴행")의 정확히 반대 —
  헷갈리는 쪽이 r5 입니다. 현행 문장 유지 + 코드 주석에 기록. → JJ-3.
- 나머지 6문항(RUMOR·SOLICIT 위반, 정상 4)은 양 모델 모두 여유 통과 (위반 r5 0.862/0.865 ·
  P1-A 0.966/0.940, 정상 최대 r5 ≤0.249 · P1-A ≤0.282).

### ⑤ II-1 — 런 D: 신규 사전 등록 → 실행 → **수렴** (게이트 결과 포함)

`training/README.md` 에 **별도 라운드의 새 가설**로 먼저 등록했습니다(가설: B 미수렴은
관례 설정의 결함이 아니라 에폭 부족 / gap 17: D 성공 = "B설정+12에폭"이라는 새 설정의
성공이지 B 의 소급 통과가 아님 / 반증: 12에폭에도 미수렴, 또는 C 형 EVASION 폭증·시소).

**학습 결과 (GPU, P1 × B설정 × 12에폭, 유효 배치 16):**

> loss 36.98 → **9.07**, macro-AP **0.900** (A 런 0.923), val 순이익 +28.
> B(5에폭)가 멈춘 loss 22.9 는 이 곡선의 **4에폭 자리**입니다 — 과소적합 가설이
> 학습 곡선 위에서 그대로 확인됐습니다. 등록된 반증 조건 ①(미수렴)은 기각.

부수: int8 동적 양자화 **4연속 자동 폐기**(검증 오차 1.12) — "110M 은 fp32 전제" 재확인.

**게이트 배터리 (sha `e034179618355e63`, CPU 사이드카 — A·B·C 런과 동일 항목):**

| 게이트 (t=0.7) | P1-A (참조) | **P1-D** | 판정 |
|---|---|---|---|
| DART 정제판 (켜진 라벨) | 0 | **0** (전 라벨 3 — 전부 CM, P1-A 의 6보다도 적음) | ✓ |
| 시소 (기준 r5) | 비겨냥 1 ✓ | **비겨냥 새 탈락 8** (PG 4·RUMOR 3·PRIVATE 1) + 겨냥 1 | ✗ **용량 경보** |

C 는 과민(EVASION 폭증·가짜 소견), D 는 **마진 침식**(점수 대역 전체가 낮아 r5 가 잡던
비겨냥 문장 8건이 임계 밑으로 가라앉음 — score-median 이 그대로 보여줍니다: PRIVATE 0.551,
PG 0.637). 등록한 반증 조건 ②의 문언(EVASION 재현)은 아니지만, 결론부("110M 은 r5 설정
근방에서만 채택 가능 성적")는 **한 번 더, 다른 실패 모양으로** 지지됐습니다.
새 라운드의 등록 조건(A·D 일치)은 **불성립** — 관례 설정은 12에폭으로 수렴 문제를 풀어도
성적 문제를 못 풉니다.

## 2. 판정 사안 (JJ-1~JJ-5) — 각각 그대로 / 고쳐서(대안) / 폐기(이유), gap 17 함정, 반증 조건

#### JJ-1. 런 D 게이트 탈락 후 — "설정 축은 닫혔다"를 확정 기록해도 됩니까
D 가 수렴하고도 게이트에서 탈락하면서, 설정 축의 실측이 넷이 됐습니다: B(5에폭) 미수렴 ·
C(lr 1e-4) 과민 · D(12에폭) 마진 침식 · **A(r5 설정)만 채택 대역**. 저희 안: ① "110M 의
채택 가능 대역 = r5 설정"을 확정 사실로 기록하고 **설정 탐색 런을 종료**합니다(에폭 8~10,
lr 2.5e-5 같은 중간값 탐색은 결과 보고 설정을 고르는 gap 17 경로) ② 용량 우위의 증거는
31차 A런 셋(P0/P1/P2 에서 일관)과 zero-shot r6 로 이미 서 있으므로, "A·B' 일치" 형태의
확정은 **포기**하고 그 사실을 그대로 적습니다 — 등록 조건을 충족하는 데이터를 찾을 때까지
런을 반복하는 것이야말로 사전 등록의 반대입니다. 이 종결이 맞습니까, 아니면 남은 정보가
있어 추가 런이 정당합니까? 교체 후보는 어느 경우에도 **P1-A 그대로**입니다.

#### JJ-2. 지연 — P95 1,511ms (예산 위 11ms), "(a) 극한 적용" 판정
32차 반증 조건은 "(a) 극한 적용에도 P95 1,500ms 지속 초과 → 110M CPU 서빙 폐기, (b)".
실측이 정확히 경계에 앉았습니다. 저희 판단 재료: ① 측정 셋이 최악 길이 100% 구성이라
운영 분포에서는 P95 가 이보다 내려갑니다(짧은 문서는 창 자체가 안 돎) ② 같은 셋의
회차 간 변동(±20~50%)이 11ms 보다 훨씬 큽니다 ③ 반대로, "경계에서 유리한 해석을
고르는 것"이 gap 17 입니다. 선택지: (가) 운영 길이 분포로 재측정 후 판정 (나) 예산의
정의를 "최악 길이 P95"가 아니라 "운영 분포 P95"로 명문화 (다) 지금 수치로 (b) 착수.
저희는 (가)가 맞다고 봅니다 — 실제 분포 없이 (나)를 정하면 그것도 사후 변형입니다.

#### JJ-3. PG 핑 선정선 — r5 대에는 0.85 가 달성 불가능한 값입니다
9문장 실측으로 r5 PG 헤드 상한이 ~0.84 임이 확인됐습니다. 라이브 집행은 t=0.7(여유
0.14)이라 운영 위험은 없습니다. 선택지: (가) 선정선 0.85 유지 + "r5 대 PG 는 달성 불가"
를 기록으로 남김(현행 조치) (나) 선정선을 "min(0.85, 현행 모델 상한 −여유)"로 정의
변경. (나)는 선정선이 모델을 따라 움직이는 것이라 gap 17 냄새가 있어 저희는 (가)로
두었습니다 — 판정 부탁드립니다.

#### JJ-4. SOLICIT_CONTACT zero-shot 하락 (r5 65.8% → P1-A 50.0%)
세 과목 중 유일한 하락입니다. t=0.5 에서도 92→71%. 가설: r8 자료(P1 추가분)가
UNSUPPORTED·CM 겨냥이라 SOLICIT 은 헤드 간 간섭을 받았을 가능성. 다만 라이브 운영에서
SOLICIT 은 **규칙(연락처 묶음 모양·채널 어휘)이 1차 방어**라 학생 단독 하락의 운영 영향은
제한적입니다. 질문: 이것을 후보 확정의 유보 조건으로 봅니까, 기록·계측 대상으로 봅니까
(출시 후 운영 50건 적립 시 SOLICIT 재측정)?

#### JJ-5. 융합본의 지위 — 승격 시 서빙 본체를 융합본으로 합니까
로짓 차 1.4e-6 이라 수치적으로 같은 모델이지만, 파일이 다르면 다른 모델(int8 규칙)이라
별도 후보로 두었습니다. 승격 시나리오: 교체 사건이 오면 **융합본이 게이트 전수를
재통과한 뒤 서빙 본체**가 되고 fp32 원본은 보관·재융합 원천으로 남습니다. 게이트가
로짓 동일성 위에서 도는 이상 결과는 P1-A 와 같을 것이 예상되지만, 예상을 근거로
게이트를 건너뛰지 않습니다. 이 절차가 맞습니까?

## 3. 답변 형식
JJ-1~JJ-5 각각 그대로 / 고쳐서(대안) / 폐기(이유), gap 17 함정, 반증 조건.
JJ-2 가 출시 경로에 걸려 있어 먼저입니다.
