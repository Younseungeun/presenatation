# 15차 검토 요청 — 사후 대응 네 라운드 뒤, 어디로 가야 하는가

## 0. 이 문서의 위치

13차에서 표기 회피 방어를 붙였고, 14차에서 그 구현이 **운영에서는 꺼져 있었다**는 것을 발견해 관측 장치를 넣었습니다. 이 문서는 14차 답변(R-1~R-6)의 구현 결과와, 그 과정에서 새로 드러난 것을 놓고 다음을 묻습니다.

**고정 제약** (변함없음): 즉시 거절은 결정적 규칙만 · λ=4 (오탐 1건 = 미탐 4건) · 운영 경로에서 외부 API 0회 · 학생 모델은 KoELECTRA-small 14M

## 1. 14차 답변 중 구현한 것

### R-1 조용한 무동작 관측 → **규칙 카나리아 + 구조 시험**

층마다 정답이 정해진 문장 하나씩, 정상 문항 둘. 총 6문항이 **운영과 같은 함수**(`collectFirstTierFindings`)를 통과합니다.

| 문항 | 층 | 죽었을 때 잃는 것 |
|---|---|---|
| `원금을 보장해 드리겠습니다` | 원문 | 정규식이 통째로 죽음 |
| `원.금.보.장 확실합니다` | 기호 제거 | 글자 벌린 회피가 전부 통과 |
| `ㅇ ㅝ ㄴ ㄱ ㅡ ㅁ ㅂ ㅗ ㅈ ㅏ ㅇ 해 드립니다` | 깊은 정규화 | 낱자·유니코드 회피가 전부 통과 |
| `텔le그ram 으로 오세요` | 훼손 신호 | **종목 마스터 미배선 = 14차 사고** |
| `과거 수익률이 미래 수익을 보장하지 않습니다` | 정상 | 표준 면책 문구가 막힘 |
| `삼성SDI의 하반기 실적을 분석했습니다` | 정상 | 정상 종목명이 회피로 지적됨 |

- 기동 직후 1회 + 매시 정각. 실패하면 **어느 층이 죽었는지**와 함께 운영자 알림
- **성공했을 때만** 박동(`AppSetting`)을 찍습니다. 실패도 찍으면 "돌긴 돌았다"가 "괜찮다"로 읽힙니다
- **카나리아의 카나리아**: 보류 큐 운영(매일 07:00)이 박동을 읽어 하루 넘게 낡았으면 알립니다. 둘 다 죽으면 스케줄러가 죽은 것이라 기존 워치독이 잡습니다 — 거기서 퇴행이 끝납니다
- 시험이 **"종목 마스터를 안 넘기면 훼손신호 문항이 빨개진다"**를 강제합니다. 이게 없으면 카나리아가 배선을 못 잡는 카나리아가 됩니다

### R-3 보이지 않는 문자 → **서식 전용은 제거, 결합 문자·태그는 신호로**

| | 이전 | 지금 |
|---|---|---|
| ZWSP · ZWNJ · ZWJ · 워드조이너 · 소프트하이픈 · 좌우재정의 · BOM | **5/7 뚫림** | 7/7 잡힘 |
| 한글 위 결합 문자 (`원́금́보́장́`) | 뚫림 | 잡힘 (지우지 않고 지적) |
| 유니코드 태그 블록 (U+E0000~) | 뚫림 | 잡힘 |
| 이모지 📈 · 라틴 결합 문자 `café` | — | **건드리지 않음** |

결합 문자를 지우지 않는 이유는 검토 답변대로입니다 — 지우면 **공격자 대신 원문을 복원해 주는 꼴**입니다.

### R-4 화이트리스트 감시 → **매일 06:00 동기화 직후 충돌 검사, 알리기만**

그리고 **지금 실제로 2건 충돌합니다:**

```
올 인 퓨처테크 얼라이언스 (AIFA)  →  RISK_INDUCEMENT
루시드 다이어그노스틱스 (LUCD)    →  RISK_INDUCEMENT
```

둘 다 **②층(공백 제거) 정규화가 만든 우연**입니다:
- `올 인 퓨처테크` → `올인퓨처테크` → `올인` 매칭
- `루시드 다이어그노스틱스` → `루시드다이어그노스틱스` → **`시드다`**가 `시드\s*(전부|다)`에 매칭

**이 종목을 분석하는 리서처는 지금도 전부 보류에 걸립니다.** 검사를 넣기 전에는 아무도 몰랐습니다.

## 2. 구현 중 새로 드러난 것

### 2-1. 깔때기 가정은 **77%만** 참입니다

13차에서 이렇게 설계했습니다: 표기 회피는 유형을 짚지 못하고 "정상 표기로 고치라"만 말하되, **고친 글이 전체 규칙을 다시 만나 거기서 진짜 유형이 나온다.**

회피 신호만 걸린 13건을 **사람이 정상 표기로 고쳤다고 가정**하고 다시 통과시켰습니다:

| | |
|---|---|
| 고친 뒤 진짜 규칙에 걸림 | **10건 (77%)** — 깔때기 성립 |
| 고친 뒤 아무것도 안 걸림 | **3건 (23%)** — 한 바퀴 헛돎 |

**⚠ 이 측정은 자동으로 할 수 없었습니다.** 우리 설계가 해독을 거부하므로 시스템은 "고친 글"을 만들지 못합니다 — 손으로 13건의 정상 표기를 적어야 했습니다. 즉 **깔때기 가정은 원리적으로 자동 검증이 불가능**하고, 이건 R-2/R-6 판단의 전제입니다.

### 2-2. 헛돈 3건이 같은 구멍을 가리킵니다 — **연락처 규칙이 아예 없습니다**

```
"연락처 0l0-팔구23-칠팔90 입니다"  → 고침 "연락처 010-8923-7890 입니다"  → 소견 없음
"O1O_3321_4455 문자주세요"        → 고침 "010-3321-4455 문자주세요"     → 소견 없음
"ⓘⓓ : kakao_trust100 입니다"      → 고침 "아이디 : kakao_trust100 입니다" → 소견 없음
```

**정상 표기로 적은 전화번호·아이디는 어떤 규칙에도 걸리지 않습니다.** `SOLICIT_CONTACT`는 채널 이름(`카카오톡`·`텔레그램`)만 보고, 연락처 자체는 안 봅니다.

즉 지금 시스템에서 가장 쉬운 우회는 **회피 표기가 아니라 아무 표기도 안 하는 것**입니다 — 그냥 번호를 적으면 됩니다. 네 라운드 동안 회피 표기를 쫓는 사이 이 자리가 비어 있었습니다.

### 2-3. 구현하지 않은 것: R-2 · R-6

두 답변은 서로 묶여 있습니다(④층 λ<1은 반려 카운터 제외가 전제). 구현하지 않은 이유:

- **R-2가 요구한 측정 둘 중 하나(깔때기 비율)를 이제 얻었지만(77%), 나머지(무한 루프 세션 비율)는 운영 데이터가 없으면 못 잽니다.**
- 그리고 77%라는 숫자 자체가 판단을 바꿉니다 — 23%가 헛돈다면 "카운터에서 빼면 안전하다"는 근거가 약해집니다. 헛도는 경로가 곧 공격자의 무한 재제출 통로입니다.
- 게시 흐름은 돈·상태가 걸린 경로라, 근거가 흔들리는 상태에서 손대지 않았습니다.

## 3. 검토 질문

### S-1. 연락처 규칙을 어떻게 만드는가 (2-2)

지금 없습니다. 만들어야 하는 것은 분명한데 오탐이 무섭습니다 — 리포트에는 숫자가 가득합니다:

```
정상: "목표가 71,000원"  "2026-08-20 실적 발표"  "3분기 매출 1,234억"  "PER 12.5배"
      "010 사업부"        "2024-2026 CAGR"       "1주당 8,923원"
우회: "010-8923-7890"    "01089237890"          "공일공 팔구이삼 칠팔구공"
```

- 어떤 형태로 규칙을 씁니까? 전화번호 패턴(`01[016789]-?\d{3,4}-?\d{4}`)만으로 충분합니까?
- **한글 숫자 표기**(`공일공 팔구이삼`)는? 이건 다시 표가 됩니다 — 14차 R-3에서 "닫힌 집합이면 표를 써도 된다"고 했는데, 한글 숫자는 열 글자짜리 닫힌 집합입니다. 같은 논리가 적용됩니까?
- 심각도는? 연락처는 `SOLICIT_CONTACT`처럼 **BLOCK(즉시 거절)**이어야 합니까, 아니면 WARN입니까? 정상 리포트에 전화번호가 들어갈 이유가 있습니까?
- 아이디 형태(`kakao_trust100`, `@target_stock`)는 어떻게 합니까? 이건 패턴이 훨씬 넓습니다
- **λ=4 아래에서 어떤 오탐률까지 허용됩니까?** 그리고 그걸 재려면 어떤 대조군이 필요합니까 (지금 정상 대조군은 8건뿐입니다)

### S-2. 화이트리스트 충돌 2건을 어떻게 처리하는가 (1-R-4)

`올 인 퓨처테크 얼라이언스`와 `루시드 다이어그노스틱스`가 지금도 보류에 걸립니다. 검토 답변대로 **자동 제외는 하지 않았고**, 알림만 나갑니다. 그래서 결정이 남았습니다.

선택지:
- **(가) 규칙을 좁힌다** — `올인`에 경계를 요구(`\b올인\b` 류), `시드\s*(전부|다)`를 `시드\s*(전부|다)\s*(넣|투입|매수)`로. 위험: 진짜 위반을 놓친다
- **(나) 종목명 예외를 손으로 넣는다** — 그 이름이 문장에 있으면 그 구간을 규칙에서 뺀다. 위험: 예외 목록이 자란다
- **(다) 그대로 둔다** — 2건이고 운영자가 승인하면 된다. 위험: 마스터가 자랄수록 늘어난다

- 어느 쪽입니까? 판단 기준은 무엇입니까?
- 더 근본적으로: **②층 정규화가 정상 종목명에 우연을 만든다**는 것이 이번에 드러났습니다. `복원. 금보장`은 간격 판별식으로 걸렀는데, 이건 공백만 든 정상 어절이라 간격 판별식에 안 걸립니다. **정규화 층에 종목명 화이트리스트를 적용해야 합니까?** (지금은 ④층에만 씁니다)
- 연간 몇 건이 새로 생길지 어떻게 추정합니까?

### S-3. 깔때기가 77%면 R-2·R-6을 어떻게 결정하는가 (2-1, 2-3)

14차 답변은 ④층 지적을 반려 카운터에서 빼고 λ<1로 공격적으로 잡으라고 했습니다. 근거는 "공격자가 유효한 회피를 완성하려면 결국 ①~③층에 걸리고 그때 카운터가 올라간다"였습니다.

**측정: 77%만 그렇습니다.** 23%는 고쳐도 아무것도 안 걸립니다.

- 77%면 충분합니까? 판단 문턱이 있습니까?
- 23%가 곧 **무한 재제출 통로**입니다 — 그 경로로 카운터 없이 계속 시도할 수 있습니다. 검토 답변은 Rate Limiting으로 대응하라고 했는데, 그것이 규칙 이진 탐색을 실제로 막습니까? (탐색은 느려질 뿐 멈추지 않습니다)
- 대안으로 **"회피 지적이 반복되면 그 자체를 카운터에 넣는다"**(예: 같은 리포트에서 5회)는 어떻습니까? 성실한 사람은 1~2회에 고치고 탐색자는 반복합니다
- 그리고 2-1의 사실 — **깔때기 가정은 자동 검증이 불가능합니다**(해독을 거부하므로). 검증할 수 없는 가정 위에 처분 정책을 세우는 것이 옳습니까? 이걸 어떻게 다뤄야 합니까?

### S-4. 카나리아 6문항이 낡는 것을 어떻게 다루는가 (1-R-1)

지금 카나리아는 **오늘의 규칙**에 맞춰져 있습니다. 규칙을 고치면 카나리아를 함께 고쳐야 하고, 그때 **카나리아를 규칙에 맞추는 것**이 자연스러운 유혹입니다 — 그러면 카나리아는 규칙이 무엇을 하든 초록입니다.

- 이 유혹을 무엇이 막습니까? "카나리아 수정 시 사유를 적게 한다" 같은 절차가 실효가 있습니까?
- 문항 수는 6이 맞습니까? 늘리면 코퍼스와 구별이 흐려지고, 줄이면 층을 못 덮습니다. **카나리아와 평가 코퍼스의 경계**를 무엇으로 정합니까?
- 카나리아가 **매시간** 도는 것이 맞습니까? 배포 직후가 가장 위험한데, 배포를 감지해서 도는 편이 낫습니까?
- 반증: 카나리아는 초록인데 실제 검수가 나빠지는 경우는 어떤 모양입니까? (14차 답변은 "특권 경로"를 지목했는데, 지금은 같은 함수를 씁니다 — 그 외에는?)

### S-5. 학생 모델 재학습을 지금 해야 하는가 (14차 R-5)

14차 답변은 오염된 96건을 격리하고 44건을 영구 홀드아웃으로 고정하라고 했습니다. 44건은 고정했지만 **96건 격리와 재학습은 하지 않았습니다.**

- 지금 해야 합니까? 재학습하면 **회피 탐지 능력이 함께 사라질 수 있고**(그 96건이 유일한 회피 학습 자료), 그러면 ③음성 변형(현재 100%)이 무너집니다
- 다만 규칙 층이 ①②⑤를 맡게 되었으므로 학생이 잃어도 되는 부분이 늘었습니다. **역할 재분배 후에 재학습**하는 것이 순서상 맞습니까?
- 재학습 전후를 무엇으로 견줍니까? 44건은 이제 채점지인데, ③④에 대한 문항이 각각 5건·8건뿐입니다. 이 표본으로 판단할 수 있습니까?
- "데이터 부족과 14M 용량 한계를 구별하는 방법"에 대한 답을 14차에서 못 받았습니다. 다시 여쭙니다

### S-6. 네 라운드가 전부 사후 대응이었습니다 — 어떻게 앞서 나갑니까

돌아보면 이 순서였습니다:

| 라운드 | 계기 |
|---|---|
| 12차 | 창업자가 손으로 써 보다 `원금을 보장` 통과를 발견 |
| 13차 | 외부 AI가 회피 기법 목록을 줌 |
| 14차 | 구현하고 나서 배선 누락을 발견 |
| 15차(지금) | 깔때기를 재다가 연락처 구멍을 발견 |

**전부 우연히 발견했습니다.** 매번 "이번엔 막았다"고 보고했고 매번 다음 라운드에서 더 큰 구멍이 나왔습니다.

- 이 패턴을 깨는 방법이 있습니까? 아니면 **적대적 방어는 원래 사후적**이고, 목표는 "구멍이 없다"가 아니라 **"발견 주기를 짧게 한다"**여야 합니까?
- 후자라면 발견 주기를 무엇으로 잽니까? 지금은 우연이라 주기 자체가 없습니다
- **공격면 목록을 체계적으로 만드는 방법**이 있습니까? 지금 우리가 아는 축은 (표기 훼손 / 은유 / 문맥) 셋인데, 이 분류가 완전하다고 믿을 근거가 없습니다
- 출시 전에 어디까지 막아야 합니까? **"막지 못한 것을 아는 상태"**로 출시하는 것과 "다 막았다고 믿고" 출시하는 것 중 전자가 낫다는 것은 알겠는데, 전자를 어떻게 문서화하고 운영자에게 전달합니까?
