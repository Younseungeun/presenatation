# 31차 이행 — 부검 절차 사전 등록 확정 + int8 도구 검증 (r5 → int8)

2026-08-22. HH-1~HH-5 **전건 그대로**. 부검 절차는 `training/README.md` "110M 부검 런 — 사전 등록"으로
박혔다. 먼저 재야 할 것 넷 중 셋은 기록(A/B 설정·기준 스냅샷 r5·P0 sha 동결), 하나는 실측이었다.

## int8 도구 검증 — 파이프라인에 구멍이 있었고, 고쳤고, int8 은 공짜가 아니었다

**발견 1 — 양자화가 r5 에서 실패하고 있었다.** `export_onnx.py` 의 int8 단계는 예외를 삼키고 fp32 로
가도록 돼 있어, r5 가 int8 없이 나간 사실을 아무도 몰랐다. 원인: onnxruntime 양자화 전 형상 추론이
내보내기가 남긴 낡은 `value_info`(814건)와 충돌 — "Inferred shape and existing shape differ 256 vs 8".
공식 전처리(`quant_pre_process`)로도 같은 오류. **`value_info` 를 지우면 통과**(14.3MB). 검토자가 이
검증을 지금 시키지 않았다면 110M int8 에서 "110M 고유 문제"로 오진했을 자리다.
→ `training/quantize_candidate.py` 신설(보관본 → `out/candidates/<sha>-int8/`, 카나리아는 int8 로 구움),
`export_onnx.py` int8 경로 같은 수리.

**발견 2 — int8 은 별도 지문이고 게이트를 따로 통과해야 한다 (HH-4)가 옳았다.** 후보 사이드카(8766)에
올려 전부 다시 잰 결과:

| 게이트 / 프로브 | r5 fp32 (a0eaa12a) | **r5 int8 (adfd9aef)** | 판정 |
|---|---|---|---|
| 카나리아 | 통과 | 통과 (int8 로 구운 정답, 오차 4.9e-07) | ✓ |
| 순이익 t0.7 (λ=4) | +8 / 새오탐 0 | **+8 / 0** | ✓ 동일 |
| 핑 위반 마진 | PG 0.839 · PRIVATE 0.834 | PRIVATE 0.83 (PG 통과) | 30차와 같은 상태 |
| **DART 정제판 오탐** | 7 (소급 비적용) | **10** (EVASION 4→6 · PG 0→1) | ✗ 악화 |
| 시소 (비겨냥 새 탈락) | — | 1 (RUMOR 0.72→0.68) | ✓ ≤2 |
| 부사 스프레드 | 0/4 | 0/4 | 동일 |
| 희석 잔존 | 13% | 13% | 동일 |
| 점수 분포 PRIVATE 중앙값 | 0.472 | 0.457 | 동일 모양 |
| **fp32↔int8 피어슨 r** (정상 1,000문장 × 8라벨) | — | **0.9937** (반증선 0.95) · 최대 Δ 0.096 · t0.7 뒤집힘 5/8,000 | ✓ |
| 지연 (채점지 문장) | 18.3ms | **8.3ms** | −55% |

읽기: 양자화는 **지식을 파괴하지 않았고**(r 0.994, 순이익 동일, 시소 없음) 지연을 절반으로 줄였지만,
**DART 정상 산문에서 오탐 3건을 더 만들었다.** 경계 근처(0.65~0.75)에 있던 공시체 문장이 양자화 잡음으로
0.7 을 넘은 것 — 8,000쌍 중 뒤집힘 5건이 정확히 그 모양이다. **int8 r5 는 승격 자격 없음**(DART 게이트).
110M int8 도 같은 자리에서 같은 일이 날 것이므로, 부검의 지연 측정은 fp32·int8 둘 다 하되 int8 은
DART 를 반드시 따로 본다.

**도구 쪽 결론**: 양자화 스크립트·카나리아(int8 정답)·후보 사이드카·게이트 재실행·상관 프로브 — 전부
동작 확인. 110M int8 에서 게이트가 터지면 그건 도구가 아니라 모델이다.
