# 31차 검토 요청 — 110M 부검 런의 사전 등록: 무엇으로, 어떻게 만들고, 무엇을 재서, 어떻게 판정하나

## 0. 성격 — 사건이 아니라 사전 등록

30차 GG-5 기준으로 이것은 사건이 아닙니다(새 실측이 없음). 그러나 FF-2 가 "결과를 본 뒤 규칙을 정하면
결과에 맞춰 정하게 된다(Y-4형)"고 했고, 부검 런은 **절차 자체가 결과를 바꿀 수 있는** 실험입니다 —
학습률 하나, 데이터 한 벌이 "110M 통과/기각"을 가릅니다. 그래서 가중치가 오기 전에 절차를 박고,
가중치가 오면 **이 문서대로만** 돌립니다. 답변이 오면 그대로 `training/README.md` 의 부검 절차가 됩니다.

**고정 제약**: λ=4 · 외부 API 0회 · 출시 모델 r5 · 학습 금지 목록 · CPU 추론 · 지연 예산 1,500ms/문서
(운영 길이 ≈700tk) · 14M 재학습 금지(부검 통과가 재개 사건) · 이 환경은 HF 차단(가중치는 창업자가
브라우저로 `local_models/student-base-110m/` 에 넣음).

## 2. 제 안 — 부검 런 절차 (반박 대상)

### 2-1. 베이스와 머리
- 베이스: `monologg/koelectra-base-v3-discriminator` (110M, 같은 계열 → 토크나이저 계약·`buildStudentText`
  직렬화 그대로). **같은 계열을 고집하는 이유**: 다른 계열(RoBERTa·DeBERTa)이면 "용량" 과 "아키텍처"
  두 변수가 섞여 부검이 아무것도 가르지 못합니다
- 머리: 14M 과 **같은 8차원 분류 머리**. CARD_MISMATCH 용 NLI 머리는 **별도 2차 실험** — 같은 런에
  넣으면 분류 성적과 NLI 성적이 서로를 오염시킵니다

### 2-2. 학습 설정 — "같은 설정"의 뜻
FF-2 는 "14M 과 같은 설정"이라 했지만 lr 3e-5·batch 16 은 14M 에 맞춘 값입니다. 110M 에 그대로 쓰면
**과적합 또는 발산**이 나고, 그건 용량의 문제가 아니라 설정의 문제인데 결과는 "110M 도 실패"로 읽힙니다.
제 안:
- **런 A (대조)**: r5 설정 그대로 — 비교 가능성 확보
- **런 B (관례)**: lr 2e-5 · batch 16 · epochs 5 · warmup 10% · weight decay 0.01 — base 급 파인튜닝 관례값
- 둘 다 돌리고 **더 좋은 쪽이 아니라 둘의 일치 여부**를 봅니다: A·B 가 같은 방향(둘 다 비겨냥 ≤2 또는
  둘 다 >2)이면 결론이 설정에 안 흔들리는 것이고, 갈리면 "용량 판정 불가 — 설정 민감" 으로 기록하고
  교체 착수 금지

### 2-3. 데이터 — 세 단계, 누적이 아니라 분리
| 런 | 데이터 | 묻는 것 |
|---|---|---|
| P0 | r5 자료(727) 그대로 | 같은 자료에서 110M 이 r5 와 **같거나 나은가** (기준선) |
| P1 | P0 + r8 90쌍(180) | 14M 을 포화시킨 자료를 110M 은 **비겨냥 탈락 없이** 담는가 — FF-2 의 핵심 |
| P2 | P0 + r6 하드마진(264) | 14M 을 회피시킨 자료를 110M 은 **뭉개지 않고** 가르는가 |

P1·P2 를 합치지 않는 이유: r6 자료는 자료 결함으로 기각된 것이라(27차), 섞으면 P1 의 깨끗한 신호를
더럽힙니다. P2 는 "110M 이라도 이 자료는 못 쓴다"를 확인하는 **음성 대조**입니다.

### 2-4. 재는 것 — 전부 기존 도구, 새 잣대 없음
1. 게이트 6종 (`eval:student` t 스윕 · 핑 · DART 정제판 · 회귀 · 거절 오탐 · risk_heavy)
2. 시소 `seesaw:compare` (기준 = r5 스냅샷 a0eaa12a) — **비겨냥 새 탈락 ≤2**
3. `probe:adverb` (부사 제거 하락 ≤0.2·역전 0) · `probe:dilution` (잔존 ≥0.3)
4. `probe:zeroshot-r8` — P0 에서만 유효(P1 은 그 자료를 학습하므로 오염). UNSUPPORTED t0.5 24%↑ · 정상 오탐 ≤2
5. `probe:score-median` — **PRIVATE_INFO 중앙값 0.472 → ?** (뭉갬 해소 여부, GG-4 기준선)
6. **지연 실측** — 운영 길이(≈700tk, 창 ~11) 문서당 ms, fp32 와 int8 둘 다. `probe:window-cap` 의
   1,500/3,000tk 도 함께(선형성 확인)

### 2-5. 판정 규칙 (사전 등록)
- **용량 확정**: P1 에서 런 A·B 모두 비겨냥 ≤2 + 게이트 6종 통과 + 부사·희석 통과
- **자료 문제 확정**: P1 도 비겨냥 >2 → 합성 훈련 종료 확정, 운영 50건 대기 (FF-2 둘째 갈래)
- **설정 민감**: A·B 가 갈림 → 판정 보류, 런 C 로 재현 후 다수결이 아니라 **원인 규명**
- 교체 착수는 용량 확정 **그리고** 지연 ≤1,500ms(int8 허용, 단 int8 은 카나리아 tol 완화분 안에서) **그리고**
  출시 후 r5 라이브 2주 관찰 뒤 (FF-3 #4)
- 지연 초과면 30차 가지 (b) — 그 전에 창 수·배치 추론으로 먼저 시도

## 3. 검토 질문

#### HH-1. "같은 설정" 해석 — 런 A·B 이중 실행이 맞습니까
대안 하나만 고르라면 무엇을? gap 17: A·B 가 일치해도 "설정에 둔감"과 "둘 다 같은 방향으로 틀림"이 같습니다.

#### HH-2. P1·P2 분리 — P2(하드마진 음성 대조)를 돌릴 가치가 있습니까
27차가 자료 결함으로 폐기한 자료입니다. 110M 이 그걸 가르면 "14M 의 회피였다"가, 못 가르면 "자료가
원래 안 된다"가 확정됩니다. 비용은 런 하나. 폐기한 자료를 다시 쓰는 것이 규칙 위반입니까?

#### HH-3. NLI 머리(CARD_MISMATCH) — 같은 부검에 넣습니까, 따로 엽니까
CARD_MISMATCH 는 학생 과목에서 영구 제외돼 있고 coherence 코퍼스 34건뿐입니다(학습 금지). NLI 학습 자료가
**0건**이라 합성부터 시작해야 합니다 — 그건 별도 사건(실측 계획)으로 여는 것이 맞습니까?

#### HH-4. int8 허용 범위
14M 은 fp32 로 충분했습니다. 110M 은 int8 이 지연을 2~3배 줄이지만 카나리아 tol(fp32 1e-6 vs int8 완화)
을 건드립니다. int8 로 게이트를 통과한 모델과 fp32 로 통과한 모델은 **다른 모델**로 취급해 각각
승격 지문을 갖게 하는 것이 맞습니까?

#### HH-5. 운영 50건이 먼저 오면
부검 전에 운영 데이터 50건이 쌓이면 P1 의 검증셋이 하나 더 생깁니다. 그때는 부검을 **미루고** 50건을
포함해 돌립니까, 아니면 예정대로 돌리고 50건은 사후 검증으로만 씁니까? (사전 등록의 뜻은 나중에 온
자료로 절차를 바꾸지 않는 것이라 저는 후자입니다.)
