## MM-1 로컬 소형 LLM 2단 검수 — 승인 (즉시 후보 반입·하네스 실측 착수)

- 검토자 추가 gap 17: 1~4B 체급의 실위험 = **형식 복종력 부족**(JSON 파괴·대화형
  추임새). 대응 = **GBNF 문법 강제 필수** — 프롬프트만으로 형식 보장 시도 금지
- 반증 조건 확정판 (하나라도 → 즉시 폐기):
  ① 처리량 미달 (최적화 후에도 큐 무한 적체)
  ② 형식 붕괴 (**문법 강제 적용 후에도** 파싱 가능 JSON 반환율 < 95%)
  ③ 오탐 폭발 (부정형 오탐 > P1-A, 또는 환각 소견으로 운영자 피로 급증)
- 이행: README "로컬 소형 LLM 2단 검수 — 사전 등록" 절 신설(단일 출처),
  후보 반입 목록 `training/llm2/candidates.md` 작성 → 사장님 전달.
  하네스·GBNF 는 가중치+실행기 반입 후 작성(실측은 그때)

## MM-2 LLM 라벨 축적 — 승인 ("완벽한 인적 방어막")

- 검토자 추가 gap 17: **자동화 편향** — 유창한 환각 소견에 운영자가 설득당해
  무비판 승인 (LLM 의 이유가 유창할수록 검증을 건너뛰는 경향)
- 반증 조건 신설: **운영자의 LLM 소견 기각률 > 50% → MM-1 전체 롤백**
  (그 시점의 LLM 은 보조자가 아니라 스팸 생성기)
- 이행: README 등록. 기각률 계측은 LLM 편입 시점에 운영 지표로 추가 (편입 전에는
  잴 대상이 없음)

## MM-3 정확도 공식 잣대 — 승인 (벤치마크 → 비즈니스 지표 전환)

- 검토자 추가 gap 17: 세 지표는 **시소 관계** — 보류 오탐률을 깎으려 모델을
  보수화하면 게시 후 미탐 발견율이 치솟는다. 창업자 보고 시 이 관계를 항상 병기
- 반증 조건 신설: **운영자 1인당 건별 검수 체류 시간 폭증** 관측 시 → "④ 소견의
  가독성"을 4번째 잣대로 추가 (잣대 정의 자체의 불완전 신호)
- 이행: README 등록. 참고 — 체류 시간 원자료는 관리자 앱의 decisionElapsedMs
  (회신 6호 계약)가 이미 쌓는다: 4번째 잣대가 필요해지는 순간 재료는 있다
