# 21차 검토 요청 — 접힌 구조가 만든 새 경계선들을 공격해 주십시오

## 0. 지난 회차 이후 일어난 일 (2026-08-21, 하루 안에 전부)

20차 답변을 전부 구현했습니다 (X-1 사전의 6층 합류 · X-2 승격 금지 · X-4 홀드아웃
101건 분리 · X-5 수동 졸업 + 영구 회귀 시험셋 · X-6 그림자 비노출 명문화).
같은 날 관리자 앱 쪽 AI가 계약 질문 13개(Q0~Q12)를 보내와 회신했고, 그중 Q0이
**새 정책 하나**를 만들었습니다:

> **라이브 검사기가 죽으면 게시를 보류한다.** (창업자 확정)
> 예전 정책은 "학생이 죽어도 게시 흐름은 그대로"였는데, 그 아래에서 라이브 장애가
> **소견 0건 게시**로 새고 있었습니다.

그리고 이 정책이 **구현 당일 스스로를 증명했습니다** — 넣자마자 DB 시험 130건이
한꺼번에 빨개졌는데, 원인이 정책이 아니라 시험 환경이었습니다. 시험 프로세스가
개발용 환경 변수를 물려받아 **몇 달째 "라이브 모드 + 사이드카 없음"이라는 장애
구성으로 돌고 있었고**, 옛 정책이 그것을 조용히 통과시켜 아무도 몰랐습니다.
시험 1,500여 건의 초록불이 "검수 경로가 건강하다"의 증거가 아니었던 것입니다.
(처방: 시험은 명시적 `STUDENT_MODE=off`로 돈다 — 정책을 되돌리지 않았습니다.)

**고정 제약 (변함없음)**: λ=4 (오탐 1 = 미탐 4) · 즉시 거절(REJECT)은 코드 원천
패턴만 · **운영 경로 외부 AI API 0회** · 학생 KoELECTRA-small 14M · 운영자 1~2인 ·
회귀 시험셋·홀드아웃은 어떤 경로로도 학습에 쓰지 않는다

현재 구조 (검토 대상):

```
검사기 ① 규칙 엔진 — 입력 2원천(코드 패턴 · 운영자 사전)이 같은 6층을 지난다
   사전 항목: 1~3층은 전부, 5층은 등록 시 충돌 검사 통과분만(상한 200), 항상 WARN
검사기 ② 학생 모델 — 뜻 판단, WARN까지, 그림자→라이브
장애 정책: 라이브 학생이 죽으면 UNAVAILABLE/HOLD (규칙 BLOCK은 장애와 무관하게 거절)
졸업: 수동, 위반 3+정상 3 대비쌍 → 영구 회귀 시험셋, 항목 비활성 (원자적)
```

## 1. 검토 질문 — 구현이 그은 경계선 다섯

#### Y-1. 장애 정책의 두 우선순위 — 어느 쪽도 자명하지 않습니다

구현한 규칙 둘:

- **(a) 규칙 BLOCK은 장애보다 우선한다** — 학생이 죽어 있어도 코드 패턴이 잡은
  BLOCK은 즉시 거절로 나간다. 근거: 규칙 엔진은 학생과 독립이라 장애의 영향권
  밖이고, 거절을 보류로 낮추면 장애 시간 동안 명백한 위반이 운영자 큐에 쌓인다.
  **반론 여지**: 즉시 거절은 사람 확인 없는 유일한 처분인데, "시스템 일부가 죽은
  상태"는 정확히 시스템을 가장 못 믿을 순간 아닙니까? (보상 설계에서 SYSTEM_ERROR
  자동 지급을 거부했던 것과 같은 논리가 여기도 적용됩니까?)
- **(b) 보류 해제 밸브는 수동 `STUDENT_MODE=shadow` 전환뿐** — 장애가 길어지면
  운영자가 밸브를 내려 "학생 없이 규칙+사람"으로 게시를 다시 흐르게 한다.
  **반론 여지**: 밸브를 내린 상태는 검수가 약해진 채 게시가 흐르는 상태인데,
  되돌릴 조건(사이드카 복구 확인? 시간 상한?)이 없습니다. 밸브가 내려진 채
  잊히면 새 정책이 없던 시절과 같아집니다. 내린 상태를 시끄럽게 만드는 장치가
  필요합니까 — 예: shadow 모드로 게시될 때마다 소견에 표식, 또는 매일 재알림?

#### Y-2. 5층 상한 200의 밀어내기가 조용합니다

상한을 넘으면 **최신순으로 자릅니다** — 201번째 등록이 일어나는 순간 가장 오래된
항목이 5층(음성 변형) 자격을 **조용히** 잃습니다. 등록한 운영자는 그 사실을 모르고,
잃는 쪽 항목도 화면상 아무 변화가 없습니다.

- 최신순의 근거는 "오래된 항목은 졸업으로 나가는 것이 정상 경로"인데, 졸업은
  수동이라 안 하면 안 나갑니다. **정확도(confirmedCount/matchCount) 순**이 낫습니까?
  그러면 새로 등록한 항목이 실적 0이라 바로 밀리는 반대 문제가 생깁니다.
- 상한 도달을 운영자에게 알려야 합니까? 200개는 운영자 1~2인이 몇 년을 등록해야
  닿는 수라 "지금 문제"는 아니지만, 닿는 날 아무 소리 없이 보호가 빠지는 설계입니다.
- **재는 값 주의**: "어느 항목이 밀려야 하는가"를 무엇으로 재든, 그 값이 위반을
  잘 잡는 항목과 오탐만 내는 항목에서 같은 값이 나올 수 있는지 밝혀 주십시오.

#### Y-3. 졸업 대비쌍 6문장을 운영자가 손으로 씁니다 — 그리고 영구입니다

`graduatePhrase`는 위반 3 + 정상 3 문장(각 10자 이상, 위반엔 학생 라벨 필수)을
받아 **영구 회귀 시험셋**에 넣고 항목을 끕니다. 회귀 오답이 나면 재학습 채택이
막히는 구조라, 이 6문장의 품질이 곧 릴리스 게이트의 품질입니다.

- **잘못 쓴 문장도 영구입니다.** 수정·삭제 경로를 일부러 안 만들었습니다 —
  회귀셋을 편집할 수 있으면 "학생이 틀리는 문항을 지우는" 유혹이 릴리스 압박과
  함께 옵니다. 맞습니까? 아니면 2인 확인 같은 무거운 절차를 단 삭제가 필요합니까?
- 운영자가 쓰는 문장이 **서로 닮으면**(같은 틀에 낱말만 바꿔 3문장) 회귀셋이
  명목 6문장, 실질 2문장이 됩니다. 문장 다양성을 검사할 방법이 있습니까 —
  자모 거리? 그건 뜻이 아니라 표기의 거리라 또 다른 gap 17이 됩니까?
- 졸업 직후가 가장 위험한 순간입니다(사전 보호가 꺼지고 학생만 남음). 졸업한
  표현이 실운영에서 뚫린 것을 알아채는 경로가 **미탐 신고뿐**인데, 그 신고는
  운영자 자신이 흘려보낸 건이라 자기 오류를 자기가 발견해야 합니다. 졸업 후
  N일간 그 표현의 그림자 기록만 따로 표시하는 관찰 창이 필요합니까?

#### Y-4. 충돌 검사가 채점지의 정상 문항을 씁니다 — 17차 금기 판정을 받겠습니다

등록 시점 5층 자격 검사(`measurePhoneticEligibility`)의 대조 표본:
종목 마스터 16,553 + 금융 용어 사전 + 근사 위험 낱말 목록 + **손코퍼스 86 중
정상 문항 34문장**. 마지막 것이 문제입니다 — 17차에 "코퍼스를 보고 규칙을 만들면
학습셋이 된다(채점지 소각)"고 못 박았는데, 이 사용이 그 금기에 걸립니까?

우리 판단은 **안 걸린다**입니다: 채점지 오염은 "채점지를 보고 규칙을 고쳐 점수를
올리는" 방향인데, 이 사용은 반대 방향입니다 — 정상 문항과 충돌하는 항목의 5층을
**꺼서** 오탐을 막는 것이고, 탐지율 측정에는 영향이 없으며 오탐률 측정에는
**우리에게 불리한 쪽으로만**(정상 문항이 안 걸리게) 작용합니다.

- 이 논리에 구멍이 있습니까? 예컨대: 정상 문항 34개와 충돌 안 나게만 사전을
  꾸리면 오탐률 지표가 실제보다 좋아 보이는 착시 — 채점지의 정상 문항이 실운영
  정상 문장의 대표가 아니게 되는 순간 그 34문장에 과적합한 것 아닙니까?
- 대안: DART 3,000문장(확보 시)으로 교체하고 손코퍼스는 손대지 않는다 — 이게
  맞다면 지금은 임시로 두고 DART 확보 시 교체입니까, 지금 당장 빼야 합니까?

#### Y-5. 미배선 둘의 설계안 — 만들기 전에 결함을 찾아 주십시오

**(a) 하드 네거티브 카운터** (X-4 재학습 트리거 50건의 계기판):

```
대상 = 그림자 기록(ShadowComplianceReview)과 운영자 최종 판정이 엇갈린 건
  학생 WARN + 운영자 승인(오탐 방향) / 학생 침묵 + 운영자 반려(미탐 방향)
집계 = 마지막 재학습 채택 시점 이후의 건수 (리셋은 채택이 만든다)
```

- 우려: 운영자 판정 자체가 라벨인데, 그림자와 대조하는 순간 학생의 관점이
  "엇갈린 건"이라는 딱지로 운영자 화면 근처에 온다 — X-6 비노출 원칙과의 거리는?
  (카운터 숫자만 보이고 개별 건은 안 보이면 독립성이 지켜집니까?)
- "엇갈림"의 정의: 학생은 유형까지 내는데 운영자 반려 유형과 **다른 유형**으로
  잡은 건은 정탐입니까 엇갈림입니까?

**(b) 회귀 게이트**: `eval:student` 채택 판단에 "회귀 시험셋 전 건 통과"를 AND로.

- 회귀셋이 커지면(졸업 누적) 한 건 오답이 릴리스 전체를 막는데, 그 오답이 Y-3의
  "잘못 쓴 문장" 탓이면 풀 방법이 없습니다. 전 건 통과가 맞습니까, 허용 오답률이
  필요합니까? (허용치를 두는 순간 "어느 건을 허용하나"가 편집 유혹과 같은 문이
  됩니까?)

#### Y-6. 20차 "먼저 재야 할 것" ①의 실행 설계 — 사전-정상 간섭 거리

아직 못 쟀습니다. 계획: 등록될 법한 표현 후보(반려 사유에서 뽑은 위반 표현들)를
사전에 넣고 정상 문항 34 + 대조군 54를 통과시켜 **표현당 오탐 기여**를 잰다.

- 표현 후보를 어디서 뽑아야 측정이 정직합니까? 손코퍼스 위반 문항에서 뽑으면
  채점지로 사전을 만드는 셈이고(17차 금기 정면), 지어내면 실제 등록 분포와
  다릅니다. 합성 코퍼스의 위반 문장에서 뽑는 것이 맞습니까?
- 이 측정도 gap 17형 함정 검사를 통과해야 합니다: "표현당 오탐 기여"가 위험한
  표현과 안전한 표현에서 같은 값이 나오는 조건이 있습니까?

## 2. 답변 형식

1. **결론** — 한 문장
2. **각 항목 판정** — `그대로` / `고쳐서` / `버려라`. 뒤 둘이면 대안까지
3. **근거** — λ=4 · "즉시 거절은 코드 원천만" · **운영 경로 외부 API 0회** 아래에서
4. **먼저 재야 할 것** — 지금 있는 것으로 잴 수 있는지 반드시. 가진 전부:
   손코퍼스 86 · 대조군 54 · 신조어 127 · 합성 390(학습)+101(홀드아웃) ·
   종목 마스터 16,553 · **실제 리포트 0 · 운영 데이터 0 · 교사 답 0 · DART 미확보 ·
   사이드카 미기동**
5. **반증 조건** — 가정과 그것을 붙잡을 시험을 함께. 그리고 항목마다
   **재는 값이 위반과 정상에서 같은 값을 낼 수 있는지**(gap 17형 함정)를 밝혀 주십시오

### 반증 이력 — 이번 답변도 같은 운명일 수 있습니다

| 회차 | 반증된 가정 | 어떻게 |
|---|---|---|
| 13차 P-6 | "정규화 거리가 보편 회피 신호" | 띄어쓰기를 재고 있었다 |
| 15차 | "대조군 8건으로 오탐 0%" | 두 번 뚫렸다 |
| 16차 T-4 | "마스킹 30% 상한" | 정상 문장이 이미 63~79% |
| 17차 | "띄어 쓴 신조어 무사 = 안전" | 붙여 쓰면 12/25 오탐 |
| 18차 | "수동 2차 = 자동 2차의 느린 판본" | 여섯이 조용히 빠짐 |
| 19차 | "STRONG 확장은 오탐만 줄인다" | 주입 공격이 통과 |
| 20차 | 19차 W-4 "창 = 최대값+1" | gap 17에 위반·정상이 같은 좌표 |
| **21차 (이번)** | **"시험 1,500건 초록 = 검수 경로 건강"** | **Q0 정책 첫 실행이 시험 환경의 몇 달 묵은 장애 구성을 드러냄 — 옛 정책이 그 장애를 조용히 통과시키고 있었다** |

특히 이번 반증의 교훈: **아무 일도 안 일어나는 것이 정상인 정책은 자기 고장을
보고할 수 없습니다.** Y-1(b)의 밸브, Y-2의 밀어내기, Y-3의 졸업 직후가 전부
같은 모양 — "조용히 약해지는 상태"를 품고 있습니다. 답변에서 각 항목이 이 모양을
갖는지 점검해 주십시오.
