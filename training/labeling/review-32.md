# 32차 검토 요청 (사건 구동 — 110M 부검 결과 도착) — 판정은 "설정 민감", 그런데 규명 내용이 답을 반쯤 줬습니다

## 0. 무엇을 돌렸나 — 사전 등록(31차) 그대로

가중치 도착(koelectra-base-v3, 112.3M, 토크나이저 지문 14M base 와 동일 → 변수는 용량 하나).
P0(r5 자료 727) / P1(+r8 180) / P2(+r6 264) × 런 A(r5 설정) / 런 B(관례: 5에폭·lr 2e-5·warmup 10%·wd 0.01),
그리고 A·B 가 갈려 **런 C(관례 밖 lr 1e-4)** 까지 — 전부 등록된 절차이고 결과를 보고 바꾼 것은 없습니다.
게이트는 전 런을 후보 사이드카(CPU, 운영과 동일)에 올려 측정. 이름 `IRIS.v6-<P>-<R>`, 대장 기록 완료.

### 부수 실측 셋
- **110M fp32→int8 동적 양자화는 3런 연속 자동 폐기** (검증 오차 1.21~3.80 ≥ 0.5). 14M 에서 되던
  것이 110M 에서 판정을 뒤집는 수준으로 깨집니다 → **110M 은 fp32 서빙 전제**
- GPU(RTX 2060 6GB) 학습 환경 가동 — batch 16×512 는 VRAM 초과(6.35GB)라 `--batch 8 --accum 2` 로
  유효 16 유지. 에폭 5분(CPU) → ~1분. 추가 런의 비용이 확 내려갔습니다
- 통짜 희석 잔존율은 14M 보다 **나쁩니다**(13%→7~8%) — 큰 모델이 어텐션을 더 앞쪽에 쓰는 모양.
  창 결합 회복(1/4→2~3/4)이 그걸 덮고 있어 운영 방어는 오히려 나아졌지만, 기록해 둡니다

## 2. 사전 등록 판정 — **설정 민감** (용량 확정 아님)

등록된 조건: "용량 확정 = P1 에서 **A·B 모두** 비겨냥 ≤2 + 게이트 + 부사·희석". B 가 게이트에서
탈락했으므로 문언상 미충족 → **설정 민감**, 교체 착수 불가. 런 C 규명의 내용은:

> 110M 은 r5 설정에서 P1 자료(14M 을 포화시킨 그 자료)를 **비겨냥 탈락 없이, 핑까지 통과하며**
> 담았다. 갈림의 원인은 용량이 아니라 설정이다 — 설정 축의 양 끝(미수렴/과민)이 각자의 방식으로
> 실패했고, 가운데(r5 설정)만 정상이다.

즉 "용량이 문제였다"는 30차까지의 가설은 **A런 셋이 일관되게 지지**하지만, 등록된 확정 조건에는
못 미칩니다. 여기서부터가 질문입니다.

## 3. 검토 질문 — 각각 그대로 / 고쳐서(대안) / 폐기(이유), gap 17 함정, 반증 조건

#### II-1. "설정 민감" 판정을 받아들이되, **런 D(B 설정 + 에폭 12·GPU)** 로 확정을 시도하는 것이 맞습니까
B 의 실패가 "관례 설정 자체가 틀림"이 아니라 "5에폭이 모자람"일 수 있습니다. GPU 로 런당 ~10분이라
비용이 사라졌습니다. D 가 A 와 같은 방향이면 등록 조건(A·B' 일치)을 **사후 변형 없이** 채우는 셈인지,
아니면 "B 를 바꿔서 다시"는 이미 Y-4형인지 — 여기가 이번 회차의 핵심 질문입니다.

#### II-2. DART 게이트가 **영구 제외 라벨(CARD_MISMATCH)을 세는** 문제
P1-A 의 DART 실패 6건이 전부 라이브에서 소견으로 나갈 수 없는 라벨입니다. 게이트를 "켜진 라벨
기준"으로 좁히면 P1-A 는 통과입니다. 그러나 게이트 정의를 결과 본 뒤 바꾸는 것이라 저희가 임의로
못 바꿉니다 — 판정해 주십시오. (r5 의 7건도 CM 3건 포함이라 같은 논점이 소급됩니다)

#### II-3. 핑 선정선 0.85 미달 (P0-A·P2-A)
핑 문장은 r5 로 고른 것이라(30차 부록 — r5 자신도 0.839/0.834) 모델이 바뀌면 문장 재선정이
필요합니다. "채택 시마다 재실측"이 원래 규정입니다. P1-A 는 현행 문장으로도 통과했으니 문장을
바꿀 이유가 없고, P0-A·P2-A 의 미달은 **기각 사유가 아니라 문장 자격의 문제**로 읽는 것이 맞습니까?

#### II-4. 지연 — 예산 1,500ms 에 걸쳐 있습니다
운영 길이 fp32 1,283~1,545ms (측정 간 변동 ±20%, CPU 부하 민감). int8 은 불가(자동 폐기 3연속).
선택지: (a) 창 수·배치 추론 최적화로 여유 확보 (b) model-swap-rule 의 증류 가지 (c) 예산 완화.
(c)는 UX 근거(제출 후 대기)라 저희는 (a) 먼저가 맞다고 봅니다 — 판정 부탁드립니다.

#### II-5. 다음 채택 후보를 무엇으로 봅니까
A런 셋 중 게이트 성적·시소·핑을 모두 보면 **P1-A** 가 후보입니다 (P2-A 는 용량 경보 + 겨냥 1 탈락 —
하드마진 자료는 110M 도 온전히 못 담는다는 27차 결론 재확인 = 음성 대조 성공). 다만 어떤 경우에도
교체는 **출시 후 r5 라이브 2주 뒤**(FF-3 #4)이고, 오늘 결정하는 것은 후보 지정까지입니다.

## 4. 먼저 재야 할 것 (보유 자료)
1. 런 D (II-1 승인 시): P1 × B설정 × 에폭 12 × GPU — 게이트 전수
2. P1-A 지연 최적화 실측 (II-4 (a)): 창 배치 추론(사이드카에 batch 지원) 전후 비교
3. P1-A 로 zero-shot r8 은 **못 잽니다**(그 자료를 학습) — 대신 격리 r6 264 를 P0-A/P1-A 에 zero-shot
   으로 돌려 하드마진 일반화를 볼 수 있습니다 (학습 안 한 자료라 깨끗함)

나머지는 그 답에 걸려 있습니다.
