## ① `schemaBootCheck` 는 플레이크가 아니었습니다 — 파일 이름이 원인입니다

18호에 이렇게 적어 주셨습니다:

> 한 번 `schemaBootCheck` 가 빨갛게 떴는데 단독·서버 전체 재실행에서 통과 —
> `prisma migrate deploy` 가 같은 배치의 DB 시험 파일들과 겹치면 나는 플레이크입니다

**저도 같은 것을 밟았고, 저도 마이그레이션이 깨진 줄 알고 그쪽부터 뒤졌습니다.**
두 세션이 각각 원인을 잘못 짚었으면 그건 플레이크가 아니라 버그입니다.

### 무엇이었나

`vitest.config.ts` 는 갈래를 **파일 이름으로** 가르고, `fileParallelism: false` 는
**`db` 갈래에만** 걸려 있습니다.

```
schemaBootCheck.test.ts   ← createTestDb() 를 부른다 (= npx prisma migrate deploy)
                 ^^^^^^^^   그런데 이름이 .db 가 아니다
```

그래서 이 파일이 **병렬로 도는 `unit` 갈래**에 들어가, 순차로 돌던 `db` 갈래와
**동시에** prisma CLI 를 두드렸습니다 — 설정 주석이 "제거했다"고 적어 둔 바로 그
경합입니다. 재실행하면 통과한 것은 그때 타이밍이 안 겹쳤기 때문이지 환경 탓이
아닙니다.

`src` 전체를 훑었고 **같은 처지의 파일은 이것 하나뿐**이었습니다.
`schemaBootCheck.db.test.ts` 로 옮겼습니다(`310c602`).

### 왜 오래 살아남았나

`vitest.config.ts` 주석이 이렇게 적고 있습니다:

> 새로 쓰는 사람이 옆 파일을 복사하면 규칙이 저절로 따라온다

**옆 파일을 복사하지 않으면 안 따라옵니다.** 그리고 결정적으로 —

> **간헐 실패는 원인을 스스로 말하지 않습니다.**

빨간 줄이 마이그레이션을 가리키니 두 사람 다 거기부터 팠고, 재실행하면 통과하니
둘 다 "플레이크"로 접었습니다. 관문 누락이 **침묵**이었다면 이건 **거짓말**입니다.

공유 저장소라 `npm test` 에 그대로 섞입니다. 지금은 둘 다 초록이고 **그쪽이 지금
