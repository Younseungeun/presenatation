## 1. 검수 모델이 하는 일 — 한 장 요약

리서처가 리포트에 "게시"를 누르면 자동 검수가 돕니다.

```
게시 클릭
   ↓
┌─────────────────────────────────────────────┐
│ 1차  결정적 규칙 (코드 · 정규식 · 거리 계산)      │  ← 여기만 즉시 거절 가능
└─────────────────────────────────────────────┘
   ↓
규칙이 BLOCK ?  ──예──→  REJECT (즉시 거절)
   ↓ 아니오
소견이 하나라도 / 반려 3회 / 위험 종목 ? ──예──→  HOLD → **관리자 큐**
   ↓ 아니오                                          ↓
        PUBLISH                              문서를 뽑아 교사에게 넘긴다
                                                     ↓
                                              받은 답을 그대로 기록
                                                     ↓
                                              승인 → 게시 / 반려 → 초안 복귀
                                                     ↓
                                              그 판정이 **학습 라벨**
```

### ⚠ 이 설계에서 절대 바뀌면 안 되는 것

| 원칙 | 이유 |
|---|---|
| **즉시 거절 권한은 결정적 규칙에만** | 모델은 재현 불가능한 판정을 낸다. 같은 글을 다시 넣으면 다른 답이 나올 수 있는 것에 사람의 생계를 끊는 권한을 주지 않는다 |
| **모델이 BLOCK을 내도 REJECT가 아니라 HOLD** | 같은 "BLOCK"이라도 **누가 냈는가**에 따라 처리가 갈린다 |
| **보류는 안전하다** | 판매가 시작되지 않아 규제 노출이 0이고(유통 안 함), 거절과 달리 운영자 승인으로 되살아난다 |
| **오탐 > 미탐, 4배** | 성실한 리서처를 막는 것이 위반을 놓치는 것보다 4배 비싸다(λ=4). 화면 설계도 이 비대칭을 따라야 한다 |

코드: `src/domain/compliance.ts` (`decide` / `resolveAction`), `src/server/complianceService.ts`

## 2. 1차 규칙 안이 다시 여섯 층입니다

관리자가 "이게 왜 걸렸지"를 이해하려면 층을 알아야 합니다.

| 층 | 무엇을 보나 | 예 | 낼 수 있는 판정 |
|---|---|---|---|
| ① 원문 | 정규식 그대로 | `원금을 보장합니다` | **BLOCK** |
| ② 기호 제거 사본 | 글자를 벌린 것 | `원.금.보.장` | WARN |
| ③ 깊은 정규화 | 유니코드·낱자 | `ⓘⓓ` · `ㅇ ㅝ ㄴ ㄱ ㅡ ㅁ` | WARN |
| ④ 연락처 모양 | 전화번호 자릿수 묶음 | `010-8923-7890` · `Ｏ１Ｏ` | WARN (유도 어휘가 곁에 있으면 **BLOCK**) |
| ⑤ 음성 변형 | 금지어와 자모 거리 1 | `텔레그렘` · `원금보쟝` | WARN |
| ⑥ 훼손 사실 | 뜻은 몰라도 "바꿨다" | `텔le그ram` | WARN |

**②③⑤⑥은 전부 WARN입니다.** ④는 번호만 있으면 WARN, 곁에 `카톡`·`문의 주`·`입금` 같은 유도 어휘가 있으면 BLOCK입니다 — 공시 인용(`IR 담당자: 02-…`)을 죽이지 않기 위함입니다. 근사·추정이라 사람 확인 없이 죽이지 않습니다.

⑥번이 특이합니다 — **무엇을 감췄는지 해독하지 않고 감췄다는 사실만** 지적합니다. 그래서 리서처에게 가는 안내가 "외부 채널 유도"가 아니라 **"정상 표기로 고치세요"**입니다. 고친 글이 다시 전체 규칙을 만나 거기서 진짜 유형이 나오는 구조입니다(측정: 77%가 이 경로로 진짜 위반에 걸림).

코드: `src/domain/evasionNormalize.ts` · `phoneticEvasion.ts` · `contactNumber.ts`

## 4. 이 모델은 **운영자의 결정으로** 학습합니다

여기가 핵심입니다. **운영자가 승인·반려를 누르는 것이 곧 정답 라벨을 붙이는 일입니다.**

| 운영자 행동 | 라벨 | 뜻 |
|---|---|---|
| 보류 → **승인** (기본) | 오탐 | 막지 말았어야 했다 |
| 보류 → 승인 + "지적은 타당" 체크 | 경미 | 심각도를 낮춰야 한다 (규칙 삭제가 아님) |
| 보류 → **반려** | 정탐 | 맞게 잡았다 |
| 통과 → **강제 철회** | **미탐** | 놓쳤다 |

DB 칸: `ComplianceReview.operatorVerdict / operatorReason / operatorCategories / aiFindingsValid`

### 화면 설계가 여기에 직접 영향을 줍니다

- **승인의 기본값은 "오탐"입니다.** 승인의 대다수가 과잉 지적이라, 예외(경미)만 체크하게 해야 운영자 손이 덜 가면서 라벨이 비지 않습니다. **체크박스를 기본 켜짐으로 두면 라벨이 통째로 오염됩니다.**
- **반려할 때 실제 위반 유형을 고르게 하십시오.** 안 고르면 "검수 소견 그대로 인정"이 됩니다. 고르면 "반려는 맞았지만 엉뚱한 유형을 짚은" 소견도 오탐으로 잡힙니다.
- **미탐은 대기 큐에 없습니다.** 이미 게시된 글이라 큐에 안 올라옵니다. 대기 건이 없으면 **가장 최근 검수 기록**에 라벨을 붙이는 별도 경로가 필요합니다(`operatorVerdictWrites`). **이 경로가 없으면 미탐률은 영원히 0으로 보입니다.**

## 5. 출시 초기에 필요한 것 — 되먹임 고리를 닫는 화면

사장님이 말한 상황(출시 초기엔 모델이 불완전하니 이용자가 잡은 우회와 오탐으로 추가 학습)이 정확히 이 고리입니다. **지금 끊겨 있는 곳**을 표시했습니다.

```
   [이용자 신고]                    [보류 큐]
        │                              │
        ↓                              ↓
   신고 처리 화면                  승인 / 반려
        │                              │
        ↓ (✂ 끊김)                     ↓
   강제 철회 = 미탐 라벨          오탐 / 정탐 라벨
        │                              │
        └──────────┬───────────────────┘
                   ↓
        ComplianceReview.operatorVerdict   ← 여기까지는 이미 쌓인다
                   ↓ npm run train:operator  ← **2026-08-21 이음**
           학습 자료 (JSONL)
                   ↓
              재학습 → 배포
```

### 만들어야 할 화면 넷

#### ① 신고 → 미탐 연결 (`/admin/abuse-reports` 보강)

이용자 신고를 처리할 때 **"이 리포트는 검수를 통과했는가"**를 함께 보여주고, 철회를 누르면 그 리포트의 `ComplianceReview`에 `TAKEDOWN`(=미탐) 라벨이 자동으로 붙게 하십시오.

지금은 신고 처리와 강제 철회가 다른 화면이라, 신고로 내린 리포트가 **미탐으로 세어지지 않을 수 있습니다.** 그러면 "이용자가 잡은 우회"가 학습 자료로 안 남습니다 — 사장님이 걱정한 바로 그 자리입니다.

화면에 함께 띄울 것: 그 리포트가 받은 **검수 소견 전문**(무엇을 잡았고 무엇을 놓쳤는지), 검수 층(§2), 검수 시각.

#### ② 학습 자료 큐 (`/admin/training` — 신설)

운영자 판정이 쌓이면 그것을 **학습 자료 후보**로 보여주는 화면입니다.

| 필요한 것 | 이유 |
|---|---|
| 판정 유형별 목록 (오탐 / 정탐 / 미탐 / 경미) | 처방이 다르다 — 오탐은 규칙을 좁히거나 하드 네거티브로, 미탐은 새 규칙 또는 학습 |
| **소견 출처 표시** (`rule` / `ai` / `learned` / `semantic` / `student`) | **오탐을 고치는 방법이 출처마다 다르다.** 규칙 오탐은 정규식을 고치고, 학생 오탐은 코퍼스에 하드 네거티브로 넣고 재학습해야 한다 |
| 원문 + 예측 카드 | **카드가 없으면 학습이 틀어진다** — 운영 입력에는 언제나 카드가 있다 |
| "학습 자료로 채택" 버튼 | 사람이 한 번 더 본다. 자동으로 넣으면 잘못된 판정이 그대로 학습된다 |
| 채택 취소 | 되돌릴 수 없는 학습 통로는 통로가 아니다 |

#### ③ 학습 자료 내보내기 — **서버 쪽은 완성되어 있습니다**

버튼만 붙이면 됩니다. 호출할 함수:

```ts
import { exportOperatorLabels } from '@/server/operatorLabelExport';

const { examples, counts, leaked, skipped } = await exportOperatorLabels(prisma, {
  includeConfirmed: false,  // 정탐도 넣을지 (기본 끔 — 규칙이 이미 잡은 것이라 학생이 규칙의 그림자가 된다)
  includeClean: false,      // 정상 통과 건도 넣을지 (기본 끔 — 양이 많다)
  since: new Date(...),     // 기간 제한 (선택)
});
```

CLI 로도 됩니다: `npm run train:operator [-- --confirmed --clean --days 30 --dry-run]`

**판정을 라벨로 옮기는 규칙** (`src/domain/operatorTraining.ts` — 순수 함수라 시험이 붙어 있습니다):

| 판정 | 학습 라벨 | 왜 |
|---|---|---|
| 오탐 | **라벨 없음** | "이건 정상이다" — 가장 값진 자료 |
| 미탐 | 운영자가 지목한 유형 | "이걸 놓쳤다" |
| 미탐인데 유형 미지목 | **자료로 안 씀** | 다중 라벨 BCE 라 빈 라벨은 "아니다"를 가르친다 — 위반을 정상으로 학습시키게 된다 |
| 경미 | **자료로 안 씀** | 라벨이 아니라 **심각도**의 문제다 |
| 정탐 | 확인된 유형 (기본 꺼짐) | 규칙이 이미 잡은 것이라 새로 배울 게 적다 |

화면에 **반드시 보여줄 것**: `counts`(유형별 건수)와 **위반 : 정상 비율**. 한쪽만 쌓이면
모델이 그 방향으로 기웁니다 — 오탐만 넣으면 겁을 먹어 아무것도 못 잡고, 미탐만 넣으면
의심만 늘어 성실한 리서처를 막습니다.

`leaked > 0` 이면 경고를 띄우십시오 — 평가 코퍼스 문장이 운영 데이터에 흘러들었다는 뜻입니다.

#### ⑤ **교사에게 넘기는 문서** (`/admin/compliance` 보류 건마다) — 서버 완성

**이 화면이 이 시스템의 심장입니다.** 외부 API가 없으므로 2차 검수를 대화 상대(교사)가
합니다. 관리자는 **판단하는 사람이 아니라 잇는 사람**입니다:

```
보류 건  →  [교사에게 물어볼 문서 복사]  →  대화창에 붙여 넣기
                                              ↓
        [답 붙여 넣기] ← 정해진 형식으로 온 답
              ↓
        승인/반려 · 유형 · 사유가 **자동으로 채워짐**  →  학습 라벨
```

호출할 함수 둘:

```ts
import { getManualReviewPrompt, readManualReviewAnswer } from '@/server/manualReviewService';

const prompt = await getManualReviewPrompt(prisma, reviewId);   // 복사할 문서
const answer = readManualReviewAnswer(pastedText);              // 못 읽으면 null
// answer = { verdict, categories, reason, findingsValid }
```

**반드시 지킬 것:**

| | 왜 |
|---|---|
| 관리자가 문서를 **손으로 고치게 하지 마십시오** | 요약하거나 옮겨 적으면 거기서 라벨이 흐려진다. 뽑는 것도 넣는 것도 기계가 한다 |
| `readManualReviewAnswer` 가 **null 이면 자동 기록하지 마십시오** | 형식이 어긋난 답을 억지로 해석하면 **틀린 라벨이 학습 자료가 된다.** 그때는 관리자가 손으로 고르게 한다 |
| 원문은 **무작위 경계**로 감싸 나갑니다 | 리서처가 본문에 적어 둔 지시문이 교사에게 그대로 읽힌다. 경계는 부를 때마다 새로 만들어지니 캐시하지 마십시오 |
| 반려인데 유형이 없으면 **거절됩니다** | 라벨이 비면 다중 라벨 BCE 가 그 위반을 **정상으로** 가르친다 |

- **학생 모델 상태** — 라이브 / 그림자 / 꺼짐, 그리고 자동 격하 걸쇠가 걸렸는지
- **화이트리스트 충돌** — 새로 상장된 종목명이 규칙을 끄고 있는지 (매일 06:00 검사)
- **미탐 건수** — 이게 0으로 오래 유지되면 좋은 게 아니라 **미탐 라벨 경로가 끊긴 것**일 수 있다

## 6. 학생 모델에 대해 알아야 할 것

**지금 학생 모델의 값어치가 불투명합니다.** 최근 측정에서:

| 적대 코퍼스 90건 | 탐지 기여 | 오탐 |
|---|---|---|
| 규칙 | 36/36 | 0 |
| **학생 추가분** | **+0** | **+2** |

학생이 잘못 잡는 둘: `리딩기업으로 자리잡은 반도체 소재주`(→리딩방으로 오인), `상담역으로 영입된 인사`(→개인 상담으로 오인).

다만 이건 **규칙을 그 코퍼스를 보고 만들었기 때문**이기도 합니다. 학생이 맡기로 한 자리는 원래 **패러프레이즈**(같은 뜻 다른 말)인데, 우리가 아는 표현은 이미 규칙이 됐습니다.

→ **관리자 앱은 학생 모델의 상태를 켜고 끌 수 있게 해야 합니다** (`STUDENT_MODE`: `off` / `shadow` / `live`). 특히 **그림자 모드**가 중요합니다 — 판정에 안 끼고 기록만 남겨서, 운영자 판정과 대조해 값어치를 실측한 뒤 켤 수 있습니다.

관련 코드: `infra/compliance/studentClient.ts`, `server/studentAutoShadow.ts`(자동 격하 걸쇠), `server/shadowScreeningService.ts`

## 7. 재학습은 이렇게 돕니다 (CLI — 관리자 앱이 감싸도 됩니다)

```bash
# ① 자료 확인
npm run train:export          # 손코퍼스 (출시 전 부트스트랩)
npm run train:operator        # **운영자 판정에서 뽑기 (출시 후 주 원천)**
npm run train:case -- <파일> --violation SOLICIT_CONTACT   # 한 건 추가

# ② 학습 (파이썬 사이드카의 venv 사용, 외부 API 0회)
cd training
../sidecar/.venv/Scripts/python.exe train.py --data data/*.jsonl --epochs 12
../sidecar/.venv/Scripts/python.exe export_onnx.py

# ③ 채택 판단 — 이걸 통과 못 하면 배포하지 말 것
cd .. && npm run eval:student -- --sweep
```

### ⚠ 관리자 앱이 재학습을 실행하게 만든다면 지켜야 할 것

1. **채택선을 통과하지 못하면 배포 금지.** 사례 몇 건이 전체 성적을 깎을 수 있고, 그때 필요한 것은 더 넣는 게 아니라 **왜 깎였는지 보는 것**입니다.
2. **평가 코퍼스를 학습에 넣지 마십시오.** 8차에 이 실수를 했고(학습셋=채점지) 성적이 자기 답안을 채점하게 됐습니다. `training/holdout/` 아래 것은 **학습 금지**입니다.
3. **가중치 지문(`model_sha`)이 바뀌면 카나리아를 다시 구우십시오.** 지문이 어긋난 모델은 라이브에 못 들어갑니다.

## 8. 하면 안 되는 것

| 금지 | 이유 |
|---|---|
| 모델·AI 판정으로 **즉시 거절** | §1 원칙. 재현 불가능한 판정에 거절 권한을 주지 않는다 |
| 승인 시 "지적은 타당" 체크박스를 **기본 켜짐**으로 | 라벨이 통째로 오염된다 |
| 검수 이력 **삭제** | 차단 시도까지 보존해야 어뷰징 탐지 근거가 된다. 상태만 바꾼다 |
| 운영자 판정 없이 **자동으로 학습 자료 채택** | 잘못된 판정이 그대로 학습된다 |
| 리서처에게 **금지어 목록 노출** | 반려 사유·인용문은 주되 규칙 자체는 비공개(영업비밀). 반려 3회면 자동 통과 경로가 닫히는 장치가 이미 있다(`REPUBLISH_REVIEW_THRESHOLD`) |
| 소견에서 **원문 인용 제거** | 리서처가 자기 글에서 어디를 고칠지 모른다. 인용은 반드시 원문 기준(정규화본이 아니라) |
| 관리자 화면을 만들면서 **인증 관문을 `layout.tsx` 에 맡기기** | 아래 §8-1. 실제로 한 번 뚫렸다 |

### 8-1. 관리자 화면은 **페이지마다** 잠근다 (2026-08-23 실제 사고)

`src/app/admin/layout.tsx` 는 이름도 주석도 "전면 게이트"처럼 읽히지만 **인증 관문이
아니다.** 실제로 막는 것은 *운영자인데 패스키가 0개인 경우* 하나뿐이고, 나머지는 전부
그대로 통과시킨다:

```tsx
if (!userId) return <>{children}</>;                  // 비로그인 → 그냥 그린다
if (me?.role !== "OPERATOR") return <>{children}</>;  // 일반 이용자 → 그냥 그린다
```

의도된 설계다(각 페이지가 자기 `notFound()` 로 닫는다는 전제). 문제는 **레이아웃이
있으니 덮여 있겠지**로 읽히기 딱 좋다는 것이고, 실제로 그렇게 됐다 —
`/admin/compliance/iris` 가 **로그인 없이 200** 이었다(모델명·적재 지문·검수 정확도·
운영자 판정 건수가 그대로 노출). 화면을 만든 사람도, 시험 1,600건도, `tsc` 도 아무도
잡지 못했다. **관문이 없는 것은 오류가 아니라 침묵이기 때문이다.**

새 관리자 화면에는 이 네 줄을 **직접** 넣는다:

```tsx
const userId = await getSessionUserId();
if (!userId) notFound();
const user = await prisma.user.findUnique({ where: { id: userId }, select: { role: true } });
if (user?.role !== "OPERATOR") notFound();
```

`403` 이 아니라 `notFound()` 인 이유 — `403` 은 "여기 뭔가 있다"를 알려 준다.

**확인하는 법** (서버를 띄운 채, 로그인하지 않은 상태로):

```bash
curl -o /dev/null -s -w "%{http_code}\n" http://localhost:3000/admin/<새화면>
```

`404` 가 나와야 한다. `200` 이면 관문이 없는 것이다.
