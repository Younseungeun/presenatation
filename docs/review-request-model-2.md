# INTOVILL 검수 모델 2차 검토 요청 — 1차의 질문 여섯에 답을 정해 파이프라인을 깔았고, 첫 측정에서 오염을 발견했습니다

성과 검증형 리서치 마켓플레이스입니다. 리서처가 예측 카드(종목·방향·크기·시한·신뢰도)를
걸고 리포트를 팔면, 시한에 시장 데이터가 자동 판정합니다. 적중이면 리서처에게 정산되고,
실패면 구매자에게 현금 환불됩니다. 그 사이 돈은 에스크로에 있습니다. 검수는 그 앞단입니다 —
게시 버튼을 누르면 손실보전 약속·1:1 상담 유도 같은 규제 위반 표현과 본문↔카드 모순을 찾아
거절하거나 보류시킵니다. 지금은 정규식 + 운영자 사전 + Claude API 3단이고, 이 스레드는
**앱 안에서 도는 자체 검수 모델(증류)**을 만드는 스레드입니다.

1차 답변을 기다리는 대신 여섯 질문(F-1~F-6)에 잠정 답을 확정해 데이터 파이프라인·학습
스크립트·측정 도구까지 코드로 깔았고 — 그 답들이 맞았는지가 이번 요청의 본론입니다.
그리고 API 키 없이 교사 라벨을 만드는 우회 경로(대화 교사)를 새로 만들어 첫 측정을
돌렸는데, **그 측정에서 스스로 오염을 발견했습니다**(G-α).

이 요청서는 저장소 접근 없이 읽을 수 있게 필요한 계약·수치를 전부 인라인으로 붙였습니다.
코드를 근거로 답하실 때는 저희도 인용을 요구합니다 — 여기 없는 파일 내용은 추측하지 말고
"그 파일을 붙여 달라"고 답해 주세요.

## A. F-1 (임베딩 단계) — 게이트로는 건너뛰고, 서버 전용 의미 인덱스로만 남겼습니다

1차 질문: *"임베딩(1단계)을 건너뛰고 바로 증류로 갑니까?"* — 잠정 답 "건너뛴다"였고
그대로 확정했습니다. 근거: 콜드스타트 계획이 어차피 라벨을 만들 수 있어 "학습 불필요"라는
1단계의 유일한 우선순위 근거가 사라졌고, 임베딩은 부정에 약해(WARN 전용) 문서 단위는
구조적으로 못 합니다. 다만 1차에서 "자신 없는 이유"로 적었던 **운영자 사전의 즉시 반영
성질은 잃지 않았습니다** — 의미 인덱스를 서버 전용으로 남겨, 브라우저에 실리는 것은 증류
모델 한 벌뿐이고 사전은 서버에서 재학습 없이 즉시 반영됩니다.

## B. F-2 (한 모델 vs 두 모델) — 하나로 하되, 헤드도 합쳤습니다: 8차원 다중 라벨 단일 출력

1차 잠정 답 "하나"를 더 밀고 갔습니다. 문장 헤드 + 문서 헤드 두 출력이 아니라
**시그모이드 8차원 다중 라벨 하나**(문장 유형 7 + CARD_MISMATCH 1)입니다. 헤드를 나눠도
구조 이득이 없고, 라벨 불균형은 손실 가중으로 다루면 같은 일을 하기 때문입니다:

- 라벨별 pos_weight = (음성 수/양성 수), 상한 50 — 드문 라벨(CARD_MISMATCH)의 손실이 자동으로 커짐
- 그래도 부족하면 `--doc-weight N`으로 문서 예시의 손실 자체를 증폭
- 1차가 걱정한 "적은 쪽(문서)이 묻히는" 판정은 하네스가 한다 — 채택선 미달이면 그때 분리

출력 라벨 공간(제외 근거 포함):

```
STUDENT_LABELS = [PROFIT_GUARANTEE, PRIVATE_INFO, RUMOR, SOLICIT_CONTACT,
                  UNSUPPORTED_CLAIM, RISK_INDUCEMENT, SCREENING_EVASION, CARD_MISMATCH]
제외: MISSING_DISCLOSURE(종목 위험 플래그 필요한 결합 판단),
     RISKY_INSTRUMENT·UNREALISTIC_TARGET·UNJUDGEABLE_PATTERN(텍스트가 아니라
     종목 데이터·카드 숫자·이력에서 나오는 판정 — 규칙이 이미 결정적으로 한다)
```

## C. F-3 (실행 예산) — 여전히 근거 없는 잠정값입니다. 대신 예산이 병목이 아니게 모델을 골랐습니다

잠정 예산: 브라우저 ONNX int8 ≤ 100MB, 추론 ≤ 200ms(작성 중 사전 검사 디바운스 600ms 안).
1차에서 "근거 없이 고른 숫자"라고 자백했던 문제는 **풀리지 않았습니다** — 다만 기본 모델을
koelectra-small-v3(14M 파라미터, int8 ≈ 14MB)로 골라 예산의 7분의 1에 들어오므로, 예산이
정확한지가 당장의 병목이 아니게 됐습니다. 첫 로드는 작성 화면 진입 시 백그라운드, 로드
전에는 규칙만 동작.

## D. F-4 (브라우저·서버 버전 어긋남) — 모델 식별자를 실어 사전 검사를 끕니다

잠정 답 그대로 확정. 응답에 모델 식별자를 싣고, 브라우저가 자기 버전과 다르면 사전 검사를
끄고 "지금은 미리 볼 수 없습니다"를 띄웁니다. 낡은 모델로 집행(더 나쁨)과 화면의 거짓말
(나쁨) 사이에서 정직하게 끄는 쪽입니다. 1차가 찾던 "셋째 길"은 못 찾았습니다.

## E. F-5 (지금 직접 만드는 것이 맞는가) — API 유지 + 학생은 지금 준비, 단 그림자 모드로만

비용(현 규모 월 만 원대)은 근거에서 뺐습니다. 자체 모델의 진짜 근거는 1차의 "자신 없는
이유"에 있던 둘입니다: ① 작성 중 실시간 검사는 타이핑마다 호출이라 API로 불가
② API 장애 시 그날 게시 전체가 보류 큐로 감(운영자 1명). 그림자 모드(판단 기록만, 처리
권한 없음)는 무해하므로 준비를 미룰 이유가 없다고 판단했습니다.

## F. F-6 (1인 라벨 문제) — 합성 라벨링의 의도↔교사 불일치 목록을 사람 재검토 경로로 씁니다

이중 라벨 전수는 여력이 없으니, 합성 문장의 **생성 의도와 교사 판정이 어긋난 것만** 사람이
봅니다(어긋남 = 생성이 빗나갔거나 교사가 틀렸거나 — 어느 쪽이든 사람이 봐야 할 문장).
risk_heavy 채택선의 손코퍼스 의존은 1차 결론대로 인정하고 운영자 판정 축적을 기다립니다.

## G. 이번에 새로 넘어간 주제 — 대화 교사 경로: API 종량 과금 없이 교사 라벨을 만든다

전제부터: `ANTHROPIC_API_KEY`가 없어 1차의 블로커였던 교사 기준선 측정이 막혀 있었습니다.
사용자(창업자)가 이미 구독으로 대화형 Claude를 쓰고 있어, **대화 자체를 교사로 쓰는
경로**를 만들었습니다. 흐름:

```
label:pack   문제지 생성 — 운영 어댑터의 SYSTEM_PROMPT를 글자 그대로 싣고
             (규정 복제 금지: 따로 적으면 프롬프트 변경 시 두 교사의 기준이 조용히 갈린다),
             정답·생성 의도는 팩에 넣지 않고 manifest.json에만 둔다
             (보여주면 교사가 따라가 독립 판정이 아니게 된다)
  ↓ 사람이 대화창에 붙여넣고, 답안(JSONL: {"id","labels":[...]})을 받아 저장
label:ingest 검증 — id 오타·허용 밖 라벨·중복을 전부 잡고, 하나라도 걸리면 아무것도
             저장하지 않는다. 같은 id 재답안은 마지막이 이긴다(재라벨링 경로).
             라벨에 labeler: "conversation:모델명"을 박는다 — API 교사("claude:모델명")와
             섞였을 때 어느 쪽이 오염됐는지 구분하기 위해
  ↓
eval:teacher --from FILE   같은 하네스(evaluate)로 채점 — API 경로와 수치가 직접 비교된다
```

학습 데이터 형식(전 원천 공통, 한 곳에만 정의):

```jsonc
// TrainingExample — JSONL 한 줄
{"id":"sent:5","source":"hand_corpus","kind":"paraphrase",
 "text":"[카드] 방향 상승\n[제목] \n[요약] \n[본문] 떨어지면 차액은 제 사비로…",
 "labels":["PROFIT_GUARANTEE"],"labeler":"conversation:claude-opus-5"}
```
`text`는 `buildStudentText()`(카드+제목+요약+본문 직렬화) 한 함수가 만들고 학습·추론이
공유합니다 — 학습 때와 다른 직렬화로 추론하면 지표가 예외 없이 조용히 무너지기 때문입니다.

**첫 측정 (문장 코퍼스 86/86, 대화 교사):**

| | 교사 | 규칙 기준선 |
|---|---|---|
| 탐지율 | 100.0% | 53.8% |
| 오탐률 | 0.0% | 17.6% |
| 패러프레이즈 탐지 | 24/24 | 0/24 |
| 부정문 오탐 | **0/12** | 6/12 (50%) |
| 면책 문구 오탐 | 0/6 | 0/6 |

채택선은 문장으로 박았습니다(절대 문턱을 미리 정하지 않고 제약 안에서 최대화):
> ① 학생의 오탐률 ≤ 교사, ② ≤ 규칙 기준선의 보류율(17.6%). 그 제약을 지키는 설정 중
> 패러프레이즈 탐지율 최대를 채택. 교사의 패러프레이즈 탐지율이 천장.

## G-α. 별건 — 그 100%는 오염된 수치입니다 (스스로 발견)

라벨링을 수행한 세션(이 작업 세션)이 **코퍼스 원본 파일을 이미 읽은 상태**였습니다.
그 파일에는 정답 라벨이 함께 적혀 있어, 위반 구간(sent:0~40)의 판정은 독립적 판단이 아니라
답안 회상일 수 있습니다. 팩에서 정답을 빼는 방어는 이 경우 무력합니다.

구간별로 가르면: **오탐률 0%는 유효합니다** — 정상 34건 전부가 세션이 원본을 읽기 전
구간에 있습니다(부정문 12건 포함). **패러프레이즈 100%는 인용 불가** — 대부분 오염 구간에
있습니다. 대응: 오염 사실과 재측정 절차(코퍼스를 읽지 않은 새 세션에서 해당 팩만 재라벨 →
같은 id 덮어쓰기)를 `training/labeling/README.md`에 기록했습니다.

## G-β. 별건 — 합성 데이터 생성도 같은 경로로 겸합니다

`label:pack --task generate`가 유형별 생성 지시서를 만듭니다: 위반 패러프레이즈 N건 +
**같은 유형과 어휘가 겹치는 하드 네거티브 N건**(부정문·면책·평범한 분석 — 무관한 정상
문장은 아무것도 가르치지 않으므로 금지). 생성 의도는 라벨이 아니고, 라벨은 교사가 같은
규정으로 재판정해 붙입니다.

## H. 답을 듣고 싶은 것

### H-1. 대화 교사 라벨을 학습셋에 섞어도 됩니까?

**잠정 답**: 섞는다. `labeler` 표식으로 출처를 구분해 두고, 문제가 드러나면 그 출처만
걷어낸다.

**자신 없는 이유**: 두 교사의 조건이 다릅니다 — API 경로는 temperature 0 + 구조화 출력
강제("판정은 같은 리포트에 같은 답" 원칙), 대화 경로는 둘 다 보장이 없습니다. 게다가 대화
세션은 리포지토리 맥락(설계 논의, 심하면 코퍼스 원본)을 들고 있을 수 있어 G-α 같은 오염이
**구조적으로 재발 가능**합니다. "깨끗한 새 세션에서만 라벨링한다"는 규율로 충분한지,
아니면 사람의 규율에 기대는 방어는 방어가 아닌지 판단이 안 섭니다.

**틀렸을 때**: 학습셋이 회상·맥락 편향으로 오염되고, 그 라벨로 잰 교사 기준선(=증류
천장)이 부풀어 채택선 전체가 무의미해집니다.

### H-2. 평가(기준선)와 라벨 생산을 같은 경로에 두면 안 되는 것 아닙니까?

**잠정 답**: 나눈다 — 교사 **기준선 측정**은 오염 불가능한 조건(API temperature 0, 또는
코퍼스를 접한 적 없는 세션)에서만 인정하고, 대화 교사는 **학습 라벨 생산**에만 쓴다.
G-α에서 얻은 잠정 규칙인데 아직 문서에만 있고 도구가 강제하지 않습니다.

**자신 없는 이유**: "코퍼스를 접한 적 없는 세션"을 기계적으로 검증할 방법이 없습니다.
지금 생각한 대안은 평가용 문항을 코퍼스가 아니라 **신규 작성 홀드아웃**으로 따로 두는
것인데(원본 파일에 없는 문장이면 회상이 불가능), 그러면 1인 작성 문제(F-6)가 홀드아웃에서
재발합니다.

**틀렸을 때**: 천장을 잘못 재고, 학생이 천장에 못 미치는 건지 천장이 허수인지 영영
구분하지 못합니다.

### H-3. 생성도 라벨도 같은 모델 계열입니다 — 학생이 "Claude 문체의 위반"만 배우는 것 아닙니까?

**잠정 답**: 위험을 인정하되 지금 구조로 간다. 방어는 셋 — ① 하드 네거티브를 같은 유형에서
짝으로 생성(어휘 겹침 강제) ② 검증셋은 합성이 아니라 손코퍼스 + 이후 운영자 판정
③ 그림자 모드에서 실제 리서처 문장에 대한 Claude 판정과의 일치율을 보고 나서 실권 부여.

**자신 없는 이유**: 분포 편향을 배포 전에 **측정할 수단이 없습니다.** 실제 리서처 문장
표본이 0건(출시 전)이라, ③의 그림자 모드가 유일한 검증인데 그건 배포 후입니다.

**틀렸을 때**: 벤치마크(합성·손코퍼스)에서는 채택선을 넘는데 실제 문장에서 무너지는
모델을 앱에 싣게 됩니다. 그림자 모드가 마지막 그물이라 사고는 안 나지만, 그때까지의
학습·배포 작업이 통째로 되돌아갑니다.

### H-4. CARD_MISMATCH를 8차원 단일 출력에 태우는 것과 NLI 교차 인코더 분리, 어느 쪽입니까?

**잠정 답**: 단일 출력 먼저. 채택선(risk_heavy 오탐 이중 조건) 미달로 판명되면 분리한다.
검수 파이프라인 스레드 1차에서 "본문–카드 모순은 NLI 교차 인코더 구조로 가능"이라는
지적을 받았고 그건 맞습니다 — 다만 입력이 이미 `buildStudentText`로 카드를 문장화해 본문과
함께 넣는 형태라, 인코더 하나로도 같은 정보가 들어갑니다. 구조(교차 인코더의 상호 어텐션)가
아니라 **정보(카드가 입력에 있는가)**가 본질이라고 보고 있습니다.

**자신 없는 이유**: 14M 소형 인코더의 [CLS] 분류가 "본문 결론 추출 + 카드와 대조"라는
2단 추론을 감당한다는 근거가 없습니다. 문서 라벨이 42건뿐이라 학습으로 확인하기도 전에
데이터가 부족합니다.

**틀렸을 때**: 문서 42건 + 합성 확장으로 학습셋을 다시 짜야 하고(문서 합성은 라벨 오염
위험으로 v2로 미뤄둔 상태), 모델이 두 벌이 되어 F-2·F-3 결정이 연쇄로 되돌아갑니다.

## 검수 모델 스레드에서 이미 답이 난 것 (이번 회차에 걸리는 줄만)

| 결론 | 근거 |
|---|---|
| 오탐(정상 차단)이 미탐(위반 통과)보다 비싸다 | 미탐은 에스크로 환불로 되돌아오고, 오탐으로 떠난 리서처는 돌아오지 않는다 |
| 자동 거절 권한은 결정적 규칙에만 | AI·사전·유사도·학생 모델은 전부 보류(WARN)로만 간다 |
| 모델보다 평가셋이 먼저다 | 하네스는 탐지기를 "검수 입력 → 소견" 함수로만 본다 — 규칙이든 학생이든 같은 잣대 |
| 판정은 temperature 0 | 같은 리포트에 같은 답이 나와야 기준선이 재현된다 (대화 교사가 이걸 못 지키는 것이 H-1) |
| 정답이 없는 구간에는 라벨을 붙이지 않는다 | probe 4건은 학습셋 수출에서도 제외했다 |
| 모델 입력은 ScreeningInput 전체 | 카드를 뺀 모델은 본문–카드 모순을 영원히 못 배운다 |
| 채택은 val F1이 아니라 하네스로 | 채택선: 오탐률 ≤ 교사 그리고 ≤ 규칙 보류율, 그 안에서 패러프레이즈 탐지율 최대 |
| 손코퍼스는 절대 수치가 아니다 | 변경 전후 비교에만 쓴다. 운영자 판정이 쌓이면 그쪽이 진짜 검증셋 |
