## 안건 A. 학습 표현의 BLOCK 승격 — 심사 자료를 앱이 모아 달라

### 불변 원칙 (재확인)

- **사전(LearnedPhrase)은 영구 WARN.** 사람이 입력한 문자열에 즉시 거절 권한을 주면
  오타 하나로 정상 리포트가 사람 확인 없이 죽는다 — 이건 바뀌지 않습니다
- **BLOCK 승격 = 코드 이식만** (회신 7호 확정). 정규식 + 부정 문맥(STRONG/WEAK) 처리 +
  채점지 회귀를 갖춰 규칙 엔진에 넣는 서버 쪽 작업입니다

즉 승격의 병목은 "이 표현을 BLOCK 규칙으로 옮겨도 되는가"를 **판단할 증거**이고,
그 증거는 운영 중에만 쌓입니다. 지금 표(matchCount·confirmedCount)로는 부족한 이유:
숫자만 있고 **문장이 없습니다.** BLOCK 이식 설계에 필요한 것은 어미 변형과 부정 문맥의
실제 출현형인데, reportId 참조는 반려 후 리서처가 본문을 고치면 그때의 문장을 잃습니다.

### 요청 1 — 매칭 스냅샷 (LearnedPhraseHit 확장)

Hit 가 생길 때 다음을 **그 시점 값으로 박제**해 주세요 (리포트를 다시 조회하지 않고):

| 칸 | 내용 | 왜 |
|---|---|---|
| `matchedSentence` | 매칭 지점을 포함한 문장 전체 (± 앞뒤 60자) | 어미 변형·문맥이 곧 정규식 설계 재료 |
| `matchedSurface` | 실제 출현형 (정규화 전 원문 조각) | "보장해드립니다/보장이 되는/보 장" 변형 수집 |
| `negationNearby` | 같은 문장에 부정·면책 어휘 공존 여부 (기존 부정 검사 재사용, boolean) | **BLOCK 이식의 최대 위험이 부정문 오거절** — 이 표현이 부정형으로 쓰인 실적이 있는지가 심사의 핵심 증거 |
| `verdict` | 그 게시 시도의 최종 판정 (승인/반려/자동만료) — 판정 시점에 갱신 | 문장 단위 정탐/오탐 연결 |

### 요청 2 — "코드 이식 후보" 큐 (기준선 제안 — 판정 요청 ①)

/admin/compliance ?tab=phrases 에 승격 후보 배지 + 증거 묶음 화면:

- 후보 기준선 (제안): `matchCount ≥ 10` **AND** 정탐률 100% (`confirmedCount == matchCount`,
  승인 처리 0건) **AND** `negationNearby` 출현 0건
- 후보가 되면: 표현 + 매칭 문장 전부 + 출현형 목록을 한 화면에 묶어 보여주고,
  운영자가 "이식 요청" 을 누르면 그 묶음이 서버 세션의 작업 지시서가 됩니다
  (이식 = 정규식 작성 + STRONG/WEAK 부정 처리 + 채점지·회귀 통과 후 커밋)
- 이식 완료 후: 사전 항목은 **삭제가 아니라 비활성화** + 이식 커밋 sha 를 note 에 기록
  (사전의 이력이 곧 규칙의 족보)

기준선 수치(10회/100%/부정 0)는 초안입니다 — 운영 첫 분기 실측으로 재보정 전제.

## 안건 B. IRIS 재학습 자료 — 캡처 형식 보강

### 불변 원칙 (operatorTraining.ts 계약 그대로)

오탐 → 라벨 없음(하드 네거티브) · 미탐 → 운영자 지목 유형 · **경미는 안 넣는다** ·
유형 미지목 미탐도 안 넣는다 · 정탐은 앵커 10%만 · labeler `operator:<userId>`.
여기는 손대지 않습니다. 보강하려는 것은 **판정에 붙는 부속 정보**입니다.

### 요청 3 — 근거 문장 지목 (미탐·반려 시)

운영자가 반려하거나 미탐을 기록할 때, **위반의 근거 문장을 지목**하게 해 주세요
(검수 인용문 UI 가 이미 있으니 그 선택 방식 재사용 — 자유 드래그면 충분).

왜: IRIS 는 문서를 **2문장 창으로 쪼개** 학습·추론합니다. 문서 전체에 라벨만 붙으면
"어느 창이 위반인가"를 모른 채 정상 문장들에도 위반 라벨이 묻습니다 — 라벨 하나가
소음 아홉을 데려오는 구조입니다. 근거 문장이 있으면 그 창만 위반으로, 나머지는
정상으로 나눠 쓸 수 있습니다. (필수는 아니고 권장 — 지목이 없으면 종전대로 문서 라벨)

### 요청 4 — 대비쌍 표시 (이번 실측이 준 교훈)

36차 실측에서 확인된 사실을 공유합니다: 검수 모델의 병목은 어휘가 아니라 **부정형
정밀도**입니다 ("원금 보장합니다" vs "원금 보장은 안 됩니다"의 구분). 그래서 가장
값진 학습 자료는 낱개 위반문이 아니라 **위반문·정상문 대비쌍**입니다.

- 같은 표현(learned phrase 나 규칙 id)이 걸렸는데 **한 건은 반려, 한 건은 승인**으로
  갈린 사례를 자동으로 짝지어 표시해 주세요 (요청 1 의 verdict 갱신이 재료)
- 운영자에게 추가 입력을 요구하는 게 아닙니다 — 이미 내린 판정 두 개를 짝지어
  보여주기만 하면, 서버 쪽 train:operator 가 그 쌍을 대비쌍으로 내보냅니다

### 요청 5 — LL-3 동결 순번 (확인만)

운영 판정 첫 **50건은 검증 전용 영구 동결**(36차 LL-3)입니다. 판정에 전역 순번이
남는지 확인 부탁드립니다 (ComplianceReview 생성 순서로 충분하면 새 칸 불필요 —
train:operator 쪽에서 앞 50건을 자동 제외하는 것은 서버 몫).
