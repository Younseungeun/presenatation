## §1. 창업자의 이해 → **정확합니다** [확인]

사전 = 코드 규칙의 **입력값**. `activeRules = [...RULES, ...phrases.map(phraseToRule)]`
한 줄이 전부이고, 사전 항목은 코드 패턴과 같은 층·같은 가드(부정 문맥·종목명 마스킹·
**면제 구문**까지)를 지납니다. 4·6층이 사전과 무관한 이유도 읽으신 대로입니다 — 낱말이
아니라 글 전체의 성질(숫자 묶음 모양·문자 혼용)을 보는 층이라 "표현 한 줄"이 들어갈
자리가 없습니다.

## §2. WARN/BLOCK 을 가르는 기준 → **(나)+(다), 그리고 하나 더 (마)** [정책 확정]

여러분의 독해가 맞습니다. 20차 X-2 의 "비의미적 형태만 BLOCK" 문장은 **틀린 요약**이었고
BLOCK 목록 전수 대조로 반증됐습니다 — 감사합니다. 기준을 다시 적습니다. 즉시 거절
권한은 다음 **셋을 전부** 만족하는 패턴에만 있습니다:

| 기준 | 뜻 | 사전 항목이 만족할 수 있나 |
|---|---|---|
| **(나) 매처의 정밀도** | 문맥 조건(약속 어미·연락 유도 어휘·부정 범위)을 **코드로** 적을 수 있다 | 불가 — 사전은 문자열 하나라 "어떤 문맥에서"를 적을 자리가 없다 |
| **(다) 측정** | 채점지·홀드아웃·창업자 배터리·DART 정제판 1,945 에서 **거절 오탐 0** 이 측정됐다 | 운영 집계(matchCount/confirmedCount)는 다른 종류의 증거 — 아래 |
| **(마) 권한의 원천** | 거절 권한은 **코드 배포**를 거쳐서만 생긴다 — 26차 BB-2 에서 면제 구문에 적용한 원칙과 대칭 | 불가 — 사전은 운영 중 사람 손으로 바뀐다 |

"오타 하나로"는 (마)의 **한 사례**였지 근거의 전부가 아니었습니다. 두 어절 하한·부정
가드로 오타 사고는 줄었어도 (나)·(마)는 그대로입니다. 주석을 이 표의 뜻으로 고쳤습니다.

**(다)의 보충 — 운영 집계가 왜 같은 증거가 아닌가.** "30회 걸려 100% 반려"는 **이
플랫폼의 최근 리서처 분포**에서의 정밀도이고, 코퍼스 측정은 **적대적·형식적 대조군**
(공시 산문 1,945·창업자 공격 배터리·부정문·면책 문구)에서의 정밀도입니다. 앞의 것은
리서처 한 명이 같은 문구를 30번 쓰면 만들어집니다. 즉시 거절이 지키는 상대는 "지금
리서처"가 아니라 "아직 안 온 정상 문장"이라, 후자의 증거만 인정합니다.

### (b) 사전 항목의 승격 → **사전 자체로는 열지 않습니다. 단, 승격 경로는 있습니다**

승격은 "사전 항목의 심각도를 올리는 것"이 아니라 **"사전 항목을 코드 패턴으로 이식하는
것"**입니다 — 개발자가 문맥 조건을 적고(나), 코퍼스 전수 검사를 통과시키고(다),
배포한다(마). 운영 집계는 그 이식의 **후보 선정 근거**로만 씁니다. 화면에 보여도 좋은
후보 조건(표시 전용, 자동 승격 아님):

- 걸린 횟수 ≥ 30 · 반려 확정률 100% · 등록 후 30일 경과 · 서로 다른 리서처 ≥ 5명
  (한 사람이 만든 30회는 증거가 아니다)

화면 문구 제안: **"이 표현은 보류만 시킵니다. 30회 이상 걸려 전부 반려로 확정되면 코드
규칙 후보로 올라갑니다 — 즉시 거절은 코드 배포로만 생깁니다."**

20차 X-2 의 근거 문장은 이렇게 바꿔 적어 주십시오: ~~"의미의 관할은 학생"~~ →
**"즉시 거절은 문맥 조건을 코드로 적을 수 있고 대조군에서 오탐 0이 측정된 패턴에만,
코드 배포를 거쳐서만 생긴다. 사전·학생은 사람이 보는 보류까지."**

## §3. 학습으로 WARN 이 BLOCK 이 되는가 → **아니오, 영구 확정** [정책 확정]

세 갈래 표를 확정합니다:

| 무엇 | 지금 | 학습으로 BLOCK 에 닿나 |
|---|---|---|
| 학생 모델 | 항상 WARN | **아니오 — 영구.** 성능과 무관한 권한 설계 |
| 사전 항목 | 항상 WARN | 아니오 — 코드 이식이 유일한 경로 (§2-b) |
| 코드 패턴 | 일부 BLOCK | 학습이 아니라 사람이 문맥 조건을 적는 일 |

이유는 "확률 모델이라"가 절반, 나머지 절반이 더 중요합니다: **학생의 정확도는 측정한
분포 위의 값**이고, 실전 리서처 산문의 분포는 출시 전에 측정할 수 없습니다(27차
넷째 범주). 오늘 실제로 겪었습니다 — 재학습 r6·r7 이 합성 검증 AP 는 비슷한데 채점지
점수는 붕괴했습니다. 학습이 권한을 열 수 있었다면 그날 거절 오탐이 생깁니다.
WARN 은 "사람이 본다", BLOCK 은 "사람 없이 죽는다"의 차이이고, 후자는 λ=4 아래에서
코드 배포라는 사람의 결정으로만 늘어납니다. **네, 의도한 상태입니다** — 검수
커버리지(보류)는 학습으로 넓어지고, 즉시 거절 목록은 사람이 코드를 고쳐야 늘어납니다.

사전 화면 문구는 §2-b 제안대로 "보류만 + 코드 규칙 후보 조건"으로 적어 주시면 됩니다.
승격 가능성은 **있되 사람의 일**이라는 것이 정확한 표현입니다.

## §4. 규칙 id 정렬 → **완료** [수정]

7개 전부 여러분 표대로 바꿨습니다(`PROFIT_EUPHEMISM`→`CONTACT_MIXED_DIGITS` … `RULE_10`
→`RISK_INDUCEMENT`). ruleId 읽는 곳이 0 이라는 확인도 맞아, 도메인 시험 727건 전건
통과로 끝났습니다. 규칙 단위 오탐 집계를 시작하실 때 이 이름들을 쓰시면 됩니다.
