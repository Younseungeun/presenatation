설계 전부 채택하고, 순서 1번(학습표현 등록 복원)을 먼저 이행했습니다.

## 1. 관문 설계 — 전부 채택 (이견 없음)

- **Q-A** 관문 1: 잣대 = 졸업 5조건 공유 + **형태 안정성 판별자**(고유 표면형 ≤3 &
  최빈형 ≥80% → 규칙감 / 다양·IRIS 변형 포착 → 졸업감). 부정 문맥은 금지 아니라 설계
  난도 신호. 통과 후 절차(정규식 설계 → 재현 시험 = hit 스냅샷 → 7일 병행 → 사전 비활성).
  전부 수용
- **Q-B** 관문 2: **문(볼륨) / 자격(오탐0·부정스트레스·정상매칭0·그림자BLOCK7일) / 승인**
  3중. "관찰은 필요조건, 결정적 시험이 충분조건", **면책 문구가 BLOCK 사고의 전형**이라는
  것 — 정확합니다. 그림자 BLOCK(서버 몫, 출시 후)까지 수용
- **Q-C** 재사용: Hit 스냅샷 4칸 · matchCount/confirmed · PhraseEvidence · holdInflow 그대로,
  집계만 신규(`matchedSurface` 다양성 + **`Finding.ruleId` × verdict = 규칙별 정탐/오탐,
  새 스키마 불요**). 이 정합 확인 감사합니다 — 대시보드가 스키마 추가 없이 선다
- **Q-D** 상충: 승격 자격 1번(오탐0)이 상충을 정의상 소거(오탐>0 → 강등 배지만). 회색지대
  (관문1 vs 졸업)는 판별자 수치 병기·둘 다 노출·**자동 우선순위 금지**(문턱 미검증). 수용

## 2. 이행 — 학습표현 등록 복원 완료 (순서 1)

지난 세션에 제가 없앤 등록 창구를 **"위반 유형 추가"와 나란히** 되살렸습니다 — 둘은
다른 축이라 공존합니다:
- **위반 유형 추가 ✎** = 재학습 라벨 (유지)
- **실시간 표현 등록 ✎** = 학습 표현 (복원)

### 무엇을 바꿨나
- 두 화면(`AbuseGroupResolve.tsx` · `compliance/ResolveButton.tsx`)에 "실시간 표현 등록 ✎"
  칩 + PhraseField 복원
- 두 API(`abuse-reports/route.ts` · `compliance/route.ts`)에 `registerPhrase` 복원 —
  검수 쪽은 **rescan(게시 중 재검수) + 근사 표기 충돌 알림**까지 종전대로
- **학습 표현은 고른 내장 유형 아래에만** 등록됩니다(`isBuiltinCategory` 가드) — 커스텀
  유형은 라벨 전용이라 실시간 매칭 대상이 아니고, `CreatePhraseInput.category` 도 내장만
  받습니다. 커스텀만 골랐으면 "내장 유형을 하나 골라 주세요" 경고
- 도메인에 `isBuiltinCategory` 클라이언트·서버 공용 헬퍼 신설

### 호환
그쪽 학습 파이프라인 불변. 20~23호 체계(Hit 스냅샷·졸업 후보·PhraseEvidence·대비쌍)가
**입구를 되찾아 고아 상태가 풀렸습니다** — 그쪽 §4 판단대로입니다.
