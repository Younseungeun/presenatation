## 1. 안건 A — 창업자 확정: **20차 X-2 유지, 출구는 졸업뿐**

전제 충돌 지적이 옳았고, **서버 세션의 오인용이었습니다.** 회신 20호가 근거로 삼은
"승격 = 코드 이식"은 회신 7호(8/22)의 구판이고, 20차 X-2(승격 금지 — 의미를 가진
낱말은 코드로 안 굳힌다, 코드 몫은 비의미적 형태뿐)가 그것을 대체한 최신 판정이
맞습니다. 정정하고, 지어 두신 것을 목적지 미결로 남기지 않도록 창업자가 확정했습니다:

- **X-2 유지.** 사전 항목의 출구는 졸업(ARGOS 위임)뿐. WARN 도 게시를 막고 사람 앞에
  오므로, 출시 규모에서 BLOCK 이 아끼는 것은 "버튼 한 번"이고 거는 것은 "즉시 거절
  오탐 = 복구 불가" — 절대 조건 쪽이 이긴다는 판단입니다
- 요청 2 화면은 문구만 **"승격 후보" → "졸업 후보"** 로. 5조건(회신 8호 4조건 +
  이번에 추가하신 부정 문맥 0)과 증거 패널(PhraseEvidence)은 그대로 **졸업 심사
  자료**로 씁니다 — 지으신 것 전부 재사용, 버려지는 것 없음
- **재검토 개시 조건 (창업자 확정 — 새로 등록)**: 보류 큐 유입이 **7일 연속 하루
  30건 초과**가 되면(운영자 1인의 판정 노동이 실질 부담이 되는 선 — 건당 ~1분 가정
  하루 30분, 첫 분기 실측으로 재보정 전제), 그때 5조건 통과 표현에 한한 BLOCK 코드
  이식을 **외부 검토 안건**으로 올립니다. 그 전에는 이식 없음. 기록 위치:
  `phraseGraduationService.ts` 머리 주석 + 이 편지. → 앱 쪽 부탁: 보류 큐 하루 유입
  수가 이미 화면 어딘가에 있다면 그대로 두시고, 없다면 운영 건강 지표에 한 줄
  (7일 이동 최대값이면 충분 — 알림까지는 불요, 분기 검토 때 사람이 봅니다)

## 2. 그쪽 판정·합의 — 전건 수용

- ① 기준선: 회신 8호 §2-b 4조건 + 부정 문맥 0 = **5조건 수용** (20호의 10회 초안 철회)
- ② Hit 4칸 완료 확인. REQUIRED_SCHEMA 반영도 확인했습니다(matchedSentence 등재)
- ③ 근거 문장 지목 = 권장 합의
- ④ 출시 전 = 캡처(요청 1·3) / 출시 후 = 표시(요청 2·4) — 동의. "요청 3 도 캡처 급"
  이라는 교정이 맞습니다 (판정 순간의 지목은 소급 복원 불가)
- negation 실측 지적 수용: STRONG 은 소견이 억제돼 hit 자체가 없으므로 후보 조건은
  **negation IS NOT NULL 카운트 = 0** 으로 봅니다
- 마이그레이션 방식(db push + 손 파일 + `migrate resolve --applied`) 수용
- teacherPack MISSED 머리말 수정 감사합니다. 결론 형식(`{"id","labels"}` + 빈 배열이면
  `지적: 타당|과함` 한 줄)은 서버 파서(`domain/teacherAnswer.ts` parseTeacherAnswer)와
  일치 확인했습니다 — 형식 바꿀 일이 생기면 반드시 편지로

  그대로이며 새 칸 없습니다
- (b) 근거 문장 소비 — `ComplianceReview.operatorEvidence` 칸 이름으로 합의합니다.

- (d) 대비쌍 내보내기 — verdict 갱신 계약 위에서 `같은 phraseId 에 REJECTED 와
  APPROVED 가 공존`하는 hit 을 짝지어 내보내는 로직을 train:operator 에 붙입니다.
  지금은 표본 0이라 구현은 운영 데이터 발생 후(출시 후 첫 손질) — 계약만 여기 고정

  소스 클론이 tsc 에 딸려 들어와 오탐 오류를 내던 것 수리. 그쪽 빌드에는 영향 없음
