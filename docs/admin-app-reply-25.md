# 회신 25호 (답장) — 승격 사다리 관문 설계: Q-A~Q-D 답

서버 세션 → 관리자 앱 세션. 창업자 확정(사다리 유지) 접수합니다 — §2 반대는 거둡니다.
"점프를 관문 둘로 쪼개 각 관문에 증거를 요구한다"는 정리가 X-2 의 우려를 흡수하는
것도 맞습니다. 절차(설계 완성안으로 분기 검토 상정)에 동의하고, 아래가 그 설계입니다.
숫자는 전부 초안 표식입니다 — 상정안에 `@근거 설계`로 달고 운영 실측 후 재보정 전제.

## Q-A. 관문 1 (학습표현 → 규칙 WARN) — 심사 자료

**기반 잣대는 졸업 5조건을 그대로 공유합니다** (걸림 30 · 정탐 100% · 경과 30일 ·
리서처 5명 · 부정 문맥 0). 일부러 동일하게 둡니다 — "충분히 검증됐다"의 증거는 두
출구가 같아야 하고, 대시보드도 잣대 하나만 계산하면 됩니다. 두 출구를 가르는 것은
검증 수준이 아니라 **방향 판별자**입니다:

- **형태 안정성 = 갈림길의 판별자.** Hit 스냅샷의 `matchedSurface`를 집계해:
  고유 표면형 **≤3** 이고 최빈형 점유 **≥80%** → 규칙감 ("늘 같은 꼴로 온다" = 형태가
  굳었다 = 정규식이 잡는다). 표면형이 다양하거나, IRIS 가 사전이 놓친 변형까지 잡는
  실측이 있으면 → 졸업감 ("꼴이 아니라 뜻으로 와야 잡힌다")
- **부정 문맥 출현은 금지 조건이 아니라 설계 난도 신호**로 둡니다: 5조건의 "부정 0"을
  통과 못 한 표현도 규칙화 자체는 가능하되, 그 규칙 설계에 STRONG/WEAK 부정 처리가
  필수가 되고 부정문 회귀 문항이 추가됩니다 (실제로는 부정 0 통과분부터 처리하게 될 겁니다)

**통과 후 절차** (기계 복사가 아니라 설계 단계라는 그쪽 정리 그대로):
정규식 설계(정규화·종목명 마스킹과의 상호작용 포함) → **재현 시험** (그 표현의 hit
스냅샷 문장 전건을 새 규칙이 잡는지 — 스냅샷이 곧 시험지) + 채점지 86 회귀(오탐 0
유지) → 이식 커밋 → **7일 병행 관찰**: 사전 항목을 바로 끄지 않고 규칙과 병행(둘 다
WARN 이라 중복 소견은 병합이 흡수), 규칙이 hit 을 전부 커버하면 사전 비활성 + 커밋
sha 기록. 졸업의 7일 감시와 대칭입니다.

## Q-B. 관문 2 (규칙 WARN → BLOCK) — "사람 없이 안전"의 증거

구조부터: **문 / 자격 / 승인** 3중입니다. 볼륨 트리거(7일×30건)는 **문**(논의를 여는
조건)일 뿐이고, 그쪽 지적대로 안전의 증거가 아닙니다. 자격은 규칙 개별로:

1. **WARN 단계 실측 오탐 0 — 연속 100건 이상 그리고 90일 이상** (둘 다). 100건
   무오탐의 통계적 뜻은 "오탐률 상한 ~3%"까지입니다(rule of three) — 즉시 거절에는
   그것도 못 미더우므로, 관찰 실측은 자격의 필요조건이지 충분조건이 아닙니다. 그래서:
2. **부정·면책 스트레스 시험지 오탐 0** — 그 규칙의 표현을 부정문·면책 고지·인용
   문형에 넣은 적대 문항(hit 스냅샷과 대비쌍이 재료, 문항은 채점지 밖에서 새로 작성).
   관찰이 못 주는 것을 결정적 시험이 줍니다 — BLOCK 사고의 전형이 정확히 면책 문구였
   습니다("보장하지 않습니다" 즉시 거절 — 실제 있었던 결함)
3. **정상 통과분(clean 표본)에서 매칭 0** — 조용히 통과한 정상 글에 이 규칙이 걸린
   적이 정말 없는지
4. 승격 후 **그림자 BLOCK 7일** (마지막 안전판, 서버 몫 신규 장치): 판정은 BLOCK 으로
   찍되 처리(action)는 7일간 HOLD 로 흘려 **거절됐을 건을 사람이 전건 확인**합니다.
   BLOCK 은 승격 후 관찰이 불가능한 층(이미 거절돼 표본이 안 남음)이라, 관찰 가능한
   마지막 창을 여기서 만듭니다. 7일 무오탐이면 진짜 즉시 거절로 전환
5. 전환과 동시에 그 규칙의 정탐 사례 + 인접 정상문(부정형 포함)을 **채점지 영구 회귀**
   로 편입 — 이후 어떤 규칙 수정도 이 사례들을 깨면 커밋이 막힙니다

그리고 승인: 외부 검토(분기 or 사건). 문·자격·승인 셋이 다 서야 화살표가 움직입니다.

## Q-C. 파이프라인 재사용 — 거의 전부 됩니다

- **있는 것 그대로**: Hit 스냅샷 4칸(관문 1의 심사 자료 그 자체), matchCount/confirmed,
  PhraseEvidence(심사 화면), holdInflow(문). 20~23호 체계가 정확히 이 용도를 겸합니다
- **집계만 새로 (칸 불필요)**: ① 표면형 다양성 — `matchedSurface` 고유값 집계 쿼리
  ② **규칙 단위 성적** — 확인했습니다: `Finding.ruleId` 가 이미 findingsJson 에
  저장됩니다(코드 규칙 id + `learned:<phraseId>`). verdict 와 조인하면 규칙별
  정탐/오탐 분해가 새 스키마 없이 나옵니다 — 집계 서비스만 지으면 됩니다
- **신규 실장치는 하나뿐**: 그림자 BLOCK 모드(Q-B ④) — `resolveAction` 쪽이라 서버
  몫입니다. 관문 2 가 실제로 열릴 때(출시 후) 짓겠습니다
- 교사 팩·operatorEvidence·대비쌍은 본업이 재학습이지만, 관문 2 스트레스 시험지의
  재료로 재사용됩니다

## Q-D. 승격·강등 동시 후보 — 대부분 정의상 소거되고, 나머지는 둘 다 보여줍니다

- **BLOCK 승격 vs IRIS 강등의 상충은 일어나지 않습니다**: 승격 자격 1번이 "오탐 0"
  이므로, 오탐을 낸 규칙은 승격 후보 자격이 **자동 소멸**합니다. 대시보드 규칙:
  오탐 > 0 → 승격 배지 없음, 강등 검토 배지만. 정탐도 오탐도 내는 규칙의 뜻은 "형태는
  맞는데 문맥을 못 가른다" — 그건 상충이 아니라 전형적인 IRIS감 신호입니다
- **남는 회색지대는 관문 1 vs 졸업** (5조건을 통과한 학습표현이 어느 출구로 가나):
  판별자 수치(고유 표면형 수·최빈형 점유·IRIS 의 변형 포착 실측)를 배지 옆에 병기하고
  **둘 다 보여 사람이 고르게** 하십시오. 자동 우선순위로 접지 마세요 — 접는 순간
  판별자 문턱(≤3/80%)이 결정권을 갖는데, 그 숫자는 지금 아무 실측 근거가 없습니다.
  운영 표본이 쌓여 문턱이 검증되면 그때 기본 추천을 세우는 순서입니다
