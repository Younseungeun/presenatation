## Q1. 실시간 자격 판정 → **(가) 채택 + 사후에는 (나)** [결정]

여러분의 함정 인식이 정확합니다 — 실시간 미리보기는 "대조 표본에 맞춰 표현을
다듬는" 행동을 값싸게 만들고, 그건 21차 Y-4 가 막은 것의 운영 판입니다. 그리고
비대칭 논리도 그대로 맞습니다: 자격 탈락의 손실은 작고(정확 표기 감시는 유지),
표본에 최적화된 사전의 손실은 측정 자체의 오염이라 되돌릴 수 없습니다.

확정 계약 — **시점으로 가릅니다**:

- **입력 중 (phrase-preview)**: 형태 검사·중복·자격 **여부만**. 자격 없음의 문구는
  `근사 표기까지는 감시하지 못합니다 (정확 표기 감시는 됩니다)` 까지 — 무엇과
  부딪혔는지는 싣지 않습니다. 응답에 collisions 필드를 **아예 넣지 마세요**
  (숨김 처리가 아니라 부재 — 숨긴 필드는 언젠가 켜집니다)
- **등록 직후 (registerPhrase 반환)**: 충돌 목록 전체를 한 번 보여줍니다 — 이게
  주석의 원래 의도("등록 직후 한 번")이고, 표현이 이미 확정된 뒤라 반복 다듬기
  고리가 성립하지 않습니다. 여러분이 잇겠다는 배선이 정확히 이 자리입니다

남는 구멍 하나는 기록해 둡니다: (가)여도 자격 **여부** 자체가 느린 오라클이라
끈질기게 고치면 경계를 더듬을 수 있습니다. 등록이 반려에 붙어 일어나는 정상
동선에서는 그럴 이유가 없어 수용하고, 사전 등록 빈도가 이상해지면(하루 수십 건)
그때 다시 봅니다 — 24차 안건 후보로 적어 뒀습니다.

## Q2. 자카드 브라우저 계산 → **동의** [확인]

`charBigramJaccard` 는 순수 함수고 금지 목록을 담지 않으며, "0.4 이상 거절"은
회피에 쓸 정보가 아니라 운영자가 알아야 할 규칙입니다 — 판단 그대로입니다.
서버 검증이 최종 관문인 것만 유지되면(지금 graduatePhrase 가 어차피 다시 검사)
브라우저 계산은 순수한 UX 개선입니다. 한 가지: 컷오프 0.4 를 화면 코드에 숫자로
박지 말고 `GRADUATION_MAX_PAIR_SIMILARITY` 를 import 하세요 — 값이 실측 재조정될
수 있고, 그날 화면과 서버가 갈라지면 안 됩니다.

## Q3. 재활성화 = 이중 방어 → **의도 맞습니다** [확인]

읽으신 그대로입니다 — 되살린 이유가 "학생이 못 미덥다"인데 그 학생을 시험하는
문항까지 빼면 판단과 어긋납니다. 화면 문구("사전이 다시 잡습니다. 회귀 시험 문항은
그대로 남습니다.")도 좋습니다. 계약 두 가지만 못 박습니다:

- **"졸업 상태"의 판정식은 `active === false && graduatedAt !== null`** 입니다.
  재활성화하면 active 가 true 로 돌아오지만 graduatedAt 은 남습니다 — 그 항목은
  "졸업한 항목" 목록이 아니라 일반 활성 목록으로 돌아가야 합니다 (graduatedAt 만
  보고 졸업 목록에 두면 재활성화가 화면에서 안 보입니다)
- 재활성화하면 **관찰 큐에서도 빠집니다** (recordGraduationWatch/getGraduationWatch 가
  active=false 만 봅니다) — 사전이 다시 잡고 있으니 감시할 공백이 없어진 게 맞습니다

관찰 큐를 사전 화면 상단 묶음으로 얹는 자리 선택도 동의합니다.

## Q4. 그림자 중 졸업 문구 → **확정 + 둘째 문단 한 곳만 고칩시다** [문구]

둘째 문단을 보탠 판단이 맞습니다 — 경고만 있고 "지금 해도 되나"가 없으면 운영자가
멈춥니다. 다만 한 구절이 사실과 어긋납니다: 회귀 시험은 학생의 **근무(라이브)**가
아니라 **재학습 채택 판정**(eval:student)마다 돕니다 — 그림자인 채로도 다음 재학습
때 그 문항으로 시험합니다. 권장:

> 학생이 연수 중입니다. 지금 졸업시키면 이 표현은 당분간 아무도 막지 않습니다
> (규칙·코드 패턴에 걸리는 부분은 계속 막힙니다).
> 대비쌍은 지금 써 두어도 됩니다 — **다음 재학습 채택 판정부터 이 문항으로
> 시험합니다.**
