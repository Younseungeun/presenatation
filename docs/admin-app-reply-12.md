## §3. 절차가 갖게 했습니다 [구현 완료]

`npm run drill` 마지막에 **⑧ 부팅 검사 무장 확인** 을 얹었습니다. 지켜 달라신 둘을 그대로:

1. **`register()` 를 태웁니다, `registerNode` 가 아니라** — `scripts/bootCheckProbe.ts` 가
   `import('../src/instrumentation').then(m => m.register())` 한 줄입니다. 깨질 수 있는 것이
   검사 함수가 아니라 그 함수로 가는 길(가드 조건·동적 import 경로)이라는 지적 그대로입니다
2. **자식 프로세스로 띄우고 종료 코드를 봅니다** — `process.exit(1)` 이라 같은 프로세스면
   리허설이 함께 죽고, 지켜야 하는 성질이 "던진다"가 아니라 "끝난다"입니다. 탐침은
   `register()` 가 *던지면* exit 2 로 구별해 둡니다(반쪽 fast-fail 로의 퇴행을 따로 잡습니다)

절차: 리허설 DB 사본 → `REQUIRED_SCHEMA[0]` 의 표 삭제 → 탐침 실행 → exit 1 + 메시지에 표
이름 확인 → 사본 삭제. 목록 첫 항목을 쓰므로 목록이 바뀌어도 따라옵니다. 그 전에 **멀쩡한
사본도 한 번** 태웁니다 — 거기서 exit≠0 이면 검사가 아니라 환경이 깨진 것이라 둘을 가릅니다.

실측 (오늘 `npm run drill` 끝부분):
```
⑧ 부팅 검사 무장 확인 — register() 를 실제 입구로 태운다
   멀쩡한 사본 → exit 0 · register() 가 돌아왔다 (exit 0)
   표 "ComplianceReview" 삭제 사본 → exit 1
     - 표 "ComplianceReview" 이 없습니다 — 마이그레이션 기록만 있고 SQL 이 돌지 않았을 수 있습니다
   무장 확인 — 가드 → 동적 import → registerNode → 검사 → exit 1, 사슬 전부 살아 있다
```

**무장 해제도 재현해 봤습니다** — 같은 깨진 사본에 가드를 속여(`NEXT_RUNTIME=edge`) 탐침을
돌리면 exit 0 으로 돌아옵니다. 그 경우 ⑧ 은 "⚠ 부팅 검사가 기동 경로에서 빠져 있다 — 표가
없는데 서버가 뜬다"를 찍습니다. 즉 이 단계는 양쪽을 구별합니다.

탐침의 성공 문구는 일부러 "검사가 돌았다"고 말하지 않습니다 — 가드가 건너뛰어도 그 줄에
옵니다. 돌았는지는 깨진 사본의 exit 1 만이 말합니다.

## 왜 시험이 아니라 리허설인가 — 동의

말씀대로입니다. 단위 시험으로 두면 prisma 를 가짜로 바꾼 채 "함수가 맞게 동작한다"를 확인하게
되고, 오늘 물어야 했던 것은 "실제 기동에서 그 함수까지 닿는다"였습니다. 리허설은 단언 없이
사람이 읽는 자리라(incidentDrill 머리말의 원칙) ⑧ 도 채점하지 않고 **무장 확인 / ⚠** 두 줄 중
하나를 찍습니다. 인수인계서 §10 에 `npm run drill` 을 넣고 기대 문구를 적었습니다.
