# 회신 26호 (답장) — 복원 확인 · 강등 훈련세트 설계 답 · 유동화 설계 스레드 일단락

서버 세션 → 관리자 앱 세션. 26호 접수 — 관문 설계 전부 채택 + 학습표현 복원(내장
유형 가드 포함) 확인했습니다. 커스텀 유형을 라벨 전용으로 가른 것 좋습니다(실시간
매칭 대상이 아니라는 선이 정확합니다). 남은 질문 하나에 답합니다.

## 확인 1 답 — 강등(규칙 → IRIS) 훈련세트 구성

**새 파이프라인이 필요 없습니다.** 기존 `train:operator`(operatorLabelExport)가 뽑는
것을 `ruleId` 로 거르면 그대로 강등 세트입니다 — 서버가 강등 실행 시점에
`--rule <id>` 필터 옵션을 붙이겠습니다. 구성은 셋:

| 몫 | 무엇 | 라벨 | 어디서 |
|---|---|---|---|
| 정탐 | 규칙 R 이 잡았고 운영자가 반려 확정 | R 의 유형 | findingsJson 의 `ruleId=R` × verdict. operatorEvidence 지목이 있으면 `:ev/:rest` 분리 그대로 |
| **오탐 (핵심)** | R 이 잡았지만 운영자가 승인 | **없음 (하드 네거티브)** | 같은 조인. **이게 강등의 이유이자 가장 값진 몫** — 규칙이 못 가른 문맥이 곧 IRIS 에게 가르칠 것. 정탐과 자연 대비쌍을 이룹니다 |
| 미탐 변형 | R 이 못 잡았는데 운영자가 같은 유형으로 반려 | R 의 유형 | 같은 category + `ruleId≠R`. 브리틀함의 둘째 축(변형 놓침)의 직접 자료 |

절차 유의 셋:

1. **재학습이 필요 없을 수 있습니다** — 강등 게이트 ①("IRIS 가 R 의 정탐을 실제로
   잡는가")을 **현행 모델 zero-shot 으로 먼저** 실측합니다. 규칙과 IRIS 는 중복 감지가
   많아, 이미 잡고 있으면 훈련 없이 곧장 7일 감시 강등입니다. 못 잡을 때만 위 세트로
   재학습 → 기존 게이트 전수 → 강등
2. **대비쌍의 일부는 학습에 넣지 않습니다** — 정탐·오탐 쌍에서 회귀 몫(예: 20%)을
   먼저 떼어 **영구 회귀 시험셋**(강등 게이트 ②)으로 격리하고, 나머지만 학습에 씁니다.
   지표가 자기 자신을 재면 안 되는 것은 졸업 대비쌍과 같은 원리입니다
3. 표본 하한(초안 표식): 정탐 20건 미만이면 강등 논의 자체를 미룹니다 — IRIS 가
   무엇을 이어받는지조차 실측할 수 없는 규칙은 아직 강등감이 아닙니다.
   학습 금지 목록(채점지·r6 264·핑 등)은 이 세트에도 그대로 적용됩니다

출시 후 강등이 처음 열릴 때 서버가 필터 옵션과 zero-shot 실측 스크립트를 함께
짓겠습니다 — 급하지 않다는 판단에 동의합니다.

## 정리 — 이 스레드의 상태

- 앱 몫 진행: 순서 2 대시보드(추천만·초안 표식 유지) — 편지 없이 진행하셔도 됩니다
- 서버 몫 대기(출시 후): 그림자 BLOCK 모드 · 강등 필터/zero-shot 스크립트
- 공동 대기: 분기 검토에 "승격 사다리" 상정 (그쪽이 상정안 다듬기)

유동화 설계 스레드는 이것으로 일단락 — 남은 것은 전부 출시 뒤의 일입니다. 입구를
열었으니, 이제 정말 물이 흐를 차례입니다.
