지적이 정확합니다. 인용문을 뺀 것으로는 못 막습니다 — **팝업의 출현/소멸 자체가 신호**라
취소 루프로 흔적 없이 무한 튜닝됩니다. 제안하신 카운터 강등을 그대로 넣었습니다.

### 무엇을 바꿨나
- `Report.previewHoldCount`(Int, 기본 0) 신설. 마이그레이션
  `prisma/migrations/20260828100000_report_preview_hold_count/`
  (db push + 손 파일 + `migrate resolve --applied`, dev.db 보존)
- `publishReport`(`src/server/reportService.ts`): 프리뷰가 **보류감(HOLD·반복반려)**을 낼 때
  카운터만 +1 하고(리뷰 행 아님, 큐 유령 없음) `HoldConfirmationRequired`를 던진다.
  `previewHoldCount > PREVIEW_HOLD_LIMIT`이면 **프리뷰를 통째로 건너뛰고** 곧장 실제 검수
  (기록되는 보류) 경로로 강등 — 이진 탐색만 비싸진다
- **게시 성공 시 리셋하지 않습니다** (권고 그대로 — 리셋하면 상한마다 한 번 게시해 우회)

### 문턱 값
`PREVIEW_HOLD_LIMIT = 5`, **초안값 그대로 유지**했습니다. 시뮬은 안 돌렸고(재조정은 운영
데이터가 나온 뒤가 맞다고 봅니다), 근거는 코드 태그에 남겼습니다:
> @근거 설계 정직한 리서처는 1~2회면 끝나 UX 손해가 없고 이진 탐색만 비싸지는 선. 반복
> 반려 문턱(3)보다 느슨해 정상 반복을 살린다

한 가지 경계만 밝혀 둡니다 — 조건이 `previewHoldCount <= LIMIT`이라 **프리뷰 6회까지
허용하고 7회째부터 강등**됩니다("5회 초과 = 6회 이상 강등"). 이 자리가 거슬리면 부등호만
옮기면 되니 답장에 선호 남겨 주세요.

## 수리 ② (몇 줄) — 프리뷰 REJECT 가 기록에서 사라지던 것

"검수 이력은 차단 시도까지 보존" 위반이 맞습니다. 프리뷰 분기에서 REJECT 를 **던지지
않고 흘려보내** 아래 실제 검수(commit=true)가 시도를 기록한 뒤 거절하게 했습니다.
- `if (preview.action === 'REJECT') throw ...` 줄을 걷어냈습니다 — 이제 프리뷰는 HOLD 만
  가로채고, REJECT·PASS 는 실제 검수로 흘러갑니다. 대놓고 수익보장 넣은 시도가 종전대로 남습니다
