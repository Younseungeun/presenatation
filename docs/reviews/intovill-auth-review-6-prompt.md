# INTOVILL 인증 축 6차 검토 — 2인 승인을 1인 체제에 맞게 갈아끼웠습니다. 이 전환을 검증해 주십시오

성과 검증형 리서치 마켓플레이스입니다. 리서처가 예측 카드(종목·방향·크기·시한·신뢰도)를
걸고 리포트를 팔면, 시한에 시장 데이터가 자동 판정합니다. 적중이면 리서처에게 정산되고,
실패면 구매자에게 **현금 환불**됩니다. 그 사이 돈은 에스크로에 있습니다.

**설계 주체(창업자)가 체제를 확정했습니다: 사업 초기 운영자는 본인 1명이고, 이는 바꾸지
않습니다.** 이 문서는 2~5차에 걸쳐 세운 2인 승인 체계를 그 현실에 맞게 전환한 결과를
담습니다. 전환의 원리부터 적습니다 — 반박은 이 원리를 겨눠 주십시오.

---

## 1. 전환의 원리 — 왜 2인 승인을 그대로 두지 않았나

2인 승인이 막는 것은 둘이었습니다: **내부자의 악의**와 **운영자 계정 탈취**.

- **내부자 방어는 1인 체제에서 원리적으로 0입니다.** 내부자 후보가 코드·DB·배포를 전부
  쥔 창업자 본인이라, 앱 관문이 막을 수 있는 상대가 아닙니다. 막을 수 없는 상대를 향한
  관문은 방어가 아니라 절차이고, 그 절차의 비용은 정당한 운영만 냅니다
- **계정 탈취 방어는 진짜였습니다.** 그래서 그 몫을 버리지 않고 축을 바꿨습니다 —
  두 번째 **사람** 대신 **실행 직전 생체 재확인**(지문·얼굴):

```
세션만 훔친 자   → 생체가 없어 못 한다
폰을 주운 자     → 주인의 얼굴·지문이 없어 못 한다
창업자 본인      → 1초
```

재확인은 승인서와 같은 성질로 만들었습니다: **1회용**(쓰면 사라짐), **5분 창**(재확인해
둔 세션을 훔쳐 얹혀 갈 창은 좁게), 세션 주인의 패스키 서명만 인정. 그리고 **진짜 운영자가
2명이 되는 순간 자동으로 2인 승인이 복귀**합니다 — 전환은 코드가 감지하지, 수칙에
맡기지 않습니다.

## 2. 관문별 전환 결과

| 행위 | 2인 체제 (유지, 2명부터 자동) | 1인 모드 (지금) |
|---|---|---|
| 동결 해제 | 다른 운영자 승인 | 생체 재확인 |
| 판정 이의 인정 | 다른 운영자 승인 | 생체 재확인 |
| 기계 판정 없는 수동 판정 | 다른 운영자 승인 | 생체 재확인 |
| 고액 지급 (500만원↑) | 다른 운영자 승인 | **관문 없음 — 지시서 화면 색 강조**만 |

고액 지급만 재확인조차 안 건 이유: 이 관문의 취지는 "큰돈은 주의해서 보자"였고(설계
주체 확인), 승인자가 없는 체제에서 그 취지는 **금액 색 강조**(문턱 절반 주의색, 문턱
이상 경고색 + "실행 전 한 번 더 확인" 문구)가 잇습니다. 일일 출금 한도(1,000만원)·
48시간 정산 쿨다운·계좌 검증·동결은 전부 그대로 삽니다.

승인 인프라(대기열 화면·72시간 만료·48시간 재알림·승인 건강도 지표)는 **제거하지 않고
휴면**시켰습니다 — 1인 모드에서는 승인서가 아예 생기지 않아 저절로 조용하고, 건강도
지표는 "운영자 1명 — 해당 없음"으로 표시됩니다. 2명이 되면 손대지 않아도 전부 즉시
살아납니다.

## 3. 함께 확정된 구조 — 관리자는 계정이 아니라 신원이다

창업자의 CI 해시를 환경 변수에 고정해, **그 사람의 본인 인증(풀 로그인)이 곧 관리자
승격**입니다. DB 초기화·앱 재설치 뒤에도 풀 로그인 한 번이면 관리자 화면이 돌아옵니다.
로그인하면(세 경로 모두) 이용자 홈이 아니라 **운영 대시보드**가 첫 화면입니다 —
큐마다 대기 건수가 붙어 "사람을 기다리는 일"이 먼저 보입니다.

## 4. 질문

### 질문 1 (최우선) — 신원 기반 관리자 + 유심 스와핑 = 관리자 탈취입니까

관리자 승격이 본인 인증(CI)에 걸려 있으므로, **유심을 가로챈 공격자는 풀 로그인으로
관리자 대시보드까지 들어옵니다.** 제가 그린 방어 사슬은 이렇습니다:

```
유심 스와핑 → 풀 로그인 성공 → 관리자 화면 진입 (여기까지 뚫림)
  → 돈에 닿는 실행(동결 해제·이의 인정·수동 판정)은 생체 재확인 요구
  → 공격자 기기에는 창업자 계정의 패스키가 없다 → 등록하려면?
  → 패스키가 이미 있는 계정에 본인 인증 경로로 들어왔으므로 48시간 기기 등록 유예
    + 창업자에게 "다른 경로 로그인" 알림
  → 창업자가 48시간 안에 알아채고 유심을 되찾으면 돈은 한 푼도 안 나갔다
```

이 사슬이 성립하려면 **창업자 계정에 패스키가 반드시 등록돼 있어야** 합니다(없으면
유예가 안 걸립니다 — 첫 기기 등록을 막을 수 없어서). 지금은 그것이 운영 수칙이지
코드 강제가 아닙니다. **"관리자 계정은 패스키 없이는 관리자 화면을 못 연다"를 코드로
강제해야 합니까?** 강제하면 첫 설정 전의 창업자가 스스로 잠기는 부트스트랩 문제가
생기는데, 그 해법(첫 로그인 시 패스키 등록을 필수 절차로)까지 포함해 답해 주십시오.

### 질문 2 — 고액 지급의 "주의"가 강제력이 없습니다

색 강조는 읽지 않으면 그만입니다. 남은 강제 장치는 일일 한도(1,000만원)뿐인데, 이건
하루 단위라 **문턱(500만) 지급 두 건이면 그날 한도가 끝**입니다 — 즉 최악의 하루 유출이
한도만큼입니다. 저는 이것이 1인 체제에서 수용 가능한 크기라고 봤습니다(카드 가격
5천~5만원 구조상 단일 정산이 문턱을 넘는 것 자체가 이례라, 실측상 발동 0회 예상).
고액 지급에도 생체 재확인을 걸면 비용이 지문 1초뿐인데, **안 건 것이 맞습니까** —
아니면 색 강조 위에 재확인 하나를 더 얹는 쪽이 맞습니까?

### 질문 3 — 생체 재확인의 남는 우회로

재확인이 못 막는 것을 제가 아는 대로 적습니다: ① **강요**(물리적 협박으로 본인이
지문을 대게 함 — 어떤 앱 관문도 못 막음) ② **원격 화면 조작**(원격제어 앱을 깔게
하는 사기 — 생체 창은 원격으로 못 누르지만, 피해자에게 "지문 대세요"라고 시키면
됨). ②는 계좌 유예 해제 화면에 넣은 것과 같은 **사기 경고 문구**가 유일한 방어라고
보는데, 운영자 재확인 창 앞에도 같은 경고를 넣어야 합니까? 아니면 운영자는 본인이
설계를 아는 사람이라(창업자) 그 문구가 소음입니까?
