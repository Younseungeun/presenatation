# INTOVILL 인증 축 2차 — A·B를 넣었습니다. **닫기 전에 세 가지만 확인받고 싶습니다**

성과 검증형 리서치 마켓플레이스입니다. 리서처가 예측 카드를 걸고 리포트를 팔면 시한에
시장 데이터가 자동 판정하고, 적중이면 정산·실패면 구매자에게 현금 환불됩니다.

1차 답변의 **A(최근성 요구)·B(경로별 권한)·C(CI 유지)를 전부 채택해 구현**했습니다.
"두 로직만 추가하면 인증 축도 닫아도 좋다"고 하셨는데, **넣고 보니 새로 생긴 자리가
셋** 있어 그것만 확인받고 닫으려 합니다.

---

## 1. 넣은 것

### A. 최근성 요구 — 기기 등록은 방금 인증한 세션만

세션 토큰이 이제 **"누구인가"에 더해 "어떻게 들어왔는가"와 "언제 인증했는가"**를 담습니다.
서명에 함께 들어가므로 경로를 위조하면 토큰이 통째로 거부됩니다.

```
본인 인증 로그인 → { method: IDENTITY, verifiedAt: now }
패스키 로그인    → { method: PASSKEY,  verifiedAt: 0    }   ← 인증을 안 거쳤으므로
```

`verifiedAt: 0`의 뜻이 중요합니다 — **패스키로 들어온 세션은 기기 등록 관문에서 항상
재인증을 요구받습니다.** 열쇠로 들어와 열쇠를 또 심는 길을 열어 두면 훔친 기기 하나가
계정을 영구히 장악하기 때문입니다.

말씀대로 **첫 등록도 예외로 두지 않았습니다.** 가입 직후는 방금 인증했으므로 예외 없이도
자연히 통과합니다 — 예외를 안 두고도 UX가 매끄러워지는 것을 확인했습니다.

**옛 형식 세션은 "인증한 적 없음"으로 읽습니다.** 배포 순간에 살아 있던 세션들이 관문을
그냥 통과하지 않게, 안전한 쪽으로 틀리는 선택입니다.

### B. 경로별 권한 — 위험한 경로로 들어왔으면 열쇠를 못 심는다

```
패스키가 있는 계정  +  본인 인증으로 로그인
      → 로그인은 허용
      → 48시간 동안 새 기기 등록 차단
      → 본인에게 "다른 경로로 로그인됨" 알림
```

**패스키가 하나도 없으면 걸지 않습니다.** 걸어 버리면 아무도 첫 기기를 등록하지 못합니다.

**삭제는 막지 않습니다.** 그쪽은 권한을 *내려놓는* 행위라, 막으면 기기를 잃은 사람이
도둑이 쥔 열쇠를 뽑지 못하게 됩니다.

### 계좌 변경에는 B를 걸지 않았습니다 — 한 걸음 뺐습니다

1차에서 제가 "계좌 변경·패스키 등록에 쿨다운"이라고 적었는데, 넣으려다 **계좌 변경 쪽은
이미 같은 보호를 받고 있다**는 것을 발견했습니다:

```
계좌를 바꾸면 → 48시간 뒤부터 돈이 나간다 (기존 쿨다운)
```

공격자가 계좌를 바꿔도 48시간 동안 돈이 안 움직이고 그 사이 알림이 갑니다. **B를 또
걸면 같은 48시간을 두 번 세는 것**이고, 정상 사용자만 두 배로 기다립니다.

반면 **기기 등록에는 뒤를 받쳐 줄 것이 없습니다** — 심는 순간 곧바로 쓸 수 있어서요.
그래서 B는 거기에만 걸었습니다. 이 판단이 맞습니까?

## 2. 확인받고 싶은 것 셋

### 질문 1 — 재인증 창(10분)이 **다른 관문의 우회로**가 되지 않습니까

지금 구조가 이렇습니다:

```
본인 인증 통과 → 10분 동안 "최근성" 만족 → 그 사이에는 기기 등록이 열린다
```

그런데 유심을 가로챈 공격자는 **본인 인증을 통과할 수 있습니다.** 그러면:

- 패스키가 **있는** 계정 → B가 막습니다 (48시간) ✅
- 패스키가 **없는** 계정 → **A도 B도 안 막습니다** ← 여기

즉 패스키를 한 번도 등록하지 않은 리서처는 유심 탈취에 **그대로 노출**됩니다. 공격자가
첫 패스키를 심고, 그때부터는 정당한 기기가 됩니다.

제 처방은 **"첫 기기 등록도 알린다 + 그때부터 48시간은 계좌 변경을 막는다"**입니다.
지금은 첫 등록에 알림을 보내지 않고 있는데(본인이 방금 한 일이라고 봐서), 위 경로를
생각하면 **첫 등록이야말로 알려야 하는 사건** 같습니다. 맞습니까?

### 질문 2 — 세션 수명 30일이 이 설계와 맞습니까

세션 쿠키가 **30일**입니다. 패스키가 붙기 전에는 "매번 본인 인증시킬 수 없으니 길게"가
근거였는데, **이제 지문 한 번이면 다시 들어옵니다.**

```
지금:   세션 30일 — 훔친 세션이 한 달 동안 유효
바꾸면: 세션 짧게(1~7일?) + 만료되면 지문으로 즉시 재로그인
```

세션 탈취의 피해 창을 줄이는 값싼 방법으로 보이는데, **패스키가 없는 사용자에게는
"한 달에 한 번이 아니라 주마다 본인 인증"**이 되어 비용과 마찰이 붙습니다.

패스키 유무에 따라 세션 수명을 다르게 주는 것(패스키 있으면 짧게, 없으면 길게)이
합리적입니까, 아니면 그런 분기가 또 다른 예외를 만드는 것입니까?

### 질문 3 — 운영자 계정에도 같은 규칙을 적용해야 합니까

지금 관문은 **리서처 기준**으로 설계됐습니다. 그런데 운영자는 권한이 더 큽니다 —
**정산 동결을 푸는 유일한 사람**이고, 판정을 되돌리고, 지급을 실행합니다.

운영자 계정이 탈취되면 지금까지 만든 방어가 대부분 무의미해집니다(동결을 풀고 지급을
실행하면 됩니다). 그런데 운영자에게는 **아무 추가 관문도 없습니다.**

제 처방은 **"운영자는 패스키 필수 + 돈이 나가는 실행에는 최근성 요구"**입니다.
운영자는 소수라 마찰을 감당할 수 있고, 기기를 잃어도 다른 운영자가 도울 수 있습니다.
과합니까, 아니면 오히려 더 강하게(2인 승인 등) 가야 합니까?
