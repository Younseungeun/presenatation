# 등급 임계값 — 점수 v5 재캘리브레이션 (2026-08-13)

> 실행: `npx tsx scripts/simSkillSeparation.ts` (n=12,000 × 시즌 20장)
> 구현: `domain/tiers.ts DEFAULT_TIER_THRESHOLDS` · 등급 사다리는 CLAUDE.md §3.1
>
> 이 문서의 2026-07-13판(실버 600 / 골드 2,000 / 플래티넘 5,000)과 그 근거였던
> `scripts/simulateTierThresholds.ts`는 폐기됐다. 그 사이 점수 모델이 두 번
> 바뀌어(v3 → v4 → v5) 같은 숫자가 전혀 다른 뜻이 됐기 때문이다.

## 임계값이 조절하는 것은 마진이 아니라 공급·신호다

선결제 할증 때문에 등급별 실효 수수료 격차는 명목 격차보다 작다. 그래서 임계값이
움직이는 것은 플랫폼 마진이 아니라

① **리서처 유지** — 승급이 너무 멀면 콜드스타트 단계에서 공급이 이탈한다
② **등급의 신호 가치** — 너무 가까우면 전원 상위 등급이 되어 구매자 변별력이 사라진다

이 전제는 v3 때와 같고, 바뀐 것은 점수의 눈금뿐이다. 그래서 **목표 피라미드
(상위 50 / 25 / 10%)를 고정하고 새 점수 분포의 50·75·90분위로 다시 잡았다.**

## 채택

| 등급 | 임계값 | 목표 비율 | 실측 도달률 |
|---|---|---|---|
| 시니어 | **1,330** | 상위 50% | 준수형 48% |
| 마스터 | **2,770** | 상위 25% | 우수형 78% |
| 펠로우 | **5,250** | 상위 10% | 정밀형 98% |
| 인투빌 펠로우 | 상대평가 | ~1% | 심사 |

모집단 가정: 정밀 5% / 우수 25% / 준수 50% / 하위 15% / 스팸 5%.
실력 = 일 드리프트 k·σ (0.5 / 0.35 / 0.2 / 0.08 / 0), 행동 = 각자 EV 최적 —
v5는 적정 점수법이라 이것이 곧 "정직하게 신고한다"와 같은 뜻이다.

## 피라미드 모양은 자리를 맞게 앉히는지 말해주지 않는다

그래서 분리력을 함께 쟀다:

| 지표 | v4 | **v5** |
|---|---|---|
| AUC 하위 < 준수 | 0.785 | **0.940** |
| AUC 스팸 < 준수 | 0.819 | **0.961** |
| AUC 준수 < 우수 | — | 0.936 |
| AUC 우수 < 정밀 | — | 0.979 |
| 순위상관(실력↔점수) | 0.792 | **0.835** |
| 오분류 | — | **0%** |

**오분류 0%** — 스팸이 시니어에 오르지도, 정밀이 시니어에 못 오르지도 않는다.

결정적인 것은 꼬리다:

| | v4 | **v5** |
|---|---|---|
| 준수형 하위 5% | −3,354 | **+177** |
| 스팸 상위 5% | −189 | **−30** |

v4에서는 성실한 리서처의 하위 5%가 스팸보다 3,165점 아래였다 — "점수가 낮다"가
"실력이 없다"를 뜻하지 못했다. v5에서는 두 분포가 겹치지 않는다.

## v4 대비 시즌 장수 민감도가 낮아졌다

v4의 알려진 약점은 시즌 카드 수에 대한 민감도였다(12장이면 마스터 12.8%,
30장이면 펠로우 23.9%). v5는 **카드당 점수가 유계**라 누적 분산이 훨씬 작고,
그만큼 이 민감도가 완화됐다. 그래도 운영 데이터로 재조정하는 것은 전제다.
