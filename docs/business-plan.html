독립 리서처가 주식·기업 분석 리포트를 판매하고, 그 안의 예측이 시장 데이터로 자동 판정되어 정산과 평판이 갱신된다. 틀리면 구매자는 현금으로 환불받는다. 평판은 팔로워 수가 아니라 판정된 트랙레코드로만 쌓인다.

01한 장 요약

이 사업이 파는 것은 리포트가 아니라 검증된 판단이다.

핵심 차별화3무위험 진입 · 조작 불가 평판 · 정직한 신호
수수료20→10%등급이 오를수록 내려간다
구현 시험1,666149개 파일 전부 통과
출시 전 과제비코드계약 · 법률 · 배포

세 문장

  1. 구매자는 무위험으로 들어온다. 신규 리서처 리포트는 100% 성과 연동 — 예측이 틀리면 대금 전액이 현금으로 돌아간다.
  2. 평판은 조작할 수 없다. 모든 유료 리포트에 자동 채점 가능한 예측 카드가 붙고, 시한이 오면 시장 데이터가 판정한다. 사람이 개입하지 않는다.
  3. 리서처의 확신이 조건에 드러난다. 선결제 비율을 높이면 수수료가 올라간다 — 자신 있는 사람만 지는 비용이라, 그 숫자 자체가 신호다.
이 설계의 중심

이 서비스에서 사람이 판정에 손대는 자리가 없다. 판정은 시한과 시장 데이터가 정하고, 운영자는 게시 전 검수와 돈의 집행만 한다. 그래서 "우리가 봐줬다"는 의심이 구조적으로 성립하지 않는다.

02문제와 해법

투자 콘텐츠 시장의 공통 약점은 하나다 — 사기 전에 실력을 확인할 방법이 없다.

지금 시장이 파는 신뢰의 근거

플랫폼구매자가 볼 수 있는 것빠진 것
오렌지보드고수의계좌 · 리포트 이력예측의 사후 자동 판정
네이버 프리미엄콘텐츠구독자 수 · 미리보기성과 추적 자체가 없음
Seeking Alpha기고자 성과 추적구매 전 무위험 진입 없음
Substack · Smartkarma팔로워 수 · 기관 평판개별 예측의 검증

전부 팔로워 수가 실력의 대리 지표다. 팔로워는 먼저 시작한 사람에게 유리하고, 틀려도 줄지 않는다. 그래서 실력 있는 신규 진입자가 뚫고 들어갈 길이 없다.

해법 — 결과를 기계가 채점한다

모든 유료 리포트에 예측 카드를 필수로 붙인다. 종목·방향·크기·기간·신뢰도 다섯 값이 들어가면, 시한이 왔을 때 시세 데이터만으로 적중·실패가 갈린다. 이 판정이 세 가지를 동시에 만든다.

  • 정산 — 적중이면 리서처에게, 실패면 구매자에게 현금이 간다
  • 평판 — 그 결과가 점수가 되고 점수가 등급이 된다
  • 데이터 — 예측과 결과의 쌍이 쌓인다 (3단계 사업의 자산)

03검증 시스템

예측 카드 · 자동 판정 · 마스킹 — 세 장치가 맞물려 조작 가능성을 닫는다.

예측 카드 (필수)

입력내용왜 이 형태인가
종목종목 마스터에서 검색·선택자유 입력을 막아 자동 판정 가능성을 구조적으로 보장. 상폐 종목은 신규 게시 차단
방향상승 / 하락하락은 실제 숏 수단이 있는 종목만 — 맞아도 수익화 못 하면 상품이 아니다
크기% 또는 목표가하한 = 1.2 × σ × √기간. 종목 변동성에 연동해 "방향만 맞히기"를 막는다
기간검증 시한코인 최소 1일 · 주식 최소 14일 · 상한 365일
신뢰도2 ~ 10 (등비 사다리)한 칸 = 승산 ×1.73, 꼭대기 ×140. 이것이 곧 확률 신고다

구매 전에는 가린다

종목·목표가·제목·요약을 서버에서 아예 내려보내지 않는다(화면에서 가리는 방식이 아니다). 구매 전 공개 범위는 리서처 신원·자산군·방향·확신 3종·시한·가격·환불 조건까지다. 제목을 가리는 이유는 자유 입력이라 "비트코인 4분기 전망" 한 줄로 나머지 마스킹이 통째로 무력화되기 때문이다.

자동 판정 — 규칙은 하나다

검증 시한 안에 목표가에 닿은 일봉 종가가 있는가?

  있다  →  적중.  판정가 = 목표가      (초과분은 반영하지 않는다)
  없다  →  실패.  판정가 = 시한 종가   (극값으로 재면 잠깐 스친 카드가 이득)

  · 종가만 본다  장중 꼬리로 적중이 만들어지면 시세 조작 통로가 열린다
  · 목표 도달일에 판정  예측이 이뤄진 날 판정하는 것이지 "조기 판정"이 아니다
  · 판정 불가  거래정지·상장폐지 → 전액 환불 · 수수료 0 · 점수 0

판정을 지키는 장치

  • 앵커 방식 권리 사건 대응 — 게시 시점 종가를 적어 두고, 같은 날짜를 다시 조회해 배수가 달라지면 그게 액면분할이다. 임계값 추측이 필요 없다
  • 교차 검증 — 두 번째 시세 소스와 값이 아니라 결론을 대조한다. 목표선 근처에서만 갈리고, 거기가 정확히 사람이 봐야 하는 자리다
  • 불가능한 일봉 차단 — 국내 30%(가격제한폭) 초과는 막되, 거래량이 평소의 5배 이상이면 통과시킨다. 자릿수 오류는 가격만 튀고 진짜 사건은 거래량이 함께 터진다
  • 수동 큐에도 상한 — 사람이 안 보면 영영 안 닫히던 구멍을 막았다. 시한 후 14일이면 전액 환불로 닫는다

04점수 산정 모델

이름은 인투빌 점수 산정 모델 vmax. 카드를 확률 예보로 보고, 그 신고가 무정보보다 얼마나 위였는지를 잰다.

적중   +S · w · ln( p̂ / p₀ )
실패   +S · w · ln( (1−p̂) / (1−p₀) )

  S  = 100          눈금
  w  = 1.0 ~ 2.0    수익성 가중 (크기에 연속)
  p̂  = 신고 확률     신뢰도가 함의하는 값
  p₀ = 무정보 도달 확률  방향·크기·기간·그 종목의 σ로 계산

이 공식이 지키는 성질

성질뜻
적정(proper)기대값이 정직하게 신고할 때 최대. 부풀리면 손해라 거짓말할 유인이 없다
무실력자 기대값 ≤ 0확신을 신고하는 순간 음수. "은신처"를 따로 막을 장치가 필요 없다
실력자 기대값 = +D(p‖p₀)그 사람이 시장에 더한 정보량 그 자체
카드당 유계한 장으로 잃을 수 있는 점수에 한계가 있다 — 야심 있는 예측을 벌하지 않는다

정보량이 음수로 쌓이면 신뢰도 상한을 내린다. 문턱을 고르지 않는다 — 점수가 로그우도비라 Ville 부등식이 그대로 적용되어, 각 단이 "정직한 사람을 잘못 잡을 확률"을 이름으로 달고 있다.

05검수 파이프라인

게시 전에 위법·위험 표현을 거른다. 두 단계고, 앞은 기계 뒤는 사람이다.

자동 검수 ─┬─ 규칙 엔진 (정규식 · 학습 표현)   ← 즉시 거절은 여기만
              └─ IRIS (자체 증류 분류기)        ← 언제나 WARN
                     │
운영자 판정 ────┴─ 승인 / 반려
절대 조건

즉시 거절 권한은 결정적 규칙에만 있다. 모델은 재현 불가능한 판정을 낸다 — 같은 글을 다시 넣으면 다른 답이 나올 수 있는 것에 사람의 생계를 끊는 권한을 주지 않는다. 모델이 BLOCK을 내도 처리는 보류고, 보류는 판매가 시작되지 않아 규제 노출이 0이면서 승인으로 되살아난다.

IRIS — 자체 증류 모델

KoELECTRA-small 14M을 증류해 만든 분류기. 로컬 사이드카로 돌고 외부 AI API 호출이 운영 경로에 0회다. 규칙이 못 잡는 패러프레이즈(같은 뜻 다른 말)를 메운다 — 규칙의 탐지율이 0%인 유일한 칸이고, IRIS 단독 66.7%가 그대로 순증이다.

Claude는 교사로만 쓴다. 운영자가 질문지를 복사해 붙여 넣고 답을 기록하면 그것이 재학습 라벨이 된다. 자동 호출 경로는 코드가 막는다 — API 키를 넣어도 게시 검수에서는 돌지 않는다.

06등급과 수수료

등급마다 새로 열리는 것이 하나씩. 등급은 전적으로 누적 점수로 정해진다 — 건수·적중률은 표시 지표일 뿐 승급 조건이 아니다.

신규 20%의 근거는 에스크로 + 자동 판정 + 평판 인프라다. 단순 유통이 아니라 판정과 정산을 대행한다. 초기 입점 프로모션으로 첫 6개월은 10%.

2단계 — 구독

펠로우 이상에게 구독 상품 개설을 해금한다. 성과 연동 없이 일반 정산이라 안정 매출로 전환된다. 상위 10%만 열리므로 구독 자체가 등급 신호가 된다.

3단계 — 데이터

예측–결과 쌍이 쌓이면 그것 자체가 상품이 된다. 리서처 컨센서스 지수, 기관 대상 API. 이 데이터는 다른 곳에서 살 수 없다 — 예측이 사전에 봉인되고 사후에 기계로 판정된 기록이라, 사후 편향이 구조적으로 들어갈 수 없기 때문이다.

앱스토어 대응

디지털 콘텐츠를 인앱결제로 팔면 애플·구글이 15~30%를 떼간다. 우리 수수료가 20%라 그러면 남는 게 6%도 안 된다. 그래서 결제는 웹, 소비는 앱 구조다 — 국내 콘텐츠 플랫폼의 통상 구조이나, 앱 심사 규정과 얽혀 있어 법률 확인 대상이다.

08운영 체계

1인 운영을 전제로 설계했다. 사람이 빠져도 돈이 잘못 나가지 않는 것이 기준이다.

정산 흐름

구매자 결제(PG) → 에스크로 보관 → 검증 시한 → 시장 데이터 자동 판정
                                                    │
        ┌───────────────────────────────────────────┼───────────────────────┐
     적중                                        실패                    판정 불가
   리서처에게                              성과분 → 구매자 환불          전액 환불
  (판매액 − 수수료)                        선결제분 → 리서처            수수료 0

환불은 전부 현금이다. 크레딧을 쓰지 않는 이유는 선불전자지급수단 규제 이슈를 원천 제거하기 위해서다. PG 취소가 원칙이고, 취소 기한(통상 1년)을 넘긴 건은 계좌이체로 폴백한다 — 검증 시한이 최대 365일이라 실제로 발생 가능한 경로다.

돈을 지키는 관문

장치막는 것

인증 — 두 겹

  • 풀 로그인 — 본인 인증. 가입·재설치·로그아웃 후에만. CI 해시로 1인 1계정을 강제하고 실명을 암호화 저장한다
  • 간편 로그인 — 생체(패스키) 또는 6자리 비밀번호. 둘 다 기기에 묶인다 — 비밀번호가 유출돼도 다른 기기에서는 못 쓴다. 새 기기는 무조건 풀 로그인이고, 그것이 탈취자를 막는 뼈대다

스스로를 감시하는 장치

운영자가 한 명이면 조용한 실패가 가장 위험하다. 그래서 검수가 실제로 도는지를 재는 장치를 따로 뒀다.

  • 규칙 카나리아 — 정답이 정해진 문항을 운영과 같은 함수에 5분마다 통과시킨다. 층마다 한 칸씩이라 한 층만 죽어도 잡힌다
  • IRIS 출근 점검 — 아무도 리포트를 안 올려도 5분마다 확인한다. 리포트가 없으면 IRIS가 죽어도 알림이 안 나가던 구멍을 막았다
  • 운영자 습관화 감지 — 판정 소요 시간이 특정 유형만 유독 짧으면 그 소견은 읽히지 않고 승인되고 있다는 뜻이다
이 장치들이 존재하는 이유

2026-08-20에 표기 회피 탐지가 통째로 꺼진 채로 돌았다. 차단율 92%로 측정된 기능이 운영에서는 0%였고, 예외도 경고도 없었으며 시험 820건이 전부 초록이었다. 관문이 없는 것은 오류가 아니라 침묵이다 — 그래서 사람이 기억하는 대신 기계가 확인한다.

09시장과 경쟁

참여자

타깃 공급자 — 전직 애널리스트, 펀드매니저 출신, 회계사, 산업 전문가, 개인 리서처. 현직 증권사 애널리스트는 소속사 겸직 금지로 사실상 불가하다(플랫폼이 막을 필요는 없다).

방어벽

기능은 복제 가능하다. 복제 불가능한 것은 축적된 트랙레코드다. 리서처 입장에서 다른 플랫폼으로 옮기면 판정된 예측 기록이 0에서 시작한다 — 그것이 이적 비용이고, 시간이 갈수록 두꺼워지는 유일한 자산이다.

10로드맵

1단계 (0~12개월) — 공급 확보와 판정 신뢰

목표는 사용자 수가 아니라 검증된 리서처 30~50명이다. 경력자를 직접 영입하고 수수료를 면제한다. 이 시기 수익은 후순위고, 가장 중요한 산출물은 판정 무분쟁 기록이다.

2단계 (12~24개월) — 평판 데이터 자산화

적중률 리더보드를 마케팅 콘텐츠로 쓴다("이번 분기 최고 적중 리서처"). 구독 상품을 열어 안정 매출로 전환한다.

3단계 (24개월~) — 데이터 사업

예측–결과 데이터의 2차 상품화. 리서처 컨센서스 지수, 기관 대상 API.

코드 품질 관측

  • TODO·FIXME 0건 — 미룬 것을 주석으로 남기지 않고 문서나 시험으로 옮겼다
  • 숫자 상수 근거 래칫 — 내보내는 숫자 상수에 @근거를 요구한다. 근거를 못 대면 constants-debt.txt에 이름을 올려야 하고, 그 파일의 줄 수가 곧 남은 빚이다(현재 66줄). 목록에 없는 무태그 상수는 시험이 막는다
  • 규약을 시험이 강제한다 — 관리자 화면 인증 관문, DB 시험의 파일 이름 갈래, 상수 근거. 셋 다 사람의 기억으로는 안 지켜져서 시험으로 옮겼다

12리스크

1. 콜드스타트 이중고

리서처는 무보수 위험을 지고 들어와야 하고, 평판은 판정 시한만큼 기다려야 쌓인다. 두 지연이 겹친다.

대응 — 첫 6개월 수수료 10%, 경력자 직접 영입, 시니어 승급선을 상위 50%로 넓게 잡아 첫 시즌 승급 경험을 만든다.

2. 대기업 모방

기능은 복제된다. 다만 트랙레코드는 복제되지 않는다 — 뒤늦게 시작하면 그 시점부터 쌓아야 한다.

3. 규제

유사투자자문업 신고 의무, 그리고 정산 구조가 전자금융거래법 PG 영역인지가 최대 변수다.

가장 큰 단일 리스크

"플랫폼이 구매자 돈을 받아 판매자에게 나눠주는 것"은 현행법상 PG 등록 대상으로 해석될 여지가 있고, PG 등록은 자본금 요건상 1인 창업이 불가능하다. 개정 전금법(2026-12-17 시행)이 "다른 업무를 영위하는 과정에서 부수적으로 정산을 대행하는 경우"를 제외하며 이커머스 중개 플랫폼을 예시로 든다 — 인투빌은 면제 쪽에 설 여지가 크다.

대응 결정 — 2026-12-17 이후 출시로 정해 현행법 위반 구간을 통째로 피한다. 다만 "부수적"의 수치 기준이 시행령에도 없어 변호사 서면 의견이 필요하다.

알려진 기술적 약점 — 고치지 않고 출시한다

13출시 전 과제

코드가 아니라 계약 · 법률 · 배포다. 이것들이 붙기 전까지 인증·정산 관문은 형태만 완성이다.

계약

  • 본인 인증 실공급자 (통신사/PG)
  • 은행 예금주 조회 — 계좌 실명 대조의 실물
  • 토스페이먼츠 라이브 키 (가맹점 심사)
  • PG 수수료 환급 여부를 계약 때 확인 — 실패 판정마다 전액 환불하는데 이미 낸 PG 수수료(약 3%)가 안 돌아오면 환불 건마다 순손실이다. 계약서에 사인한 뒤에는 못 바꾼다

법률 — 한 번에 물을 다섯 질문

  1. 유사투자자문업 경계 서면 의견서
  2. 앱 안에서 "웹에서 결제" 안내가 앱스토어 심사·전기통신사업법상 가능한가
  3. 인투빌 정산이 개정 전금법의 "부수적 정산 대행"에 해당하는가
  4. 시행 전 출시 시 지급대행이 필수인가
  5. 판정까지 대금을 보관하는 에스크로가 결제대금예치업 등록 대상인가

+ 상표 조사·가출원 (변리사). 가출원은 MVP 공개 전이어야 한다 — 공개 시 신규성을 잃는다.

돈 실무

  • 에스크로용 별도 은행 계좌 — 지금 "에스크로"는 장부상 상태값일 뿐 실제 계좌 분리가 아니다. 시한이 최대 365일이라 1년 가까이 묶인 남의 돈이 일반 계좌에 섞인다. 어느 규제 경로로 가든 계좌 분리는 항상 옳다
  • ⚠ 새 통장은 대개 이체 한도가 하루 30만원이라 정산 이체가 안 된다. 창구에서 금융거래목적 증빙을 내고 그 자리에서 한도 해제까지 끝낼 것

배포

  • 바깥 감시자 — 이 목록에서 제일 중요하다. 지금 알림은 전부 우리 서버 안에서 나가므로 서버가 죽으면 알림도 같이 죽는다. 외부 핑 서비스가 신호를 못 받으면 그쪽이 연락하게 한다. 코드가 아니라 계정 하나 + URL 하나
  • 스케줄러 자동 재시작 (pm2 / systemd) — 단순 사망만 복구하고 좀비는 못 잡는다
  • 환경 변수 이관 (텔레그램 · 파이어베이스 · 창업자 CI 해시)
  • 홈 우측 상단 "관리자 →" 임시 버튼 제거

앱스토어

계획은 앱스토어 앱이고 "결제는 웹, 소비는 앱"이 그 전제다. 다만 지금은 네이티브 프로젝트가 없다 — Next.js + PWA 매니페스트뿐이다. 화면 재작성은 불필요하고 감싸는 작업이 필요하다.
