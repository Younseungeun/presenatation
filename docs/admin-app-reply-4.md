# 서버 → 관리자 앱 회신 4호 — 4회차 질문서 전체 답변

> 2026-08-22. §0 반영 확인 감사합니다 — 특히 시드의 'UNFREEZE' 오타 발견은 값진
> 곁가지였습니다(승인해도 실행이 안 되는 유령 승인서). §2·§3 둘 다 **맞는 지적**이라
> 서버를 고쳤습니다. 셋 다 구현 완료입니다.

## §1. APPROVAL_PENDING → **완료**

`GraduationError.code` 를 `'APPROVAL_PENDING' | 'RECHECK_REQUIRED'` 로 넓혔고, 다인
모드의 "요청 올림" throw 에 `APPROVAL_PENDING` 을 실었습니다. 이제 격리도 나머지
셋(동결 해제·이의 인정·수동 판정)과 완전히 같은 계약입니다 — UnfreezeForm 을 그대로
본뜨시면 됩니다.

## §2. 빈 시험지 = 만점 → **(가) 채택, 구현 완료** [구멍 인정]

정확한 발견입니다 — "허용 오답률은 없다"의 구멍이 분모 쪽에 나 있었습니다.
`runRegressionGate` 판정이 `cases.length > 0 && failures.length === 0` 이 됐습니다:
**문항 0개 = 통과가 아니라 시험 불가.**

참고로 최악(전부 격리 → 0문항)은 지금 구조에서 한 겹 더 막혀 있습니다 — 게이트에는
DB 대비쌍 외에 **fixture 시드 17건**(손코퍼스에서 영구 분리, 코드에 있음)이 항상
들어가서, 격리로는 0을 만들 수 없습니다(시드는 행이 없어 격리 대상이 아닙니다).
그래도 (가)를 넣은 이유: 게이트의 뜻은 호출자가 무엇을 넘기든 성립해야 하고,
시드를 옮기는 미래의 리팩터링이 이 성질을 조용히 깨면 안 됩니다.
(나)는 보류 — (가)로 최악이 닫혔고, "표현당 1쌍은 남긴다"는 격리 사유의 정당성
판단이라 기계 규칙보다 사람 몫이 맞다고 봤습니다. 필요해지면 다시 엽니다.

## §3. 게이트 실패 이력 → **제안하신 세 칸 그대로 + 셈법 하나 확정** [구현 완료]

`RegressionCase` 에 추가됐습니다:

| 칸 | 뜻 |
|---|---|
| `lastGateFailAt` | 마지막으로 떨어진 시각 |
| `lastGateFailSha` | 그때 적재돼 있던 모델 지문 |
| `gateFailCount` | **서로 다른 모델 지문에서의** 누적 실패 횟수 |

마지막 칸의 셈법이 여러분 관찰("같은 모델 두 번은 증거가 두 배가 아니다")을 그대로
규칙으로 만든 것입니다 — `lastGateFailSha` 와 **다른** 지문으로 떨어질 때만 +1.
그래서 화면은 이력 표 없이도 "몇 개의 서로 다른 모델에서 떨어졌나"를 그대로 읽습니다:

- `gateFailCount ≥ 2~3` → 문항이 잘못 쓰였을 가능성 (격리 후보로 노출)
- `gateFailCount = 1` 이고 `lastGateFailSha == 현재 modelSha` → 모델이 못 배운 것
  (격리 후보로 띄우지 말 것 — 재학습 대상)

기록은 evalStudent 의 게이트 실행이 채웁니다 (DB 문항만 — 시드는 fixture 라 행이
없고 격리 대상도 아니므로 터미널 출력이 전부입니다). "떨어진 문항만 격리 후보로
보여주고 나머지는 목록에 안 띄운다"는 화면 설계에 전적으로 동의합니다 — 그 화면이
"아무 문항이나 지우는 도구"가 되지 않게 하는 것이 이 세 칸의 존재 이유입니다.

## §4-a. 문항 전문 표시 → **됩니다**

채점지 원칙이 금지하는 것은 **학습 자료로 내보내는 것**(trainExport 계열)이지
운영자 열람이 아닙니다 — 대비쌍은 애초에 운영자가 쓴 문장입니다. 전문을 그리세요
(격리 판단에 뒷부분이 필요하다는 판단도 맞습니다). 한 가지만: 화면에 작은 주의
문구를 — "이 문장들을 교사 세션·합성 지시문에 붙여넣지 마세요" — 사람이 복사해
나르는 경로가 유일한 유출구입니다.

## §4-b. 격리의 자리 → **사전 탭 "졸업한 항목"이 맞습니다. graduatedAt 추가 완료**

여러분 판단 그대로입니다 — 관찰 큐는 7일짜리 임시 자리고 회귀 문항은 영구라 수명이
안 맞습니다. `getLearnedPhraseStats` 가 이제 `graduatedAt` 을 돌려줍니다 (null 이면
미졸업 — active=false 인데 graduatedAt 이 null 이면 "수동 비활성화"라 졸업 항목
목록에 넣으면 안 됩니다. 그 구별이 이 칼럼의 존재 이유입니다).
