> v1.1: 자산 범위를 국내주식 + 해외주식(미국 우선) + 암호화폐로 확장.

## 1. 자산군(Asset Class) 모델

예측 카드와 판정 엔진은 자산군 공통으로 동작하고, 자산군별 차이는
**시세 소스·거래일 규칙·티커 표기**의 세 가지로 격리한다.

| 자산군 | 코드 | 티커 표기 | 통화 | 거래일 기준 시간대 | 특성 |
|---|---|---|---|---|---|
| 국내주식 | `KR_EQUITY` | 6자리 단축코드 (예: `005930`) | KRW | Asia/Seoul | 거래정지·상폐 있음 |
| 해외주식(미국) | `US_EQUITY` | 심볼 (예: `AAPL`) | USD | America/New_York | 거래정지·상폐 있음, 서머타임 |
| 암호화폐 | `CRYPTO` | 업비트 마켓코드 (예: `KRW-BTC`) | KRW | Asia/Seoul (업비트 일봉 기준) | 24/7 거래, 휴장 없음, 거래소 상폐 있음 |

- **판정은 항상 해당 자산의 표시 통화 기준** — 목표가·기준가·판정가가 같은 통화이므로 환율 개입 없음
- **거래일 날짜는 자산군의 시간대로 환산** — 예: 미국주식 시한이 KST 새벽이면 ET 기준 전일 장 데이터로 판정
- 암호화폐는 24/7 거래라 "휴장일 직전 종가" 규칙이 사실상 발동하지 않음. 일봉 마감은
  업비트 KST 자정 기준으로 약관에 명시 (국내 사용자 기준 직관성 우선)
- 유럽·아시아 주식 등 추가 자산군은 이 표에 행을 더하는 방식으로 확장

## 2. 판정 엔진이 요구하는 데이터

`src/domain/judgment.ts`의 `judge()`는 순수 함수이며, 입력 `MarketSnapshot` 하나로 판정한다.
데이터 레이어의 책임은 **이 스냅샷을 자산군별로 정확하게 만들어내는 것**이 전부다.

| 필드 | 용도 | 원천 데이터 |
|---|---|---|
| `highSincePublish` | 상승 목표가 도달 판정 | 게시일~시한 일봉 고가의 최댓값 |
| `lowSincePublish` | 하락 목표가 도달 판정 | 게시일~시한 일봉 저가의 최솟값 |
| `priceAtDeadline` | 수익률형(RETURN_PCT) 판정 | 시한 당일(휴장 시 직전 거래일) 종가 |
| `status` | 판정 불가 처리 | 거래정지·상장폐지(거래소 상폐) 여부 |

추가 요구사항:
- **일봉 데이터로 충분** — 판정은 시한 도래 후 배치로 실행되므로 실시간 불필요
- **감사 가능성** — 판정에 사용한 원천 데이터를 스냅샷으로 저장해 분쟁 시 재현
  (`Judgment.marketSnapshotJson`)
- 액면분할·감자 등 기업행위 발생 종목은 판정 불가(AMBIGUOUS) 처리 후 수동 검토 (MVP 단순화)

## 3. 자산군별 데이터 소스

### 국내주식 (KR_EQUITY)

| 후보 | 비용 | 갱신 | 인증 | 비고 |
|---|---|---|---|---|
| **공공데이터포털 금융위 주식시세정보** ✅ 주 소스 | 무료 | 일 1회, D+1 영업일 13시 이후 | API 키 | 약관·상업 이용 조건 확인 필요 |
| KIS Developers | 무료 | 실시간 | 증권사 계좌 + APP Key | 2단계: 게시 시점 기준가 확정, 교차 검증 |
| 코스콤 오픈API | 유료 | 실시간 | 계약 | 시세 재표시·데이터 상품화 단계 |

### 해외주식 (US_EQUITY)

| 후보 | 비용 | 갱신 | 인증 | 비고 |
|---|---|---|---|---|
| **Twelve Data** ✅ 주 소스 | 무료 티어 800콜/일, 8콜/분 | EOD 무지연, 실시간은 지연 | API 키 | 주식+크립토 단일 API. 판정용 EOD에 충분 |
| Alpha Vantage | 무료 티어 25콜/일 | EOD | API 키 | 무료 한도 너무 작음 |
| Polygon.io | 유료(개인 무료는 EOD 5콜/분) | 실시간 | API 키 | 스케일 단계 유력 (정식 라이선스) |
| KIS 해외주식 시세 | 무료 | 실시간 | 증권사 계좌 | 2단계 교차 검증 |

- Twelve Data 무료 티어는 초기 판정량(일 수백 건 이하)에 충분. 초과 시 유료 전환($29/월~)
- 미국 외 시장(유럽·일본 등)도 Twelve Data가 커버하므로 자산군 추가 시 재사용

### 암호화폐 (CRYPTO)

| 후보 | 비용 | 갱신 | 인증 | 비고 |
|---|---|---|---|---|
| **업비트 공개 API** ✅ 주 소스 | 무료 | 실시간 (일봉 즉시) | 불필요 (공개 시세) | KRW 마켓, 국내 사용자 기준가와 일치 |
| 바이낸스 공개 API | 무료 | 실시간 | 불필요 | USDT 마켓 — 업비트 미상장 코인 보조 |
| CoinGecko | 무료 티어 | 집계가 | API 키 | 집계가는 판정 기준으로 부적합 (거래소가 우선) |

- **판정 기준가는 단일 거래소(업비트) 가격으로 고정** — 집계가·타거래소가와 섞으면
  분쟁 소지. 약관에 "업비트 KRW 마켓 일봉 기준" 명시
- 업비트 상장폐지(거래지원 종료) 공지는 별도 배치로 수집 → `DELISTED` 처리
- 김치프리미엄으로 글로벌 시세와 괴리 가능 — 기준 거래소 고정으로 해결되는 문제이며
  리포트에 기준 거래소 표기

## 4. 판정 배치 흐름

```
자산군별 배치 스케줄 (모두 KST):
- KR_EQUITY: 매 영업일 13:30 (금융위 D+1 데이터 공개 이후)
- US_EQUITY: 매일 09:00 (ET 장 마감 + EOD 확정 이후)
- CRYPTO:    매일 00:30 (업비트 KST 일봉 마감 직후)

공통 파이프라인 (runJudgment):
1. 시한이 지났고 미판정인 PredictionCard 조회 (자산군 필터)
2. 카드별:
   a. registry에서 자산군의 provider 선택
   b. provider.getDailyQuotes(ticker, publishedAt, deadline)  ← 자산군 시간대로 날짜 환산
   c. provider.getSecurityStatus(ticker, deadline)
   d. buildMarketSnapshot() → judge() → 판정 결과
   e. 판정 성공 → Judgment 저장 (원천 스냅샷 JSON + 소스 식별자)
                → 해당 리포트의 모든 에스크로 Purchase에 settle() 적용
   f. 데이터 미도달/결측 → 다음 배치로 이월 (최대 5영업일, 초과 시 보류 큐)
3. 보류 큐는 운영자 대시보드에서 수동 판정 (사유 기록 필수)
```

- **멱등성**: `Judgment.predictionCardId` unique — 재실행해도 중복 판정 불가
- **레이트 리밋**: Twelve Data 8콜/분 → US 배치는 큐 처리(분당 8건). 판정량 증가 시 유료 전환
- 자동 추정이 애매하면 항상 **판정 불가(사람 확인) 쪽으로 기울인다** — 오판정 1건이
  평판 시스템 전체 신뢰를 훼손

## 5. 코드 구조

```
src/domain/marketData.ts        공급자 인터페이스, 자산군별 시간대 규칙,
                                ProviderRegistry, 스냅샷 조립(순수 함수)
src/domain/judgmentPipeline.ts  카드 1건: 데이터 조회 → 판정 → 감사 기록
src/infra/marketData/
  fixtureProvider.ts            개발·테스트용 인메모리 공급자
  fscProvider.ts                공공데이터포털(금융위) — KR_EQUITY
  twelveDataProvider.ts         Twelve Data — US_EQUITY
  upbitProvider.ts              업비트 공개 API — CRYPTO
```

- 스냅샷 조립·파싱은 전부 순수 함수로 분리해 네트워크 없이 단위 테스트
- 배치 잡은 자산군 → provider 매핑(`ProviderRegistry`)만 구성하면 됨

## 6. 엣지 케이스 정리

| 케이스 | 처리 |
|---|---|
| 시한이 휴장일(주말·공휴일) | 직전 거래일 종가로 판정 (약관 명시). 크립토는 해당 없음 |
| 미국주식 시한의 시간대 해석 | 자산군 시간대(ET) 기준 날짜로 환산 후 판정 |
| 게시~시한 사이 거래정지 후 재개 | 거래된 날짜 데이터만으로 판정 |
| 시한 시점 거래정지 지속 | UNDECIDABLE(TRADING_HALT) → 전액 환불 |
| 상장폐지 / 거래소 거래지원 종료 | UNDECIDABLE(DELISTED) → 전액 환불 |
| 코인 하드포크·티커 변경·스왑 | UNDECIDABLE(AMBIGUOUS) → 수동 검토 (MVP) |
| 액면분할·감자 등 기업행위 | UNDECIDABLE(AMBIGUOUS) → 수동 검토 (MVP) |
| 데이터 소스 장애 | 판정 이월 (멱등 재실행), 5영업일 초과 시 보류 큐 |
| 게시일이 비거래일 | basePrice는 게시 시점 직전 거래일 종가로 고정 (게시 플로우에서 확정) |
| 업비트 미상장 코인 | MVP는 업비트 상장 코인만 허용 (게시 시 검증). 바이낸스 확장은 후순위 |

## 7. 남은 결정 사항

- [ ] 공공데이터포털 API 활용신청 + 상업 서비스 이용 조건 확인
- [ ] Twelve Data 무료→유료 전환 기준 (판정량 임계치) 및 약관상 상업 이용 확인
- [ ] KRX 상장폐지·거래정지 목록 + 업비트 거래지원 종료 공지 수집 배치
- [ ] 기업행위 자동 감지 도입 시점 (수정주가 소스 필요)
- [ ] 판정 배치 실행 인프라 (cron / 큐) — 배포 환경 결정 후
- [ ] 코인 분석 콘텐츠 규제 검토 (CLAUDE.md 6.5절과 연동)
