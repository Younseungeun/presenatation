> CLAUDE.md 6.5절 미확정 사항 "판정 데이터 소스 선정"에 대한 설계안.
> 최종 업데이트: 2026-07-12

## 1. 판정 엔진이 요구하는 데이터

`src/domain/judgment.ts`의 `judge()`는 순수 함수이며, 입력 `MarketSnapshot` 하나로 판정한다.
데이터 레이어의 책임은 **이 스냅샷을 정확하게 만들어내는 것**이 전부다.

| 필드 | 용도 | 원천 데이터 |
|---|---|---|
| `highSincePublish` | 상승 목표가 도달 판정 | 게시일~시한 일별 고가의 최댓값 |
| `lowSincePublish` | 하락 목표가 도달 판정 | 게시일~시한 일별 저가의 최솟값 |
| `priceAtDeadline` | 수익률형(RETURN_PCT) 판정 | 시한 당일(휴장 시 직전 거래일) 종가 |
| `status` | 판정 불가 처리 | 거래정지·상장폐지 여부 |

추가 요구사항:
- **일 단위 데이터로 충분** — 판정은 시한 도래 후 배치로 실행되므로 실시간이 불필요
- **감사 가능성** — "판정 무분쟁 기록 축적"이 1단계 최우선 목표이므로, 판정에 사용한
  원천 데이터를 스냅샷으로 저장해 분쟁 시 재현 가능해야 함
- **수정주가 아닌 원주가 사용 시 액면분할·감자 등에서 오판** → 기업행위(corporate action)
  발생 종목은 판정 불가(AMBIGUOUS) 처리 후 수동 검토 (MVP 단순화)

## 2. 데이터 소스 후보 비교

| 후보 | 비용 | 커버리지 | 갱신 | 인증 | 비고 |
|---|---|---|---|---|---|
| **공공데이터포털 금융위 주식시세정보** | 무료 | KRX 상장 전 종목 OHLCV | 일 1회, D+1 영업일 13시 이후 | API 키 (활용신청) | 공공 API — 약관·상업 이용 조건 확인 필요 |
| KIS Developers (한국투자증권) | 무료 | 국내주식 실시간·기간별 시세 | 실시간 | 증권사 계좌 + APP Key/Secret, 토큰 갱신 | 호출 한도 있음. 법인 계정은 별도 협의 |
| 코스콤 오픈API | 유료 | KRX 전 종목, 시세 재분배 라이선스 | 실시간 | 계약 | 상용 서비스 정식 라이선스 — 스케일 단계 |
| KRX 정보데이터시스템 | 무료 | 전 종목 + 거래정지·상폐 목록 | 일 단위 | 없음 (웹) | 공식 API 아님(크롤링성) — 보조 검증용만 |

### 권고안

- **MVP (1단계)**: 공공데이터포털 금융위 주식시세정보 API를 주 소스로 사용
  - 판정은 `시한 + 1영업일 13시 이후` 배치 실행으로 D+1 지연을 흡수
  - 무료·무계좌라 콜드스타트 단계 비용 0
- **2단계**: KIS API를 보조 소스로 추가 — ① 리포트 게시 시점 기준가(`basePrice`) 실시간
  스냅샷, ② 주 소스 결측 시 교차 검증
- **스케일 단계**: 시세 데이터를 화면에 재표시하거나 데이터 상품화(3단계 로드맵)할 때
  코스콤 등 정식 재분배 라이선스 계약 검토
- 어떤 소스든 갈아끼울 수 있도록 **`MarketDataProvider` 인터페이스 뒤에 격리**한다 (§4)

### 거래정지·상장폐지 감지

금융위 시세 API는 종목 상태를 직접 제공하지 않는다. MVP 전략:
1. 시한 전후로 시세 레코드가 존재하면 정상 거래로 간주
2. 시한 포함 최근 N영업일(기본 5일) 연속 레코드 부재 → `TRADING_HALT` 추정 → 판정 보류 큐로 이동, 운영자 확인
3. 상장폐지는 KRX 상폐 종목 목록(일 배치)과 대조
4. 자동 추정이 애매하면 항상 **판정 불가(사람 확인) 쪽으로 기울인다** — 오판정 1건이
   평판 시스템 전체 신뢰를 훼손하므로 보수적으로 설계

## 3. 판정 배치 흐름

```
매 영업일 13:30 KST (D+1 데이터 공개 이후)
1. 시한(deadline)이 지났고 미판정인 PredictionCard 조회
2. 카드별:
   a. provider.getDailyQuotes(ticker, publishedAt, deadline)
   b. provider.getSecurityStatus(ticker, deadline)
   c. buildMarketSnapshot() → judge() → 판정 결과
   d. 판정 성공 → Judgment 저장 (원천 데이터 스냅샷 JSON 포함)
                → 해당 리포트의 모든 에스크로 Purchase에 settle() 적용
   e. 데이터 미도달/결측 → 다음 배치로 이월 (최대 5영업일, 초과 시 보류 큐)
3. 보류 큐는 운영자 대시보드에서 수동 판정 (사유 기록 필수)
```

- **멱등성**: `Judgment.predictionCardId`가 unique이므로 재실행해도 중복 판정 불가
- **감사 스냅샷**: `Judgment.marketSnapshotJson`에 판정에 사용한 일별 시세 원본과
  소스 식별자(`dataSource`)를 저장 — 분쟁 시 그대로 재현
- 판정 완료 → 알림(구매자·리서처) 발송은 후속 단계

## 4. 코드 구조

```
src/domain/marketData.ts        공급자 인터페이스 + 스냅샷 조립(순수 함수)
src/domain/judgmentPipeline.ts  카드 1건: 데이터 조회 → 판정 → 정산 입력 생성
src/infra/marketData/
  fixtureProvider.ts            개발·테스트용 인메모리 공급자
  fscProvider.ts                공공데이터포털(금융위) 어댑터
```

- `judge()`와 마찬가지로 스냅샷 조립(`buildMarketSnapshot`)은 순수 함수로 두어
  API 어댑터 없이 단위 테스트한다
- 어댑터는 "원격 응답 → `DailyQuote[]`" 파싱만 담당하고, 파싱 함수는 분리해 테스트한다

## 5. 엣지 케이스 정리

| 케이스 | 처리 |
|---|---|
| 시한이 휴장일(주말·공휴일) | 직전 거래일 종가로 판정 (약관 명시) |
| 게시~시한 사이 거래정지 후 재개 | 거래된 날짜 데이터만으로 판정 (고저가는 거래일 기준) |
| 시한 시점 거래정지 지속 | UNDECIDABLE(TRADING_HALT) → 전액 환불 |
| 상장폐지 | UNDECIDABLE(DELISTED) → 전액 환불 |
| 액면분할·감자 등 기업행위 | UNDECIDABLE(AMBIGUOUS) → 수동 검토 (MVP) |
| 데이터 소스 장애 | 판정 이월 (멱등 재실행), 5영업일 초과 시 보류 큐 |
| 게시일이 비거래일 | basePrice는 게시 시점 직전 거래일 종가로 고정 (게시 플로우에서 확정) |
