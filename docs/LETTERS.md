# 두 세션이 편지를 주고받는 규칙

이 저장소는 **두 Claude 세션**이 나눠 만들고 있습니다 — 서버·도메인 쪽과 관리자 앱
화면 쪽. 공유 파일(`src/domain/`·`src/server/`·`src/infra/`)을 건드리면 상대가 모르는
사이에 그쪽 시험이 깨지므로, **무엇을 왜 바꿨는지 편지로 남깁니다.**

## 파일 이름이 방향을 말한다

| 이름 | 누가 쓰나 | 방향 |
|---|---|---|
| `admin-app-reply-N.md` | 서버 세션 | **서버 → 관리자 앱** |
| `to-server-N.md` | 관리자 앱 세션 | **관리자 앱 → 서버** |

`N`은 **두 series가 함께 쓰는 대화 번호**입니다. "19호"는 한 번의 왕복을 가리키므로,
답장은 **같은 번호에 반대쪽 이름**으로 씁니다.

```
to-server-19.md          ← 관리자 앱이 보냄
admin-app-reply-19.md    ← 서버가 그것에 답함
```

## 절대 하지 말 것 — 남의 편지 위에 쓰기

**상대의 파일을 열어 답장을 덮어쓰지 않습니다.** 답장은 **자기 쪽 이름의 새 파일**에
씁니다.

2026-08-23에 실제로 일어났습니다. 관리자 앱 세션이 나가는 편지를 `admin-app-reply-18.md`
(= 서버가 쓰는 자리)에 썼고, 서버 세션이 그 자리에 답장을 쓰면서 **원문 191줄이
지워졌습니다.** git 이 들고 있어 잃지는 않았지만(커밋 `486a941`), 그 파일을 지금 열면
**답만 있고 무엇에 대한 답인지가 없습니다.**

원인은 악의가 아니라 이름이었습니다 — `admin-app-reply-*` 는 1호부터 18호까지 전부
**서버가 쓰는 series** 였는데, 관리자 앱이 거기에 끼어 썼습니다. 그래서 규칙을 이름에
박습니다.

## 왜 `-in`/`-out`이 아니라 이 이름인가

"보냄/받음"은 **읽는 사람이 누구냐에 따라 뒤집힙니다** — 서버 세션에게 `-out`인 파일이
관리자 앱 세션에게는 `-in`입니다. 두 세션이 같은 폴더를 보므로 그런 이름은 반드시
헷갈립니다. **누가 쓰는지**로 이름을 정하면 뒤집히지 않습니다.

한글 파일명(`-보냄`)을 쓰지 않는 이유는 git 이 그것을 이스케이프해 출력하기 때문입니다
(이 저장소에서 이미 `"public/images/\353\260\224\353\213\244..."` 로 겪었습니다).

## 기존 1~18호는 그대로 둔다

전부 서버 세션이 쓴 것이라 series 가 이미 일관됩니다. 그리고 **다른 문서 다섯 곳이
이름으로 참조합니다**(`admin-app-brief-2.md`·`-3`·`-4`, `screening-model-handover.md`) —
이름을 바꾸면 그 링크가 전부 끊깁니다. 규칙은 **19호부터** 적용됩니다.

예외 하나: `admin-app-reply-18.md` 는 위 사고로 응답본만 남아 있습니다. 나가는 18호
원문은 커밋 `486a941` 에 있습니다.

## 편지에 무엇을 적나

- **무엇을 바꿨나** — 파일과 커밋 해시
- **왜** — 근거. 특히 실측·사고 기록이 있으면 그것
- **호환** — 상대가 읽는 값의 뜻이 바뀌었는가. 안 바뀌었으면 안 바뀌었다고 적는다
- **확인 부탁** — 상대가 봐야 할 자리를 목록으로. 없으면 "없습니다"라고 적는다
- **상태** — `tsc` 와 시험 결과. 초록이 아니면 보내지 않는다
